# 설계 — 본문은 언제나 파일, pane 에는 «명령»만 (2026-09-03)

발의: yoonhwan 오빠. 「mbox 길이 제한하니 애들이 tmux send-keys 로 본문을 바로 보낸다 —
파일 기반으로 «mbox 읽어라» 명령만 보내는 게 어떠냐. pane 에 doorbell 이 쌓여 있으면
안 보내는 처리도 pane 읽는 비용 덜 드는 방법으로.」

## 지금 무엇이 잘못돼 있나

| 층 | 현재 | 결과 |
|---|---|---|
| 규약 | COMM-GUIDE §1 이 **발주는 pane 에 본문 직접**이라고 못박음 | 좌석이 본문을 화면으로 쏜다 |
| 가드 | mbox 본문 700자 상한(`BODY_TOO_LONG`) | 길면 큐가 거부 → **더 나쁜 채널(send-keys)로 우회** |
| 우회 | `ft-tmux-send.sh` 가 `--dispatch` 로 가드를 통째 면제 | 길이 규율이 사실상 없다 |

**가드가 트래픽을 더 위험한 경로로 밀어냈다.** send-keys 본문은 ①멀티바이트 손상 ②사람의
터미널 입력 차단 ③미제출 잔류 — 셋 다 파일 큐에는 없는 위험이다.

## 바꿀 것 셋

### 1. 본문은 파일, pane 에는 «명령 + 착수 지시» 한 줄
doorbell 이 넣는 줄을 명령만이 아니라 **지시문**으로 만든다:

```
[발주 도착] bash <mbox> recv <me> — 실행하고 그 안의 지시를 즉시 착수하라
```

★왜 이 형태여야 하나★: COMM-GUIDE §1 의 실측(mbox 로 발주하면 좌석이 읽고 답만 하고
끝났다)은 **도구 출력은 «참고»로 읽힌다**는 것이었다. 본문을 파일로 옮기면 그 문제가
그대로 돌아온다. 그래서 pane 에 남는 한 줄이 **사람이 친 지시**의 형태를 갖게 한다 —
본문은 여전히 파일이고, 화면에는 «가서 읽고 착수하라»만 남는다.

### 2. 길이 규율을 «발신 차단»에서 «수신 절단»으로
- `send` 는 길이로 **실패하지 않는다** — 실패시키면 우회를 부른다.
- `recv` 가 본문을 N자에서 끊고 `전문: <경로>` 를 붙인다. 받는 쪽 컨텍스트는 그대로 보호되고,
  긴 내용은 유실 없이 남는다.
- `relay` 는 그대로 둔다(사람이 요약을 쓰는 정본 절차는 여전히 최선이다).

### 3. doorbell 억제 — 싼 게이트를 먼저, pane 은 실제 주입 직전에만
현재 `doorbell()` 은 **capture-pane 을 맨 먼저** 부른다(`ft-mbox.sh:38`). 그 뒤 3초 억제
검사(`:51`)에서 걸려도 **화면은 이미 읽은 뒤**다.

실측(10회 평균): `capture-pane` **20.6 ms** / `stat` **8.6 ms**.
★차이는 «압도적»이 아니다★ — 이득은 절대 비용이 아니라 **안 읽어도 될 때 안 읽는 것**이다.

순서를 뒤집고, 파일 stat 만으로 판정하는 게이트를 앞에 둔다:

1. `pending == 0` → 울릴 이유 없음(이미 큐에 넣기 전에 아는 값이다)
2. **outstanding doorbell** — `last_doorbell > last_recv` 면 **아직 소비 안 된 doorbell 이 떠 있다** → skip.
   `recv` 가 자기 스탬프(`.mbox-recv-<seat>`)를 touch 하면 두 파일 mtime 비교만으로 안다.
   ★이것이 「pane 에 mbox 가 쌓여 있으면 안 보낸다」를 pane 을 안 읽고 하는 방법이다.★
3. 시간 억제(기존 `FT_MBOX_DOORBELL_MIN`)
4. **여기까지 통과했을 때만** `capture-pane` — 옵션모드(사람 프롬프트) 보호와 `❯` 잔류 정리는
   실제로 주입할 때만 필요하다.

## 남는 위험

- **1 의 지시문이 안 먹으면** 좌석은 다시 «읽고 답만» 한다. 판정 방법: 발주 후 좌석이
  `recv` 를 실행했는지가 아니라 **착수했는지**를 본다(도구 호출 발생 여부).
- **2 의 절단 길이**를 너무 짧게 잡으면 사람이 매번 파일을 열게 되어 아낀 게 없어진다.
  초기값은 현행 상한과 같은 700자로 두고 실사용으로 조정한다.
- 규약 변경이므로 **COMM-GUIDE §1·§1.5 를 같이 고쳐야 한다** — 문서와 코드가 갈리면
  좌석은 문서를 따른다(지금 이 사달이 그것이다).
