Git·사건·대시보드의 경계

Git에는 골, 아키텍처 정본, 작업·랜딩 원장, BTS 근거와 판정을 남깁니다. 검증 뒤 원장·문서 갱신과 코드/실관측 대조를 거쳐야 완료입니다. runtime에는 접수, 현재 owner와 revision, 미처리 사건과 미확정 효과를 보존합니다. 대시보드는 runtime을 읽어 만든 화면입니다.

사건 기록을 사용한다는 설명이 무한 journal을 채택했다는 뜻은 아닙니다. 모든 journal·JSONL에 유한 cap을 두고 스크립트로 회전합니다. 필요한 완료 근거는 Git 보존을 확인하고, 처리하지 않은 사건은 조용히 버리지 않습니다. 포화면 업무 접수를 거부하고 FULL을 알립니다.

파일 잠금은 외부 명령의 권한을 대신하지 않습니다. 외부 효과 실행권은 실제 어댑터에서 검사해야 합니다. 전원 손실 내구성은 아직 검증하지 않았습니다.

반복 호출과 기록 관리 조건

Slack의 유휴·중복·무변화 사건은 모델 호출과 세션 깨움 없이 처리합니다. 필요한 thread 변경분과 근거만 전달하며, 전체 대화 재로드·무분별한 LLM 분류·틱 메시지를 금지합니다. 실제 역할 세션의 사용량으로 검증해야 합니다.

doctor는 미해결 상태로 변화 없는 동일 증상만 반복 억제합니다. 명시 요청·악화·새 설치 sha·복구 실패는 다시 검사합니다. 1.x 도구는 기능 참고만 하며 새 코어의 진단 입구 하나를 사용합니다. journal cap 숫자와 교체 방식은 arch 검토 후 결정합니다.
