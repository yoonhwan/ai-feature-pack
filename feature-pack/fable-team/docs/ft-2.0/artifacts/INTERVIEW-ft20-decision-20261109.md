## 질문 1. 완료 기록의 보존 범위

질문: 진행·대기·미확정 작업은 보호하면서, **끝난 작업의 기록은 어디까지 남길까요?** 이 답으로 «쌓이지 않음»의 범위를 정합니다.

| 선택 | 의미 | 장점·비용 |
|---|---|---|
| A 추천 | 완료 근거·결정 요약은 Git에 보존하고 상세 로그는 용량 상한으로 회전 | 운영 기록을 작게 유지하고 완료 이유를 추적. Git 이력 자체는 계속 늘 수 있음 |
| B | 완료 근거와 상세 로그 모두 보존 기간·용량을 정해 지난 기록을 정리 | 전체 기록량까지 제한. 오래된 결정·완료 근거의 재현 범위가 줄어듦. Git/원격 이력의 실제 적용 방법은 별도 설계 필요 |
| C | 원문 전체는 별도 보관하고 운영 폴더만 상한 유지 | 과거 원문 추적 가능. 보관소와 그 비용·관리 경계가 추가됨 |

답변: **A 확정**. 사용자 원문: «완료 근거·결정 요약은 Git에 보존하고, 상세 로그만 용량 상한으로 회전합니다. Git 이력은 늘 수 있습니다. (추천)»
확정 해석: 운영 상세 로그는 유한 용량으로 회전한다. 완료 근거와 결정 요약의 Git 보존 및 Git 이력 증가는 허용한다. 진행·대기·미확정·현재 복구에 필요한 기록은 보호한다. 구체적인 용량은 실험을 근거로 제안하며 이번 답변에 없는 수치를 확정하지 않는다.
질문 이유: 외부 repo에서도 완료128건 상한과 전체 보관량 상한은 달랐다. 현재 ft의 archive도 활성층만 줄이며 전체 디스크 유한성을 뜻하지 않는다. 기존 사용자 지시의 운영 의도를 정책으로 구체화할 필요가 있다.

## 질문 2. 골 진행 중 팀장 세션의 수명

팀장 책임과 골·역할·근거는 유지한다. 모델 호출이 없을 때 프로세스가 살아 있는 것과 매번 모델을 깨우는 것은 다르다. 아래 모든 선택에서 정해진 절차는 비모델 도구가 실행한다.

| 선택 | 의미 | 평가 |
|---|---|---|
| A 조건부 공동 추천 | 판단이 필요한 작업 묶음마다 팀장 세션을 열고, 인계할 상태를 기록한 뒤 닫는다. 다음 판단에서 역할을 재개한다 | 상주 세션·승계 부담을 줄이는 후보. 재기동 컨텍스트 비용과 구효과/owner·접수·마감 안전성 전체 검증이 필요하며 비용 우위는 미측정 |
| B | 진행·대기 골이 있는 동안 같은 팀장 세션을 유지하고, 새 판단이 있을 때만 호출한다 | 컨텍스트 연속성을 유지. 세션 증류·복구 경계를 관리해야 함. 상주 자체가 주기 모델 호출을 뜻하지 않음 |
| C | planner 팀장만 골 전체에 유지하고, 작업팀 팀장은 A처럼 운영한다 | 두 운영 수명을 구분하는 비용. 공통 상태 계약은 동일하게 유지 |

질문: **골이 진행되는 동안 팀장 세션을 어떤 수명으로 운영할까요?**
답변 이력: 사용자는 처음에 A를 선택한 뒤, «planner 팀장만 유지하고, 작업팀 팀장은 판단 묶음마다 열고 닫습니다 난 이것도 나브지않은데 실험 결과로 결정»이라고 보완했다.
현재 결정: **세션 수명은 확정하지 않는다.** «planner·작업팀 모두 판단 묶음별 재개»와 «planner 팀장 유지·작업팀만 묶음별 재개»를 같은 조건으로 실험해 선택한다. 처음 선택한 A를 최종 확정으로 쓰거나 뒤의 C를 즉시 채택하지 않는다. planner 유지의 범위도 전체 프로젝트 골이 남아 있는 동안이며, 골0 종료 원칙을 자동 폐기하지 않는다.
비교 근거: 실제 재개 안전성·상태 일치·응답 지연·컨텍스트/토큰/캐시·프로세스 기동 비용. 파일 상태 실험의 모델호출0 결과만으로 세션 수명 비용을 결정하지 않는다. 외부 효과·미처리·owner 경계의 안전성 통과가 비용 비교보다 우선한다.

## 결론 문서의 닫는 조건

공동 추천·정정 근거, 인터뷰 질문별 사용자 원문/확정 해석, 실험 결과와 알려진 한계, 적용 범위·이관·되돌림 책임을 연결한다. 인터뷰 미답을 추천값으로 채워 완료 처리하지 않는다. 질문 답변과 설계 선택이 끝나도 제품 구현·마이그레이션 골은 별도 완료 증거가 필요하다.

기획·시뮬·반증 완료 → 풀스펙 HTML로 ft 랜딩·BYZ 설치 후의 운영을 설명 → 사용자 이해·명시 컨펌 → 제품 구현 시작. 격리된 기획 검증 실험은 이 확인 전에도 진행하지만 제품 코드 구현·운영 설정 변경·실제 배포/설치/마이그레이션은 시작하지 않는다.
실제 구현 전이므로 HTML의 랜딩·설치 후 화면은 예상 운영과 검증된 실험을 구분해 표시한다. 이미 설치·운영이 완료됐다고 표현하지 않는다. 기준 정본은 `GATE-ft20-full-spec-before-implementation-20261109.md`다.
