# ft 2.0 최소 격리 실험 계약 v1

상태: 제품 구현과 분리된 설계 실험 발주. 원안3개와 교차 검토를 보존한다. DA 원자 JSON을 첫 실행 후보로 삼지만 최종 채택하지 않는다.
메인: 현재 Astra. 실험 구현은 공식 FT Pi 나노, 독립 검증은 다른 Pi checker. 원안의 빈 분기는 아래에 공개한 실험 전용 계약과 작성자 보완을 함께 고정한다. 이를 원안 자체가 이미 통과한 것으로 쓰지 않는다.

- aifp-ft의 `/tmp/ft-2.0/STATUS-aifp-ft-20261109.md`와 `STATUS-aifp-ft-20261109-addendum.md`. 일반 파일 잠금으로 임의 Bash 쓰기를 막지 못하며 현재 구형 writer 전환 차단 입구는 확인 범위에서 없다.

- 실제 파일·독립 프로세스로 상태와 효과 대역을 기록한다. 실패 주입은 시험 자식이 지정 지점에서 스스로 종료한다. 실 세션이나 서비스에 신호를 보내지 않는다. 시한은 가상 시계로 다룬다. sleep0, 외부 API0, 모델 호출0.

## 먼저 닫아야 할 실험 전용 분기

1. 새 claim 응답 `GRANTED(attempt_id)`만 효과 실행권이다. 같은 키 재접수는 `IN_PROGRESS` 또는 기존 `DONE` 결과이며 실행권이 아니다. 같은 키 다른 본문은 `CONFLICT`.
2. `STARTED` 효과는 owner 교체만으로 해제하지 않는다. 결과가 불명확하면 `UNCERTAIN`; 같은 대상의 충돌 효과는 `BLOCKED_UNCERTAIN`. 담당 팀장과 확인 시한·상위 보고처를 가진다. 시한이 지나도 자동 성공·재실행으로 바꾸지 않는다.
3. 입구가 FULL이면 업무 접수 성공을 반환하지 않는다. 외부 transport ACK와 업무 ACK를 구분한다. 이번 실험 입구는 CLI/파일 대역이며 실제 Slack 연동은 미검증. 대역 sender는 같은 키를 보존하고 미접수를 사용자 결과로 노출한다.
4. 생산자 ID/세대를 재사용하지 않는다. 폐기 세대 요청은 `EXPIRED`; watermark 이하 재전달은 기록 보존 중이면 결과, 정리됐으면 `ALREADY_ACCEPTED_RESULT_EXPIRED`로 응답하고 재실행0. 세대 재등록을 자동 허용하지 않는다. 접수 간격을 건너뛰어 watermark를 올리지 않는다.
5. 잠금은 비차단 시도 후 `BUSY`로 반환한다. dispatcher 대역은 해당 팀을 건너뛰고 다음 팀을 처리한다. 재시도는 다음 가상 시한의 사건이며 바쁜 폴링·잠금 강탈은 하지 않는다.
6. 마감은 현재 팀 revision과 pending/uncertain0 검사를 함께 한다. 새 접수가 revision을 바꾸면 마감은 `RETRY`; 이미 closed라면 새 pending이 팀 재개 필요 상태를 만든다. 실제 세션 종료는 대역 기록만 한다.

위 분기는 실험 전용 보완안이다. 작성자가 원안의 의미와 충돌한다고 판단하면 구현자가 임의 선택하지 말고 그 사례를 `SPEC_INCOMPLETE`로 보고한다. 후보를 통과시키려고 자유로운 Bash 외부 효과까지 통제됐다고 가정하지 않는다.

## 공통 데이터와 상한

- 동일 작업 payload 256B, 한 팀 active4/pending8을 기본 기능 시험으로 사용. 팀 상태 byte cap 1MiB, 진단 이력 4파일×1MiB는 스트레스 입력이다. 상한 수치는 실험값이지 제품 운영값이 아니다.
- 동시 갱신은4프로세스×300회, 각자 다른 카드의 증가 revision과 최종값을 확인한다. 동일 카드 중복 선점은2프로세스로 별도 시험한다. 시험 최대70초; 미완료면 `TIME_LIMIT`로 기록하고 규모를 낮춘 별도 사례를 만들며 원 시험 통과로 치환하지 않는다.
- 프로세스당 외부 도구 호출 상한과 전체7분/동시4개 한도를 지킨다. 반복3회로 시간을 늘리지 않는다.
- 비용: 상태 읽기/직렬화 쓰기 bytes, 실제 파일 작업 횟수, lock BUSY 수, 각 시험 wall time. 계측한 bytes는 논리 IO인지 실제 disk IO인지 구분한다. 토큰·캐시·전원손실 비용은 미측정이다.
- 성능 허용 SLA는 사용자 미결정. 시간 한도 내 종료는 시험 실행 가능성일 뿐 제품 성능 승인으로 쓰지 않는다.

## 고정 사례와 외부 판정

| 사례 | 입력 | 기대·독립 관측 |
|---|---|---|
| 정상 생애 | 새 골→두 카드→결과→검증/판정/착지/설치 대역→마감→새 골 | 누락된 검증 근거가 있으면 닫힘 거절. 모든 증거 후 닫힘, 신규 골은 재개됨 |
| 다른 카드 동시 갱신 | 4프로세스×300 | 네 카드 모두300, 결과 JSON 파싱 가능. 내부 성공 반환 수만 보지 않음 |
| 동일 카드·동일 키 | 동시2선점, 같은 키 재요청 | GRANTED1, 다른 요청 IN_PROGRESS/기존결과, 효과 대역1회 |
| 옛 owner | 새 세대 전환 뒤 구세대 write/퇴장/결과 | 정본 불변·명시 거절. 외부 효과가 있었다면 별도 기록 |
| 구효과 진행 | A STARTED→A 응답 없음→owner 교체/후계 충돌효과 | 미확정 보존·후계 효과0. 타팀의 독립 작업은 가능 |
| 접수 crash | 상태 교체 전·교체 후 ACK 전 자식 종료 | 미접수 또는 영속 접수, 재요청으로 하나의 작업 회수 |
| 효과 crash | 효과 전·효과 후 결과확정 전 자식 종료 | 무근거 재실행0, 불명 상태·담당자·시한 보존 |
| 만료/포화 | 완료K 정리→K 재전달·폐기세대 재설치·pending한도 초과 | K 효과 증가0, EXPIRED/명시만료 응답. 기존 pending보존, 새 입력은 FULL·성공ACK0 |
| 느린 팀 | 팀A 잠금을 대역 프로세스가 보유한 상태에서 B 검사 | A BUSY, B 전이 완료. 루트 전역 lock으로 대기하지 않음 |
| 진행 구분 | A 진척·B 침묵·C 외부 대기·heartbeat만 | B 멈춤1건, heartbeat로 재무장0, 외부 대기 확인 시한 보존 |
| 마감 경합 | 마감 revision 읽은 직후 새 골 접수 | 마감 RETRY 또는 closed 후 재개 pending. 신규 골 소실0 |
| 상태 손상 | 다음 읽기에서 파싱 불가능한 시험 사본 | 정상 초기화·완료 단정0, 명시 판정불가. 원본 증거 보존 |

효과 대역은 후보 상태 파일과 별개로 기록한다. checker는 외부 효과 기록·시작/종료 기록·파일 내용으로 판정하고 후보의 성공 flag를 그대로 믿지 않는다. 미구현·검사 누락은 PASS가 아니다.

## 다른 두 안과 비교하는 방법

Fable의 유한보관·consumer offset·구효과·역이관, Astra의 claim 응답·만료·압축 경계는 명세 반례로 먼저 유지한다. 다른 안을 불완전한 상태로 구현해 비교 실패를 만들지 않는다. 작성자 보완 없이 실행하지 못한 칸은 `SPEC_INCOMPLETE`다.
DA도 이 문서의 추가 분기를 거친 **실험 후보**라는 점을 결과에 표기한다. DA 실험 통과가 세 안 전체의 우열·원안 안전성·최종 제품 채택을 증명하지 않는다. 같은 입력에서 저장 전략 비용 비교가 필요하면 다음 회차에 journal/자기파일 후보를 별도로 고정한다.

## 산출과 종료

Pi 구현자: 격리 실험 코드·실행 명령·고정 입력 hash·원자료 경로·사례별 결과 JSON/Markdown·부족한 계약. 기존 모형 수정0. 제품 코드와 별도 `design/harness/research/ft-2.0/sim-atomic-json/` 아래 추적.
Pi checker: 구현자 commit 고정 후 다른 빈 폴더에서 재현, 별도 원자료와 verdict 문서. 반복 실행은 실패 재현 또는 독립 검증 목적1회로 제한한다. 내부 함수 이름만 바꿔 자기확인 테스트를 만들지 않는다.
종료는 사례별 PASS/FAIL/SPEC_INCOMPLETE/TIME_LIMIT/미측정과 근거가 완성됐을 때다. FAIL을 해결하려 제품 구현·운영 변경으로 넘어가지 않는다. 메인이 결과를 3안 비교본에 반영하고 사용자와 선택한다.
