## 유지할 핵심 조건

- 작은 공통 팀 도구와 파일 상태를 기반으로 한다. planner·작업팀·특수팀의 책임과 권한을 구분한다.
- 완료/다음 단계 사건은 즉시 처리한다. 300초는 무진척 재검사이며 반복 재촉 주기가 아니다. heartbeat만으로 시한을 무한 연장하지 않는다.
- 검증→문서·원장·BTS 정합→Git commit/push·main 착지→Issue 근거 연결→필요 설치 검증 뒤 완료한다.
- 레거시는 Git에 보존·격리하고 코드는 참고한다. 새 2.0 실행 의존으로 덧붙이지 않는다. 열린 골·대화·결정·미확정 자료는 무유실 이관한다.
- 모든 journal·JSONL은 용도별 유한 cap 안에서 스크립트로 회전한다. 최신 유효 상태와 필요한 tail을 읽는다. 관리용 LLM 호출은 없다. 미처리·미확정 자료를 버리지 않으며 cap 포화는 명시 처리한다.
- 완료 근거·결정 요약은 Git에 보존한다. Git 이력 증가 허용과 실행 journal의 유한 상한은 별개다.
- Slack은 메인 축이다. 유휴·중복·무변화의 모델 호출과 깨움은 0이어야 한다. 필요한 thread 변경분만 전달하고 실제 역할 세션 사용량으로 검증한다.
- doctor는 새 코어의 진단 입구 하나를 사용한다. 명시 요청·증상 악화·새 설치 sha·복구 실패는 재검사한다. 검증 결과·원인·출처를 기억에 연결한다.

## 출처와 이어받기

[manifest.json](manifest.json)에 각 사본의 원본 경로·commit·SHA256을 기록했다. Git 출처와 `/tmp` 문서 스냅샷을 구분한다. 원자료·비밀값·개인 세션 로그·실험 실행 코드는 복사하지 않았다. 외부 출처 경로가 이 폴더에 없다는 이유로 시험 근거를 새로 만들어서는 안 된다.

이 문서 사본은 제품 2.0 배포물이 아니다. 문서 branch 보존과 main 착지는 별도 상태다. 실제 구현은 풀스펙을 사용자가 이해하고 문서 버전에 명시적으로 컨펌한 뒤 시작한다. 후속 담당자는 최신 변경 여부를 확인하고 필요한 해당 문서만 읽는다. 전체 디렉터리 자동 로드·반복 요약 루프를 만들지 않는다.
