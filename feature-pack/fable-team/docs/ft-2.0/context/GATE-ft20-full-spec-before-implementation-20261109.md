# ft 2.0 제품 구현 전 풀스펙·사용자 확인 게이트

상태: 사용자 지시로 확정된 진행 조건. 현재 제품 구현 시작 컨펌은 아직 없다.
메인: 현재 Astra. Fable·DA·aifp-ft·Pi 실험자·checker가 같은 조건을 적용한다.

## 사용자 원문

«모두 완성되면 하네스 시스템 풀 스펙 html 확인하고 ft 랜딩하면 byz ft 설치후에 팀이 어떻게 돌아가는지 내가 완전이해하고 컨펌하면 구현 시작인것. 기록해두자»

## 순서

1. 기존 ft 및 외부 repo 근거를 대조하고 기획·공동 추천·질문 답변을 정리한다.
2. 격리 시뮬레이션과 반증으로 계약을 검증한다. 상태 저장 실험과 실제 모델 세션의 재기동/캐시 비용 실험을 구분한다.
3. 하네스 시스템 **풀스펙 HTML**을 공개한다. ft 랜딩과 BYZ ft 설치 뒤 팀이 어떻게 운영될지 사용자가 전 과정을 이해할 수 있어야 한다.
4. 사용자 질문과 보완을 반영하고 해당 문서 버전에 대한 **명시적 컨펌**을 기록한다.
5. 그 뒤 제품 구현을 시작한다. 구현·로컬 검증·판정 뒤 ft 2.0 랜딩, 실제 ft/BYZ 설치·마이그레이션, 설치본 checker 동작 검증으로 이어간다.

ft 랜딩·BYZ 설치 후 흐름은 제품 구현 전 HTML에서 **예상 운영**으로 설명한다. 기획 검증 모형이나 화면을 실제 배포 완료로 표시하지 않는다. 이 게이트가 실제 설치를 구현보다 먼저 집행하라는 뜻은 아니다.

## 확인 전 허용 범위

리서치, 기획·문서, 인터뷰, 대안 비교, 실제 운영과 분리된 기획 검증용 코드·파일·프로세스·모델 세션 실험. 공식 Pi 실험 카드 r1496/r1497은 격리 검증 범위로만 진행한다.
제품 코드·배포 패키지 구현, 운영 설정 전환, 실제 배포/설치/마이그레이션은 컨펌 전 시작하지 않는다. 실험용 구현의 존재가 제품 구현 승인을 대신하지 않는다.

범위 해석(팀장 질문275499에 대한 메인 회신): 이 게이트는 ft2.0 제품 구현·전환에 적용한다. 이미 별도로 발주·승인된 1.x 결함 수정은 기존 카드 범위·검증·설치/HIL 조건에 따라 계속한다. 이 해석은 새 작업이나 배포 권한을 부여하지 않는다. 1.x 수정에 2.0 상태 모델·폴더 이관·세션 수명 전환을 섞지 않으며, 실험 기준선이 바뀌면 버전·commit·설치 차이를 기록한다.

## 풀스펙 HTML에 포함할 운영 시퀀스

- 루트 접수와 planner·작업팀의 역할, 팀 생성·재개·정리.
- 골 생성 → 카드 분해 → arch 병렬 관리 → Pi 실행 → checker/tester → DA → 팀장 판정 → 착지·설치 → 골 마감.
- 역할별 기록과 대시보드, 실제 진척·응답·생존의 구분, 같은 멈춤 알림과 외부 대기.
- 접수·실행·완료의 차이, 중복 요청, 구 owner, 효과 미확정과 담당자의 해소 절차.
- 정상 진행·멈춤·재시작·동시 갱신·용량 초과·마감 중 새 골의 검사·분기·루프 복귀·중단 조건.
- 파일·폴더 정본/파생/쓰기 권한과 기존 일반화 PLAN의 유지·변경 지점.
- 완료 근거·결정은 Git 보존, 상세 로그의 유한 회전, 미처리·현재 복구 기록 보호.
- 세션 수명 두 후보의 실험 결과: 전 팀 묶음별 재개 vs planner 유지·작업팀 묶음별 재개. 실험 전 승자를 정하지 않는다.
- ft 소스·패키지·설치본·BYZ 루트의 버전/내용 대조, 단계별 전환·되돌림·최종 실동작 확인.
- BYZ 전 팀장 활성 준비, 대화·정지 전 기록·아카이브 회수, 골·카드·담당·미처리 정렬, 원본/대상 무유실 대조와 2.0 운영 이해·첫 재개 행동 확인. 한 팀이라도 미확인이 남으면 전체 이관 완료로 표시하지 않는다.
- 아직 미측정인 성능·토큰·캐시·전원손실·실환경 권한 경계와 최종 선택이 적용되는 범위.
- 메인 축인 Slack 공통 모듈의 기획·실험·독립 검증·실채널 양방향·복구·ft 패키지/설치 연결. Hermes는 참고하며 기존 봇 재사용/전용 신규 앱은 권한·연결 소유권을 확인해 선택한다.
- 2.0 기동 후 각 설치 환경의 doctor 요청/장애 반응→비모델 진단→국소 복구 또는 하네스팀 수정→재검증→기억·정본 환류. ft 프로젝트에 보존한 설계/진행 컨텍스트와 설치 버전을 연결한다.

기본 화면은 상황별 시퀀스와 실제 상태 변화를 보여준다. 긴 조사 원문·근거·결정 기록은 접힌 영역에 두되 확인할 수 있어야 한다. 현재 공개된 세 안 비교 매거진은 풀스펙 확정본이 아니다.

사용자 추가 지시(2026-11-09): HTML을 업데이트할 때마다 해당 파일을 다시 연다. 파일만 바꾸고 열지 않은 상태를 공개 완료로 보고하지 않는다.

## 컨펌 기록과 완료 판정

컨펌에는 문서 경로·버전 또는 hash, 사용자 답변 원문, 확정 범위, 남겨둔 한계를 붙인다. 추천안·DA 검토·실험 통과·인터뷰 선택 하나를 제품 구현 컨펌으로 대체하지 않는다.
현재 컨펌: **미수신**. 실제 제품 구현·랜딩·설치·이관 완료: **아님**.
전체 골은 최종 설치본에서 골 접수·작업·검증·마감·새 골 재개를 checker가 확인한 뒤 닫는다. 이번 게이트는 전체 골을 축소하지 않고 구현 시작 전에 사용자 이해·승인을 추가한다.
