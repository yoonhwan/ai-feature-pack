# planner 유지 여부: 세션 수명 비교 실험

상태: 사용자 인터뷰의 선택 유보를 닫기 위한 실험 설계. 제품 구현·실행 설정 전환 승인 아님. 실행 전 입력과 환경을 고정하고, 파일 상태 실험 r1496/r1497과 별도 결과로 기록한다.
메인: 현재 Astra. 근거: INTERVIEW-ft20-decision-20261109.md의 질문2 최신 사용자 답변, GATE-ft20-full-spec-before-implementation-20261109.md, arch 수신275507.

## 비교할 두 후보

| 이름 | planner 팀장 | 작업팀 팀장 | 공통 조건 |
|---|---|---|---|
| 전 팀 묶음별 재개 | 판단 묶음 종료 후 기록·종료, 다음 묶음에서 새 세션으로 역할 재개 | 판단 묶음별 재개 | 골·역할·기록·판정 책임은 지속하며 고정 절차는 비모델 |
| planner 유지 | 프로젝트 골이 남아 있는 동안 같은 세션 유지, 새 판단 때만 호출 | 판단 묶음별 재개 | 무의미한 주기 모델 호출0. 전체 골0 종료 원칙은 유지 |

사용자는 처음 전 팀 묶음별 재개를 선택한 뒤 planner 유지도 실험으로 비교하라고 보완했다. 어느 후보도 확정하지 않는다. 프로세스 유지와 매틱 모델 호출을 같은 비용으로 세지 않는다.

## 선행과 실행 범위

- r1496/r1497의 접수·owner·미확정·마감 안전성 결과를 먼저 받는다. 실패/명세 미완이 비교의 상태 복구 계약에 영향을 주면 관련 부분을 고친 고정 후보 없이 다음 단계로 넘어가지 않는다.
- 실제 운영 planner·작업팀 세션을 사용하지 않는다. 공식 FT Pi 실험 카드로 격리된 테스트 세션만 생성한다. 새로운 nano는 Pi다. 기존 서비스·좌석·명부·큐·Slack·설치본 변경0.
- 같은 에이전트/모델/effort/도구 허용 목록/프롬프트 계약/fixture를 사용한다. 차이는 planner 세션 유지 여부뿐이다. 모델 ID·실제 요청 옵션·계정/캐시 관측 가능성을 실행 전 기록한다. 비밀값은 저장하지 않는다.
- 세션을 생성·종료하는 테스트 러너가 자기 테스트 프로세스만 정리한다. 다른 세션 종료0, 세션 작업 폴더와 로그를 산출에 보존한다. 실제 FT 좌석 종료는 기존 정상 닫기 경로를 따른다.
- 제품 효과 대신 파일 대역을 쓴다. 하지만 모델 토큰·캐시·세션 재개는 실제 실행에서 측정한다. 파일 모형의 호출0을 이 실험의 비용0으로 대체하지 않는다.

## 동일 입력: 네 판단 묶음

| 순서 | 입력 | 기대 출력·복구 검사 |
|---|---|---|
| 골 배정 | 작은 골1개, 작업팀2개 후보, 제약 파일v1 | 허용 팀 선택·카드·owner·닫는 조건. 선택 이유와 입력 revision 기록 |
| 의존 조정 | 두 작업 결과 중 하나에 의존 충돌. 정본에 지난 결정·미처리 사건 존재 | 누락 없이 다음 작업 선택. 실제 진행 근거와 응답 시각을 혼동하지 않음 |
| 조건 변경 | 사람이 제약 한 항목을 v2로 바꿈. 옛 실행자 결과도 도착 | 최신 제약 적용, 옛 owner 결과는 검증 없이 완료 근거로 채택하지 않음 |
| 마감·재개 | 완료 근거와 미확정 효과를 섞어 제시한 뒤 해소 증거, 마감 직후 새 골 | 미확정 때 닫힘 거절, 근거 후 마감, 새 골 보존·재개. 파일과 대역 효과로 확인 |

각 묶음의 사용자 입력과 골·카드·사건은 같고, 핵심 출력은 고정 schema로 판정한다. 프롬프트/fixture hash와 차이를 남긴다. 각 모드의 작업팀 실행 조건과 결과는 동일하게 고정한다. planner의 기억만으로 정본을 건너뛴 답은 성공으로 치지 않는다.
전 팀 묶음별 재개는 공통 파일에서 필요한 정보를 실제로 읽고 재개한다. planner 유지는 같은 파일의 변경분을 읽는다. 둘 중 하나에만 정답 요약을 주입하거나 과거 토큰을 계산에서 빼지 않는다.

## 계측과 독립 판정

| 축 | 기록 |
|---|---|
| 안전성 | 접수/결과 누락, 옛 owner 수락, 미확정 자동 재실행, 잘못된 마감, 신규 골 소실, 추가 사람 확인 횟수 |
| 세션 수명 | 모델 세션 ID·프로세스 기동/종료 횟수·각 묶음의 시작/종료·재개 성공. 세션 ID와 작업 ID를 구분 |
| 토큰·캐시 | 요청별 input/output/cache-read/cache-write 등 제공된 원시 usage. 제공되지 않는 필드는 미측정. 추론 토큰은 별도 제공될 때만 기록 |
| 지연 | 묶음 접수→판단 결과, 프로세스 시작→첫 유효 결과, 복구 소요. 모델 응답 지연과 로컬 기동을 구분 |
| 파일·컨텍스트 | 읽은 파일/bytes, 주입한 골·기억·이전 대화의 크기, 출력 근거 revision |
| 운영 부담 | 역할 재개 실패, 수동 개입, 복구 단계, 상주 프로세스 유지 비용. CPU/RSS를 재지 않으면 미측정 |

checker는 같은 모델의 자기 채점에 의존하지 않는다. 실제 출력 schema·고정 기대 조건·상태 파일·효과 대역·usage 로그를 독립적으로 대조한다. 모델이 «완료»라고 쓴 문장이나 내부 success flag는 판정 근거로 충분하지 않다.
첫 비교는 제한된 표본이다. 캐시 선점, 실행 순서, 공급자 상태, context 재구성 차이를 기록한다. 반복 횟수로 통과를 만들지 않으며, 편향을 분리할 수 없으면 비용 우열을 판정불가로 남긴다. 시간 한도 내 종료를 제품 SLA 통과로 쓰지 않는다.

## 상한과 중단

- 요청·도구·시험 시간은 기존 외부 호출7초·로컬 하네스25초·시험1개70초·회차7분·동시4개 한도 안에서 나눈다. 긴 모델 요청이 필요하면 한도를 숨겨 늘리지 말고 입력을 줄인 별도 사례로 기록한다.
- 재시도는 실패 지점만1회. timeout을 성공으로 대체하지 않는다. 캐시 유지 시간을 맞추기 위한 sleep0. 실제 캐시 수명이 필요한 검증은 관측 가능한 후속 사건으로 분리한다.
- 실제 운영 자원에 접근하려는 도구 호출, fixture 밖 쓰기, 허용되지 않은 외부 효과는 실험 실패로 중단한다. 제품 수정이나 운영 전환으로 이어가지 않는다.

## 선택 규칙

안전성 미통과 후보는 비용이 낮아도 채택하지 않는다. 둘 다 안전하면 총 input/output/캐시·묶음 지연·재개 실패·복구 절차를 나란히 공개한다. 토큰 단가나 허용 지연을 임의로 합쳐 단일 점수를 만들지 않는다.
한 후보가 근거상 우세하면 메인이 추천 이유와 관측 범위를 쓴다. 지연/비용이 엇갈리거나 표본·계측이 부족하면 그 tradeoff만 사용자에게 묻고 자동 채택하지 않는다. 새로운 구조를 섞으면 별도 보완판으로 재검증한다.
결과는 풀스펙 HTML의 세션 수명 시퀀스와 한계에 반영한다. 사용자에게 전체 운영을 설명한 뒤 명시 컨펌을 받기 전 제품 구현은 시작하지 않는다.

## 산출과 완료

실험 담당: 고정 입력·명령·환경 manifest·원시 요청 usage·출력/상태/효과 로그·모드별 비교 결과. 독립 checker: 같은 근거와 실패 사례를 대조한 판정. 기록은 승인된 research 폴더, 실제 임시 실행은 별도 빈 폴더.
현재 실행: **미착수**. 모델·토큰·캐시·지연 측정: **없음**. 카드번호·좌석·실행 commit은 배정 후 기록한다. 이 문서 작성이 실험 완료를 뜻하지 않는다.
