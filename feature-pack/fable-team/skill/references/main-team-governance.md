## 1. 좌석 이름 규칙 (P6 · 프로젝트 `design/harness/issue-improvement/SPEC-session-naming-20261005.md` §2 사본)
- 문법 `<프로젝트>-<팀>-<역할>[-<꼬리>]#<N>` · 역할 예약어 10 = master arch da tester checker analyst pm nano repro tool · 역할 좌석 꼬리 = 에이전트(claude|codex|opencode|cmd|pi) 필수 · nano 꼬리 = 카드 slug · 소문자·숫자·`-` 만 · 길이 ≤ 60. 검사 = `ft-name-lint.sh <이름>`.
- **메인 팀 총괄(오케) 역할명은 전 팀 `master` 로 통일**(오빠 10-07 «master 가 메인오케다»): `byz-v65-master-claude` · `byz-cfo-master-claude` · `byz-planner-master-claude` · `byz-harness-master-claude` · `byz-issues-master-claude`(팀 글자 = 명부 파일명 `seats-<팀>.json` 과 같게).
- `#N` = 승계마다 +1 이며 **옛 이름의 번호를 이어받는다**(예 `ft-v65-master-claude#142` → `byz-v65-master-claude#143`). 승계 때 자연 교체 — 살아 있는 세션을 rename·kill 하지 않는다(구 세션 닫기는 오빠/팀 판단).
- 이 이름 규칙은 SKILL.md 의 구 규약 `ft-<slug>-<role>#0` 를 **신규 좌석부터 대체**한다.

## 2. 이슈 진입로 3 + 컨펌 게이트 (현재 유효)
역할: **planner** = 메인 PM(오빠와 직접 대화·AskUserQuestion 은 planner 만) · **issue-master** = 이슈 모니터·생성·종료·배분 총괄(하위 좌석 — 인터뷰 금지).
- issue-master 가 **스스로 하는 것**: 모니터 · 읽기 · 분류/우선순위 «안» · LOOP-LEDGER · 재현 스텝 조사. **오빠 컨펌 뒤에만**: 배분 · 착수 · 라벨 부착/변경 · 채택/배분 코멘트 · 닫기.

| 진입로 | 흐름 | 컨펌 |
|---|---|---|
| ① 밀어올리기 | issue-master 가 `[HIL]` 묶음 1통(이슈 내용 3줄 · 권장 우선순위·이유 · 진행 방식 · 선택지) → planner 가 AskUserQuestion 으로 설명·컨펌 → 값 회신 | 오빠 인터뷰 필수 |

## 6. 하네스 기획 arch 상시 좌석 (오빠 2026-10-07 「작업들 arch 검토 받고 결정 진행. 독단으로 하지 말고」 · arch 안 byz-harness-arch-claude#5)
- 좌석: `byz-harness-arch-claude#N` · 모델 Opus 5.5 high 상시 · Fable 5.1 은 에스컬레이션(같은 건 2회 수렴 실패·신규 구조 설계)만, 닫히면 Opus 5.5 로 복귀.
- 역할: arch = 설계·검토·판정 «안» · master = 집행(커밋·push·설치·좌석 개설/닫기·명부). arch 는 커밋·push·설치·좌석 조작을 하지 않는다(설계 초안 파일 Write 만, 커밋은 master).
- arch 검토 대상(안 없이 집행 0): ①설계·새 스크립트/훅 기능 ②가드·차단 훅(설치·등록 포함) ③설치·배포(홈 디렉터리·settings.json·~/.tmm·원격 머신) ④정본 변경(governance·COMM-GUIDE·BOOT·스킬 SKILL.md·전역/프로젝트 CLAUDE.md) ⑤좌석·모델·이름 규칙 변경 ⑥PR 랜딩 순서·되돌림.
- master 직접(검토 불요): 조회(seats·map·gh view) · 문서 오타 · 원장 행 추가(결정 없는 기록) · 나노 생존 확인 · «집행».
- ★«집행» 정의(arch#5 판정 10-07)★: 랜딩·커밋·push·검증된 파일의 설치 복사(cp+cmp)·.bak 복원·머지 충돌의 문서 줄 순서 정리·좌석 개설/닫기·명부·원장 기록. ★파일 «내용을 쓰는 것»은 집행이 아니다★ — 코드·스크립트·훅·시험 = 나노, 시안·설계 = arch. 나노 증거 줄 REJECT = 그 나노에 반송(닫힌 나노면 재spawn). arch 안이 있어도 master 가 «손으로» 쓰지 않고, 안 없이 집행하지도 않는다(오빠 「독단 금지」 둘 다). 전역 「한 턴 코드 2파일」 은 팀 좌석 없는 단독 세션용이고 팀 master 는 0.
- 흐름: master 발주(mbox · 골 원문 3줄 + 골 축 1줄) → arch 안(결론 1줄 · 승인/수정/반려 · 이유 3줄 · 근거 경로 · 긴 것은 design/harness/ 초안 파일) → master 집행 → master 가 결과(sha·설치 위치·되돌림 명령)를 arch 에 통지 → arch 닫힘 확인 1줄.
- 사후 검토: 긴급(라이브 장애·권한 사고)으로 master 가 먼저 집행했으면 같은 턴에 arch 에 사후 검토 발주 + 되돌림 명령을 함께 적는다.
- 오빠 값을 arch/master 판단으로 뒤집지 않는다 — 다르게 가자는 안은 §7 경로(planner [HIL])로 값을 다시 받는다.
- 나노 접두 = 팀 env 파일의 `FT_NANO_PREFIX`(`byz-<팀>-nano-`) — spawn·close·카드 키가 같은 값을 쓴다. 옛 이름(`ft-<팀>-temp-`) 나노가 살아 있으면 그 한 건만 명령 앞에 접두를 주입한다.

## 8. 일의 시작과 끝 (오빠 2026-10-23 «하네스팀 발주 마지막 하나» · slack 1792732863.955709)
> 「시작시 깃 이슈 기반으로 작업 시작. 과정을 기록. 랜딩 기록. 그리고 원장 아키텍처문서에 완성까지가 랜딩. 해당 파일을 깃이슈에 등록하고 정리 마무리. 완성.」
> 「각 팀은 완전히 팀 일이 마무리 (정본화) 완료되면 대기하는것을 목표로하며 중간에 멈추려하면 안된다.」

1. **일은 깃 이슈로 시작한다.** 카드의 «Issue:» 줄은 열린 깃 이슈 번호여야 착수할 수 있다. 이슈가 없으면 먼저 만든다(하네스 안쪽 결함도 같다 · 예외 없음 · planner 판정 2026-10-23).
2. **완성 = 과정·랜딩을 기록하고, 그 내용을 원장·아키텍처 정본 문서에 넣어 main 에 착지하고, 그 정본 파일을 깃 이슈에 등록한 때다.** 코드가 main 에 들어간 것만으로는 완성이 아니다. 이슈 코멘트에 «정본: 파일#절@sha» 한 줄이 있어야 카드를 완성으로 옮긴다.
3. **정본화가 끝나기 전에는 «대기»·«정지 레디» 를 선언하지 않는다.** 팀의 진행 카드가 0 이고 마지막 완성 카드의 정본 줄이 있을 때만 대기다. 예외는 «오빠 답·승인 대기» 와 «바깥(다른 팀·외부 서비스) 대기» 뿐이고, 그때는 무엇을 누구에게 기다리는지 한 줄을 쓴다.

## 10. 규칙 먼저 · 훅·스크립트 과적합 금지 (하드 룰 · 오빠 2026-10-27)
> 「하네스팀지침에 하드룰 업데이트 훅과 스크립트 과적합방지 파일명 규칙이면 끝날거같은 시작붙」 · 「타시작부터 방향잡으면 바로해결되는것 같은것들」
> 「이렇게해결하면될걸 안되는걸 밤새」 · 「되게하려 스크립트만들고 훅만들고 하던게 전부.과적합이다」

1. **카드를 설계할 때 arch 가 먼저 묻는다: «규칙 한 줄로 입력 범위를 정하면 끝나는가».** 끝나면 규칙 한 줄로 닫는다(예: 하드 룰 18 «파일 이름에 줄바꿈·탭 금지» 로 r978 을 닫음). 훅·스크립트는 규칙으로 안 끝날 때만 그다음에 고른다.
2. **반례를 통과시키려고 훅·스크립트·검사기를 덧대지 않는다.** 반례 입력이 우리 실제 사용에서 생길 길이 0 이면 그 반례는 [범위 밖] 이다. DA 도 처음부터 [범위 밖] 으로 적고, arch 는 첫 보류에서 «규칙으로 범위 제한 → 닫기» 를 선택지 1번으로 올린다.
3. **이미 덧댄 것은 걷어낼 후보다.** 반례 통과용으로 붙인 훅·스크립트는 규칙 한 줄로 대체할 수 있으면 걷어내는 카드를 연다(planner 후보 표 → 오빠 확인).
4. **같은 뜻의 전역 하드 룰**(오빠 10:3x «예 — 둘 다 넣음»): 18 파일 이름 줄바꿈·탭 금지 · 19 우리 도구가 만드는 파일은 일반 파일(0444·폴더·심링크 입력은 [범위 밖]) · 20 외부 명령 실패는 한 함수가 «판정 불가» 1줄로 끝냄(실패 주입은 반례 아님).
5. **결정 뒤 검증은 동작 반례만 다시 묻는다**(하드 룰 21 · 오빠 12:3x «그거개선해도 지금 느린거? 해결이 안되는거자나? 이슈하나하나가»). 오빠 결정 뒤 검증에 남은 반례가 전부 비동작(오류 번호·형식·줄 수·문구)이면 묻지 않고 착지한다. 남은 것은 카드 «알려진 한계» 1줄로 적는다. 동작 반례(틀린 결과·유실·잘못된 판정)가 남을 때만 인터뷰한다. arch 는 반례마다 «동작/비동작» 1단어를 적는다.
6. **새 가드·정리 도구는 켜기 전에 지금 도는 대상 전부로 시험 1회 한다**(회고 P4 · r1004 가드가 보드 글을 지움 · zombie-clean 이 일하는 좌석을 회수). 켜는 좌석이 `--dry-run`(없으면 같은 입력의 읽기 전용 1회) 결과를 카드 상태 절에 붙인다. 지울·막을 대상에 정상 발행물·일하는 좌석이 1건이라도 있으면 켜지 않고 arch 에 돌려준다.
7. **하네스 팀장 틱 보고 첫 줄 = «착지 후 미이동 N»**(회고 P1). 착지했는데 아직 완성으로 안 옮긴 카드 수다. 0 이 아니면 그 틱에 옮긴다(`~/.claude/guides/card-flow.md` «착지한 그 턴에 완성 이동»).
8. **우편 규칙**(회고 P7 · 오빠 «하네스팀장이 box 를 너무 밀려받는다»). 나노의 [완료]·산출·질문은 arch 에 직접 보낸다. arch 의 반송·답도 나노에 직접 보낸다. 팀장(master)에게는 착지·spawn·닫기 요청만 보낸다. 그 밖의 정리는 틱당 1통으로 묶는다.
9. **후계 좌석의 부팅 보고가 도착한 턴에 직전 세대를 닫는다.** 받는 좌석이 `ft-seat-retire`(재개 기록 1줄) → 직전 세대 `CronDelete` → kill 을 그 턴에 한다. 승계 뒤 같은 계보에 3세대가 함께 살면 정리 도구가 일하는 좌석을 회수한다(10-27 08:40→08:45 · 13:38→13:39 두 번 재현).
10. **stop-ready 로 바꾼 좌석은 그 턴에 `CronDelete` 한다.** 틱이 계속 돌면 대화 기록이 계속 쓰여 정리 판정이 흐려지고 토큰도 샌다.

## 13. 팀장 모델 사다리 (오빠 2026-10-28 10:0x «각 팀장들은 sn5.5를 기본 브레인으로 사용» · desk #177328)
> 「문제해결되지 않을때 아키랑 da를 상위로 올릴 타이밍에 사용 · 다음 세션 넘어가면 자연스럽게 울트라 종료」 · 「팀장도 문제해결되지 않을때 op5.5로 증류 가능」

1. **기본 브레인 = Sonnet 5.5**(`claude-sonnet-5-5`). 승계·개설 때 `--model` 을 안 적어도 팀장(master) 좌석은 이 값이다(도구: `ft-successor-open.sh`).
2. **이월은 모델과 «따로» 고른다 — `--carry 0|1`** (오빠 2026-10-28 «sn5.5 > sn5.5 증류시에도 ultrathink 이월가능하고 sn5.5 > op5.5 도 되고 op5.5 > op5.5 도 이월가능»). 승계하는 팀장이 그 자리에서 정한다. 문제가 아직 안 풀렸으면 `1`, 풀렸으면 `0`. **보통은 모델을 올리면 1·내리면 0 으로 같이 가지만 강제로 묶지 않는다** — sn→sn 이월, sn→op 이월, op→op 이월, op→sn 내려오면서 0 이 전부 가능하다.
3. **이월 1 의 효과 = 알림줄 꼬리 하나.** `--carry 1` 이면 검증 송신과 링 재시도에 `FT_DOORBELL_TAIL=ultrathink`(r1036)가 켜지고 발주문 끝 줄이 «승계 이월 1: 앞 세션의 확대 사고를 이어 받는다. 문제가 풀리면 다음 승계에서 이월 0.» 이 된다. 생략·`0` 이면 r1034 와 같다(«승계 이월 0» 한 줄). **그 낱말 자체는 발주문 본문에 적지 않는다** — 적으면 후계 세션이 바로 켜진다.
4. **그래도 안 풀리면 Opus 5.5**(`claude-opus-5-5`)로 승계한다. `--model op`(또는 풀네임) 를 명시하고, 문제가 이어지는 중이면 `--carry 1` 을 같이 적는다. 풀리면 다음 승계에서 `--model sn` + `--carry 0` 으로 돌아온다.
5. **사용례 한 줄**: `ft-successor-open.sh <구 좌석> <워크트리> --name <후계> --agent claude --model sn|op [--carry 0|1] --body-file <본문>` — `sn` = `claude-sonnet-5-5` · `op` = `claude-opus-5-5` (그 밖의 값은 그대로 넘어간다). `--carry` 는 값 `0`·`1` 만 받고, 팀장(master) 이름이 아닌 후계에 적으면 usage rc2 로 열지 않는다.
6. **arch 기본 = Opus 5.5(`claude-opus-5-5`) · 팀장만 Sonnet 5.5** (오빠 2026-10-28 13:5x · r1043). `--model` 을 안 적으면 `ft-successor-open.sh` 는 arch 이름(claude)에 Opus, 팀장(master) 이름에 Sonnet 을 준다. `ft-role-spawn.sh` 는 `--model` 생략 + role=master(claude) 일 때만 Sonnet(`claude-sonnet-5-5[1m]`), 그 밖(arch 포함)은 Opus(`claude-opus-5-5[1m]`). 명시한 `--model` 은 두 도구 모두 덮지 않는다.
7. **DA 기본 = `gpt-6.1-sol` effort low** (오빠 2026-10-28 19:2x 슬랙 1793182921.486359). `ft-da-codex.sh` 는 `--effort` 를 안 적으면 low 다(r1066). 어려운 판정에서만 부르는 쪽이 `--effort high` 를 적는다.
8. **상황별 최상위 = fable(`claude-fable-5-1`)·astra(`gpt-6-astra`)** (같은 오빠 슬랙). 하드 룰 14 로 arch·DA 를 올리는 시점에 arch 는 fable, DA 는 astra(또는 sol high)로 승계한다. 문제가 풀리면 다음 승계에서 기본(arch Opus 5.5 · DA sol low)으로 내린다.
9. **증류·승계 때 모델 = 명시가 없으면 역할 기본** (같은 오빠 슬랙). `ft-successor-open.sh`·`ft-role-spawn.sh`·`ft-tmux-distill.sh`(r1067) 모두 같다. 옛 좌석 모델을 그냥 잇지 않는다. 올린 모델을 이어야 하면 `--model` 을 적는다.

## 16. 검토·격리 사본 = ft-scratch-repo (오빠 2026-10-29 디스크 긴급 · r1079)
> 근거: 10-29 새벽 arch#174 실측 — 세션 scratchpad(`/private/tmp/claude-501`) 아래 `.git` 140개, 114GiB. 사본이 장부 밖이라 하루 1회 정리(ft-scratch-repo --sweep)가 보지 못했다. 하네스 arch 인계서(`design/harness/HANDOFF-arch173-to-174-20261029.md` §2)가 «`git clone --shared` 로 `<scratchpad>/x` 에 만든다» 는 꼴을 그대로 적어 두었던 것이 원인이다.

1. **세션 scratchpad 안에 git 사본(clone·worktree add)을 만들지 않는다.** `git clone`·`git worktree add` 의 대상 경로가 `…/scratchpad/…` 이면 안 된다. 근거 = 10-29 `/private/tmp/claude-501` 114GiB(사본 140개 · 장부 밖이라 정리 0).
2. **검토·격리 사본은 `ft-scratch-repo.sh <sha> [--repo <저장소>]` 로 만든다.** 출력 1줄이 사본 경로다. 팩 저장소는 `--repo /Users/yoonhwan/Project/ai-feature-pack` 를 적는다. 이 도구는 사본을 장부(`.fable-team/state/scratch-repos.tsv`)에 적고, 주인이 없어지면 sweep 이 정리한다.
3. **끝나면 `ft-scratch-repo.sh --done <경로>` 로 닫는다.** 격리 보고를 보낸 그 턴에 닫는다. 같은 sha 를 다시 볼 일이 있으면 닫기 전까지 그 사본을 다시 쓴다(같은 sha·같은 주인은 재사용).
4. **변이 시험은 사본 안에서 하고 `git checkout -- .` 로 되돌린 뒤 `--done` 한다.** 되돌리지 않은 더러운 사본은 `--done` 이 거절한다(더러운 사본 = 삭제 0).
