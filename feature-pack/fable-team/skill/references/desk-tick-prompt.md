# desk 틱 프롬프트 (정본 1줄)

## 프롬프트 — 이 줄을 그대로 쓴다
```
bash <LIVE_BIN>/ft-desk-tick.sh <내 좌석>   # 1회. 마지막 줄 «결정 필요: 0» 이면 도구 0회로 턴 끝 · N≥1 이면 그 항목만 도구 1회
```

`<LIVE_BIN>` = `~/.claude/fable-team/live/<판>/bin` (라이브 설치 자리). 승계 본문·틱 발주문에 이 한 줄만 넣는다.

## 왜 — 요청 1개는 그 순간 컨텍스트 전체를 다시 읽는다
| 항목 | 전(desk#121 · 32분) | 목표 |
|---|---|---|
| E1 깨우는 턴당 요청 | 4.52 (턴 31 · 요청 140) | ≤2 |
| E2 요청당 cacheRead | 126,852 (합 1,776만) | ≤60,000 |
| E3 틱 1회의 도구 수 | 4~6 | 1 |
| 캐시 prefix 끊김 | 3회 · 재작성 28.8만 토큰 | 0 (계정 고정 확인 뒤) |

원인은 모델이 «6항을 직접 재는» 틱 본문이다. 항목마다 도구 1회 = 요청 1회 = 컨텍스트 전체 재읽기. 재는 일을 비모델 스크립트로 옮기면 틱 1회 = 요청 1회가 된다.

## 이 줄이 대신하는 것
승계 본문의 `승계 본문 6항대로 직접 잰다: ①ft-hil --pending ②launchctl ③팀장별 쪽지 ④받은편지함 감시 ⑤mbox recv ⑥planner _master 에 [완료]` 를 이 1줄로 바꾼다.
여섯 항목은 [`ft-desk-tick.sh`](../../../harness/bin/ft-desk-tick.sh) 가 대신 한다 — 출력 ≤30줄 · 항목당 7초 · 전체 25초 · `⑥ [완료] 3줄` 발송도 스크립트가 조립한다(모델 출력이 아니다).

## 하지 않는 것
- 모델이 `ft-desk-tick.sh` 를 «두 번» 부르지 않는다. 두 번째 호출은 [완료] 쪽지를 한 통 더 보낸다.
- 스크립트는 아무것도 실행하지 않는다. `h<N>` 계획 실행·서버 재기동·press 는 사람 또는 해당 좌석 몫이다.
- `결정 필요: 0` 인데 상태를 «더 확인» 하려고 도구를 부르지 않는다. 그 확인이 곧 E1 위반이다.
- 판정이 「판정 불가 rc=N」 이면 그 항목만 손댄다(전체를 다시 재지 않는다).

## 측정 — 카드가 닫히는지 보는 법
```
python3 <LIVE_BIN>/ft_waste_measure.py <desk 세션 jsonl> [--since <ISO>]
```
`E1 · E2 · E3` 줄과 `BREAK count=` 줄이 나온다. 기준을 넘으면 `FAIL <항목>` 줄 + rc1. 착지·설치 뒤 desk 다음 세션 jsonl 1회로 E3=1 · E1≤2 를 확인한다.
