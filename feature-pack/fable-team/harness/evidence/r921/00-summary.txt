r921 — 자원·상한 «정지» 를 «회수 먼저 → WARN 1줄 + 진행» 으로 (팩 브랜치 nano/r921-resource-stop-to-warn-and-proceed · BYZ Issue #3569)

오빠 원문(2026-10-25 21:5x · master#112 전달): «이런 제약하지마라. 컴퓨터가 죽어버려도 개발은해야지 멈춰있으면 머할건데. 더 스마트하게 움직여라.»

■ 한 규칙
  넘으면 ① 회수 먼저(ft-resource-reclaim · 기존 표준승인 범위 그대로) → ② 다시 재고 → ③ 그래도 넘으면 «WARN 1줄(무엇이 · 얼마 · 문턱) + 진행»(정지 0 · rc0).
  예외 = «진짜 못 쓰는 것» 만 거절: 디스크 여유 < FT_DISK_HARD_MIN_MIB(기본 1024 MiB) · 디스크 측정 실패. 그 밖 측정 실패는 «못 재면 멈출 근거도 없다» 로 WARN + 진행.

■ 멈춤 지점 6 — 전 / 후
  ① 문지기 ft-resource-gate.sh check
     전: disk·swap·memfree·level·rate·agents 중 하나라도 넘으면 `REJECT resource …` exit 3 · 동결 파일 = REJECT · 측정 실패 = `ERROR resource measure` exit 4
     후: 갈래 3개 — OK(exit 0) / WARN(`WARN resource …` 1줄 + exit 0) / REJECT(디스크 하드 하한·디스크 측정 실패만 exit 3). 동결은 «알림용» WARN 으로 강등(오빠 10-19 «동결 표식이 머냐고 또 막고 앉았네»). exit 4 폐기.
  ② ft-nano-spawn.sh 문지기 호출
     전: rc≠0 이면 reclaim 1회 → rc≠0 이면 spawn 0
     후: WARN 이면 reclaim 1회 → 재검 → 그래도 WARN 이면 WARN 1줄 남기고 진행. REJECT(디스크)만 회수 호출 0 으로 즉시 정지.
  ③ ft-role-spawn.sh — ②와 같은 꼴(같은 문구·같은 순서). ft-successor-open.sh(승계)도 같은 규칙으로 맞췄다(--succession 문턱은 그대로).
  ④ ft-tick.sh:703 죽은 좌석 재개
     전: 문지기 rc≠0 = «재개 0»
     후: REJECT 만 재개 0 · WARN 은 `lines` 에 «자원 WARN — 재개 진행: …» 1조각 남기고 재개(회수는 부르지 않는다 — 재개 대상은 이미 죽어 라이브 목록에 없고, 회수는 살아 있는 유휴·완료 좌석만 닫는다).

     후: 상한 삭제(일반 나노와 같은 규칙) — 잠금만 남긴다(동시 개설 직렬화). 셈 실패는 WARN 1줄 + 진행.

     후: 회수 1회 → 그래도 AT-CAP 이면 `WARN resource teamset AT-CAP …` 1줄 + 그대로 연다(live=cap+1) · 순번 큐 적재 0.

■ 실 spawn 1회 (카드 완성 조건) — master 집행 몫

  press 필요: 없음 — 이 카드는 라이브 오디오·UI 를 건드리지 않는다(시험은 단위·캡처·기존 로그만).
