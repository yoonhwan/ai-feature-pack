또한 create 성공 뒤 응답 유실/서버 처리 지연이면 검색 시점에 제목이 아직 안 보일 수 있습니다. 선기록 없는 재실행이 그 부재를 근거로 다시 create하면 중복입니다. 등록 시도 id/불명 상태를 영속화하고, 동일 식별자의 원격 확인 없이는 자동 새 create를 막아야 합니다. 검색 오류·불완전 결과는 Tank 0으로 종료해야 합니다. comment k 실패 후 즉시 중단·label 0·수동 잔여 안내(113행)는 수락하지만 이 정상 부분 실패 처리만으로 생성 응답 유실까지 중복 0이 되지는 않습니다.

141행 시험에 같은 제목/다른 식별자, 동일 식별자 부분 등록, create 성공 뒤 응답 유실·일시 검색 미노출, 조회 실패를 추가하세요. 분할 수동 안내는 실패 comment가 원격에 만들어졌을 가능성도 표시하여 사람이 해당 조각의 원격 존재를 확인한 뒤 이어 쓰게 해야 합니다.

### R2-B — HOLD: 새 md 단계와 HTML 캐시의 완료/원본 계약 누락

126행의 posted→md→done은 md 공유 성공을 로컬에 기록한 뒤 HTML이 실패한 경우에는 도움이 됩니다. 그러나 md complete가 원격 성공한 뒤 응답 유실 또는 md 단계 저장 실패면 phase는 posted라 재실행이 새 md 파일을 공유합니다. HTML 성공 뒤 done 저장 실패도 동일합니다. 기존 publish는 upload_file 뒤에 phase를 기록할 뿐입니다(byz_proposal_publish.py:139–140). 새 r2의 ‘첨부 2중·누락 없이’ 조건을 충족하려면 파일 종류/rN별 원격 표식·시도 기록·불명 차단을 추가해야 합니다.

현재 upload_file은 이미 on_file_id/on_not_shared 콜백을 제공합니다(magazine_slack.py:109–128). 그 기존 인터페이스로 공유 전 file_id를 영속화하고, 같은 파일 제목/원본 hash를 원격에서 확인·채택하거나 미확인 sharing이면 ERROR로 막는 계약을 정하세요. 원격 성공 불명에서 자동 새 파일을 발급하거나 같은 complete 호출의 안전성을 가정하지 않아야 합니다. md/HTML 각각 응답 유실·phase 쓰기 실패를 142행 회귀에 포함하세요.

125행의 `<팀>-<slug>-<rN>.html` 파일 존재만으로 캐시를 채택하면 같은 경로의 md가 바뀐 경우 HTML의 결정 박스/원문은 이전 내용, md 첨부는 새 내용으로 갈립니다. 캐시와 rN 발행 기록을 원본 md hash에 연결해야 합니다. 원격 부작용 전이면 불일치 캐시를 재생성할 수 있고, 이미 진행된 rN이면 고정 승인본을 계속 사용하거나 다른 rN을 요구하는 명시적 오류로 중단해야 합니다. 파일이 있다는 이유만으로 다른 원문을 설명하는 HTML을 채택해서는 안 됩니다.

### Eli5Error 가시적 저하 — 수락

125행의 Eli5Error는 부가 AI 표현 실패이며 md는 정본입니다. ERROR와 뿌리/답글의 원인 경고를 보여주고 md를 계속 발행하는 계약은 매거진 §r1/§r2에서 수락한 제한된 가시적 저하와 일치합니다. 사실 절 파싱·템플릿 실패는 발행 0이라는 분리도 맞습니다. 이 수락은 필수 사실 오류의 일반 면제나 AI 의미 정확성 승인이 아닙니다. HTML 없음의 원인/완료 상태도 해당 rN과 원본에 묶어 남겨 재실행에서 침묵으로 바뀌지 않아야 합니다.

### 통합 이관

신규 HOLD-R2-A/B를 함께 전달합니다. 필요한 교정은 제안서 동일성/등록 불명 차단, 파일 완료 불명 차단 및 원본 연동 캐시입니다. 기존 r1 승인이나 실험 절/시각 배치 등 범위 밖 요구를 다시 열지 않습니다. architect가 계약을 교정하고 master가 가짜 원격 장애 주입·통합·첫 실제 발행 검증을 집행합니다. 같은 범위 교정 한 번, 두 번째 HOLD면 통합 이관 후 연속 리뷰 중단입니다.

## §r2 교정 1 — #61813, 마지막 동일 범위 재검

고정 설계 SHA-256 `9feb3434f49c057552e6d2e9ecf6f6e5b97cad54642b7c2a28037c2dca2793fc`를 확인했습니다. R2-A/B와 직접 회귀만 검토했으며 앞 r1을 재개하지 않았습니다. 최초 r2 발주 12:03:01부터 누적 경과 약 12분, 이번 교정 약 3분 이내로 마지막 10분 한도 안에 종료합니다. 앞 검토 예산을 초기화하지 않습니다.

### R2-A 닫힘

설계 112–119행은 제목을 힌트로 한정하고 리포/상대경로/판정/본문 hash의 ID를 Issue 본문 첫 줄에 고정합니다. 후보 본문과 ID를 완전 대조하며 같은 ID만 채택하고, 제목만 같은 다른 ID는 충돌 오류·채택 0입니다. 생성 전 creating을 영속화하고 결과 불명은 기록을 남겨 자동 새 create를 막으며, 조회 실패·불완전은 Tank 0입니다. 분할 댓글 실패는 즉시 중단하고 원격에 생성됐을 가능성을 표시해 수동 확인을 요구합니다. 148행 시험이 이 반례들을 직접 고정했습니다.

구현에서 ‘확정 거절’은 원격 생성이 없었다는 근거가 있는 경우만 인정해야 합니다. 단순한 rc≠0/번호 없는 문자열/일반 오류 문구를 그 근거로 삼으면 기존 불명 차단이 깨집니다. created/comment-k 등 기존 시도 기록에 이미 Issue 번호가 있으면 검색의 일시 부재를 새 create 허가로 해석하지 말고 해당 번호/ID를 직접 확인하거나 보이는 오류로 멈춰야 합니다. 이 문구는 기존 생성 불명 차단의 구현 전제이며 새 HOLD가 아닙니다.

### R2-B 닫힘

교정의 publish 순서는 rN 기록에 원문 md_hash를 고정하고 내용 변경은 새 revision을 요구합니다. HTML 캐시명에도 같은 원본 hash를 넣고 Eli5Error는 omitted/reason/hash를 기록해 재실행에서 생략을 침묵으로 바꾸지 않습니다. 첨부는 magazine_attach.attach의 정확 제목 채택·공유 전 file_id 기록·sharing 불명 차단을 재사용하며, md/HTML 파일 제목도 해당 원본 hash를 포함합니다. 149행은 두 종류의 원격 완료 응답 유실·상태 기록 실패·불명 상태·다른 원문 캐시를 회귀로 고정했습니다.

실제 재사용 helper는 title 인자를 받고, 원격 제목을 먼저 조회한 뒤 sharing을 차단하며 on_file_id로 전송 전에 기록합니다(magazine_attach.py:29–46). 따라서 제시한 재사용 경계는 가능합니다. 모든 phase 저장이 md_hash·files·omitted 기록을 보존하고, AttachError를 정상 완료/새 업로드로 흡수하지 않아야 합니다. 키/캐시 hit 전에 해당 rN의 원문 불변성을 확인하고 같은 읽기 스냅샷으로 md/HTML을 생성·첨부해야 합니다. 기존 md 중간 상태를 유지한다면 files.md 완료와 같은 의미로 처리해야 하며 149행의 옛 ‘md 상태’ 시험 문구만으로 새 files 계약을 대체하면 안 됩니다.

### 최종 수락·남은 증거

R2-A/B 모두 닫혔습니다. Eli5Error의 경고·ERROR·md 계속 발행은 제한된 부가 표현의 가시적 저하로 기존 수락을 유지합니다. 생성/첨부의 불명 상태는 보이는 중단과 수동 확인으로 끝날 수 있으므로 ‘재실행 수렴’을 무조건 자동 완료라고 주장하지 않습니다. --force-create/--force-file은 사람이 원격을 확인한 명시적 수동 예외입니다.

최종 판정은 **§r2 교정 설계 APPROVE**입니다. 이번 신규 범위의 마지막 교정 1회를 사용했고 심사를 종료합니다. master가 가짜 원격 실패·본문 동일성·원문 캐시·매거진 회귀·실제 세트 발행 증거를 확인해야 합니다. 구현 SHA나 실제 외부 쓰기 동작 통과 승인이 아닙니다. 요청한 판정문 외 변경과 Issue/Slack/LLM·pytest 실행은 없습니다.
