## 추가 오빠 지시 (2026-10-05 · 비교 대상 3번째 후보)
> 「PTT 스타트한 다음에 디버깅 환경에서는 마이크 막고 사운드를 재생하는 버튼을 줘도 되겠네. 실제로 마이크 입력이 아니고 마이크 입력을 막아버리고 거기에 재생 입력을 흘려보내면 동작은 완전히 똑같이 되게 하는 거지.」
- 비교표에 **「디버그 재생 주입」** 행을 추가한다: PTT 시작 뒤 디버그 환경 전용 버튼이 실제 마이크 입력을 막고, 같은 캡처 경로(FE 오디오 그래프 입구)에 재생 소리를 흘려 «이후 동작은 마이크와 동일».
- **사실로 확인할 것**: ①FE 마이크 캡처 코드의 입구(getUserMedia 이후 어느 노드부터 공통인가) ②주입 지점 후보(MediaStream 대체 · 오디오 그래프 입력 교체 · 브라우저 가짜 장치) 중 코드 변경이 가장 작은 곳 ③디버그 전용 격리 수단(빌드/환경 플래그) 실재 여부 ④마이크 경로에만 있고 주입에서 빠지는 것(실제 장치 샘플레이트·AGC·에코 캔슬·권한 프롬프트).
- **제약**: #0 RULE(NO SILENT FALLBACK) — 디버그 주입은 «명시 옵트인 + ERROR 로그 + 화면 경고» 셋 다 있어야 하고 운영 경로에 새어 들지 않아야 한다. 주입이 «마이크와 완전히 같다»는 오빠 전제는 ④ 때문에 **검증 대상**이다(어디까지 같고 어디서 다른지 표로).
- 병렬 상한은 이 경우에도 마이크 외 «머신당 1» 자원(포트·Redis·vLLM·CDP 탭)으로 다시 계산한다.
