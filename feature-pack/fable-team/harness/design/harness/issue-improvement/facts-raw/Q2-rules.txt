Never build a main merge commit as `git commit-tree <feat>^{tree} -p origin/main -p feat` unless `git merge-base --is-ancestor origin/main feat` succeeded **in the same command right after fetch**. If main moved (another track pushed), tree=feat drops that commit's files.

**Why:** 2026-10-03 S10 (master-claude#133): RD_DECISION_ARCH#0 pushed 5410b5bfaa (16 docs files, 8197 lines) to main between my fetches; my check printed nothing (not-ancestor) and I pushed anyway → 339cee88dc deleted them. Restored forward-only with tree = `git merge-tree --write-tree origin/main feat` (2ccd036b8e), no force push.

**How to apply:** for every main push: fetch → `is-ancestor origin/main feat || abort` (exit, not an echo) → if main moved, build tree with `git merge-tree --write-tree origin/main feat` (check rc=0, no conflicts) → verify `git diff <moved main commit> <new> -- <its paths>` empty before push. Related: [[feedback_local_verify_before_push]].
