## checker 4축 실측 규칙

라이브 관측 판정은 **FE 콘솔 / poller·DOM / worker 로그 / durable 저장소(Redis)** 4축 전부. FE 콘솔 미확인 상태 "전사 실패" 판정 금지 · poller·DOM 미확인 "출력 없음" 판정 금지 · 복수 호출 전부 나열 + 실패 지표가 몇 번째인지 명시.
> **사용자가 눈으로 본 것과 분석이 어긋나면 분석이 틀린 것 — 안 본 축부터 본다.**

**다이렉트 확인 루프 (투 루프 체제)**: "관찰이 곧 판정"인 건은 설계 착수 전 즉결 확인 루프(워커 즉결 지시)로 실증팩(가설+판별결과·실물경로+타임스탬프·재현조건·코드앵커·잔여질문) 완성 후 architect 송부. fix는 1줄이라도 설계+DA 경유 / 동시 1개 / 실증팩 완성 전 architect·DA 병렬발주 금지 / 활성 이슈 오너는 발동 판정세션 — 타 세션은 발주 전 오너 확인.

**안티패턴**: 추측 큰 수정 / 이슈 병렬 조사 / 체커 수집 전 기획 / master approve-loop 중간 릴레이(판단 0 pass-through 예외) / DA 단순 승인 / 유닛 통과=완성 / **하류 수용**(근원 버그를 소비자 계약으로 승격 — 근원에서 고친다, 외부 신뢰경계 검증은 정당) / **오케 직접 데이터 분석** / **폴링 수동성**(확인과 수정은 병렬, wakeup은 행동 지연용 아님).
