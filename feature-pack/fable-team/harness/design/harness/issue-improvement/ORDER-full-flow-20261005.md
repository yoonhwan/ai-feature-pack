## 할 일 (문서 1장 · `SPEC-full-flow-20261005.md` · ≤200줄 · 구현 0)
P1~P7 확정분(PIECES·VALUES)을 **하나의 끝에서 끝까지 흐름**으로 다시 쓴다. 조각별 요약이 아니라 «한 건이 지나가는 길» 한 줄기 + 갈림길.
1. **본선**: 입력(오빠 말·GitHub Issue) → planner 접수번호·큐 → issue-manager Issue 등록·배분 쌍 → 메인 마스터 접수 → 카드 분해 → 나노 N 병렬(자리 5 + 라이브 예약석 1 · 빈 자리 같은 턴 채움) → 시험 묶음(tester 1·checker 겸임·bts·poller · press 필요 카드만 · architect 직접 보고) → **문제 확인 → 수정(나노) → 재시험 루프** → 나노 close·워크트리 정리 → main 랜딩(수거·후보 1개·후보 sha 최종 게이트·push·라이브 1회) → 마감(CLOSEOUT·Issue close·큐 클리어 3회신) → **삭제 단계**(워크트리·세션·브랜치 — 어디까지 자동 · 어디서 HIL).
2. **단계마다 4칸**: 누가 · 어떤 사건으로 시작 · 어떤 사건으로 닫음(닫는 증거) · 실패 시 어디로 돌아가나.
3. **갈림길 표**: 라이브 깨짐(예약석·보류·재개) · 시험 FAIL/미측정(reopen) · main 이 움직임(④ 재동기화) · 같은 파일 겹침(직렬 수거) · ack 누락(10분 상위화) · size:small(매니저 직접 경로) · 비-press 팀(대체 축).
4. **삭제 규칙**은 현행 글로벌 그대로 적는다 — 나노 워크트리 정리·나노 세션 kill 은 nano-close 경로 상시 승인 · **브랜치 삭제(`git branch -D`)와 그 외 삭제는 HIL**. 새로 허용하는 말은 쓰지 않는다. 오빠가 브랜치 삭제까지 원하면 «질문»으로 따로 올린다.
5. P1↔P3·P5↔P1·P7↔P3 충돌 후보는 지금 합치지 않는다 — 본선에서 부딪히는 자리에 «충돌 후보» 표시만(합치기는 오빠 「합치자」 뒤).
