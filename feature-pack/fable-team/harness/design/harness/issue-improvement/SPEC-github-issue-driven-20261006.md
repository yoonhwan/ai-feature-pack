## 3. issue-manager 완주 범위 — 「아무도 아무것도 안 해도 0」 을 P10 확정값 위에 올림

오빠 문장을 동사 단위로 쪼개 **누가 집행하고 매니저는 무엇을 하는지** 한 표. P10 Q2 = (A) 루프 책임(확정) 이므로 **집행 = 소유 오케 · 매니저 = 가져오기·우선순위·독촉·대조·기록**이 기준선.

| 오빠 동사 | 집행 손(확정값) | 매니저가 하는 것 | 닫는 사건 | 확정값과 부딪히나 |
|---|---|---|---|---|
| 「가져와서 0 으로」 | 매니저 | ⓪ 열린 Issue 전부 pull → 라벨 6 검사·보완 → ①② 분류·정렬(P10 §4) | 정렬 회차 1행(추세표) | **사건 4 만**(P10 Q3 A) — 「아무도 안 해도」가 «사건 없이도» 라면 충돌 → **§6-1 · Q1** |
| 「테스트도 하고」 | 소유 오케의 시험 묶음(P7 · P8 7·8) · size:small 은 매니저 하위 나노 + 대체 축 | 묶음 PASS 분류가 close 5항에 있는지 **대조** · 재현 코멘트(`repro-e2e`)는 매니저 하위 | 5항 「재현 PASS」 | 없음 |
| 「완성하고」 | 소유 오케(P8 9~11 · 랜딩 PR Closes) | ack 10분 무응답 → 상위화(P5 Q-4 · ⓔ) · 큐 대기 Issue 를 ②에서 다시 세움 | PR 머지 = close | 없음 **단** 소유 팀 오케 세션이 0 이면(cfo 46 · 1-1) 집행 손이 없다 → **§6-3 · Q2** |
| 「정본화 문서화하고」 | 소유 오케(CLOSEOUT 1장 · P8 12 · closeout-policy) | close 뒤 5항 대조 · CLOSEOUT 경로가 코멘트에 있나 · LOOP-LEDGER 행 | 5항 코멘트 + LEDGER 행 | 없음 |
| 「브랜치 워크트리도 정리하며」 | 워크트리·나노 세션 = **자동**(nano-close · P8 10·13) · **브랜치 삭제 = HIL**(P8 Q1 오빠 확정 10-05) | 랜딩 확인된 `nano/*`·`feat/*` 브랜치의 **삭제 후보 목록 1장**(브랜치 · 랜딩 sha · cherry 게이트 결과 · tar 보관 유무)을 정렬 회차마다 갱신 → 오빠가 HIL 1회 일괄 | 목록 행 · HIL 집행 기록 | **브랜치 삭제는 「0」 범위 밖**으로 적는다(목록까지가 매니저) — P8 Q1 을 다시 묻지 않음 · §6-4 |
| 「완성」(close) | 소유 오케(머지) · 매니저는 대조 뒤 `done` / 미비 1통 → 오케 reopen | 위 | `done` 라벨 | 없음(P1 §3-3 ⑥) |

**읽기 [제안]**: 「아무도 아무것도 안 해도」 = **«오빠 손 0»** 으로 읽는다 — 사건은 좌석들이 만든다(매니저 부팅 · 클리어 seq · planner 큐 갱신 통지 · 오빠 제출). 이 읽기면 P10 Q3 (A) 그대로이고 경로 ①② 는 완전히 돈다. **경로 ③④ 만** 다음 사건까지 보이지 않는다. 「사건 없이도 혼자 돈다」로 읽으면 P10 Q3 정정(시간 트리거 1) — 어느 쪽인지 **Q1**.
