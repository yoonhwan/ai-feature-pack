# 제안서 — 쪽지는 바로 처리되고, 오빠 입력창에는 글자를 한 자도 넣지 않는다 (R34·R57·R85 한 건 · 판정 876·877 · 2026-10-10 · arch#27)
- 상태: 초안

★골 원문(복붙 3줄)★
> 내부 하네스, 내부 스킬스를 모니터하고 요청을 사용자에게 받아 해당 부분 바로 확인 검토하고. 실제 하네스와 스킬스를 업그레이드하고 레포에 커밋 푸시하며 전 환경에 물리적 컴퓨팅 환경에도 설치하도록 배포 발행(슬랙) 수신해 반영되 업그레이드.
> 하네스 스킬 관리 오케는 메인오케들과 위성오케들에게 개선요청을 직접받아 등록관리하고 사용자와 협의해 개선하는 축도 필요함.
> 메인 하네스를 유니크하게 머신들에 완전히 독립 배분해 운용하는것.

골의 어느 축: 개선요청 접수·협의(오빠 직접 「알림끄기가 아니다!!!」「인박스 개선하라는거」) + 업그레이드·반영(쪽지 도구 수정 → 전 머신 설치).

## 결론
쪽지 알림을 «오빠 입력창에 글자를 쳐 넣는 방식»에서 «planner 세션이 안에서 자기 쪽지함을 지켜보는 방식»으로 바꾸는 것을 추천해요. 새 쪽지가 오면 그 세션 안에 알림이 떠서 바로 처리하고, 오빠가 치고 있는 입력창에는 아무것도 들어가지 않아요. 알림을 끄는 게 아니라, 알림이 들어가는 길을 바꾸는 거예요.

## 오빠가 결정할 것
알림 방식 하나를 고르시면 돼요. 추천은 ①이에요.
- ① 세션 안 감시(추천): planner 가 켜질 때 자기 쪽지함 감시를 걸어 둬요. 쪽지가 오면 1~2초 안에 세션 안 알림으로 받아 처리해요. 입력창 글자 넣기 0. 감시는 30분마다 다시 걸어야 해서, 기존 10분 확인 틱이 «감시가 꺼져 있으면 다시 건다»를 같이 해요.
- ② 오빠가 안 칠 때만 울리기: 입력창이 비어 있을 때만 지금처럼 글자를 넣어요. 손이 멈춘 순간과 글자가 들어가는 순간이 겹치면 여전히 잘릴 수 있어요.
- ③ 지금 임시 조치 유지: 글자 넣기 0, 대신 10분 확인 틱이 올 때만 읽어요. 최대 10분 늦어요(늦게 올라온다던 처음 문제로 되돌아가요).

같이 정할 것: 지금 걸려 있는 임시 조치(planner 쪽 알림 0 · 쌓아만 둠)는 ①이 설치될 때까지 «유지»를 추천해요. 되돌리면 그날 다시 문장이 잘려요.

## 배경
세 문제는 한 줄기예요.
1. 10-08 「쪽지가 planner 로 늦게 올라온다」 — 실측해 보니 planner 는 쪽지를 중앙값 22초 만에 읽었고, 진짜 지연은 «읽은 뒤 오빠께 안 올리는 것»(39건 중 10건)이었어요.
2. 10-09 이 지연을 줄이려고 «중요 쪽지(① 오빠 원문 ② 승인 ③ 판정 ④ 막힘)와 분류 못 한 쪽지는 무조건 알림»으로 바꿨어요. 알림은 planner 화면에 `[발주 #N] recv …` 를 키보드로 쳐 넣는 방식이에요.
3. 그런데 planner 화면은 오빠가 직접 치는 곳이라, 그 글자가 오빠 문장 중간에 끼어 잘렸어요(10-10 5회+). 그래서 오늘 13:37 planner 쪽 알림만 꺼 두는 임시 조치를 걸었어요.

오늘 숫자(10-10 하루):
- planner 앞 쪽지 200건 중 보낼 때 «무조건 알림»에 걸린 것: 규칙표로 중요 판정 51건 + 규칙표가 못 맞혀 «분류 못 함»이 된 것 약 120건 → 약 170건이 입력창에 글자를 넣었어요(임시 조치 전).
- 분류 못 한 쪽지는 나중에 작은 모델(Haiku)이 다시 분류하는데, 전 좌석 하루 쪽지 1,025건 중 710건이 그 길로 갔어요 = 쪽지마다 `claude -p` 프로그램을 하나씩 띄워요(부하·메모리 큼). 그중 54건은 실패(20초 시간 초과 41 · 이유 없는 실패 13)했고, 20초 상한은 «외부 호출 7초 + 재시도 1회» 규칙에도 어긋나요.
- 즉 «분류 실패가 알림 남발의 원인일 수 있다»는 의심은 반쯤 맞아요: 실패보다 «규칙표가 60%를 못 맞혀 분류 못 함 → 무조건 알림»이 더 큰 원인이에요.

## 제안
### 오빠 화면에서 바뀌는 것
- planner 화면 입력창에 다른 세션이 글자를 넣는 일이 없어져요(①·임시 조치 둘 다).
- 쪽지는 1~2초 안에 planner 세션 안 알림으로 도착해요 — 오빠가 치는 중이어도 입력창 글은 그대로예요.

### 어떻게 (①을 고르시면)
1. 쪽지함 감시 도구 1개: planner 의 쪽지함 파일을 지켜보다가 새 쪽지 1건마다 한 줄(번호 · 분류 · 보낸 이 · 첫 40자)을 내요. planner 세션이 이 도구를 세션 안 감시(Monitor)로 걸면, 한 줄 = 세션 안 알림 1건이 돼요.
2. 부팅·틱 규칙: planner 는 부팅 보고 직후 감시를 걸고(크론과 같은 자리), 30분마다 감시가 끝나면 그 알림을 받아 다시 걸어요. 10분 확인 틱은 «감시가 살아 있나» 를 보고 없으면 다시 걸어요(놓친 쪽지는 틱의 recv 가 줍는 안전망).
3. 쪽지 보내는 도구: «오빠 대면 좌석에는 키보드 알림 0» 임시 조치를 정식 코드·시험으로 옮겨요. 다른 좌석(팀 master 등 사람이 안 치는 화면)은 지금 그대로예요.
4. 분류 정리: 작은 모델 호출 상한을 20초 → 7초 + 재시도 1회로, 실패 때 출력 앞부분도 기록(이유 없는 실패 13건 원인 추적). 규칙표가 못 맞히는 흔한 머리말(예: `[완료·휴식]` `[보고]` `[발주]`)을 표에 더해 모델 호출 수를 줄여요 — 목표 하루 710 → 절반 이하.
5. 확인: 설치 뒤 planner 화면에서 오빠가 치는 동안 시험 쪽지 1통을 보내 «입력창 글 그대로 · 세션 안 알림 1건» 을 한 번 확인해요.

### 하지 않는 것
쪽지 내용·분류 번호 체계·보고 의무 규칙 변경 0 · 팀 master·작업 세션 알림 방식 변경 0 · «읽은 뒤 오빠께 안 올리는 것»(처음 지연의 진짜 원인)은 기존 보고 의무 훅이 맡고, 이 건 설치 뒤 같은 방법으로 다시 재서 따로 보고해요.

## 되돌림
