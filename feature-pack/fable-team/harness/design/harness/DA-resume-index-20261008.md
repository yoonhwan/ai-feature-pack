## §3 질문 2 — HOLD-I1: 장부 부재가 미게시의 증거가 아님

자동 result와 발송 실패 시 이동 거부는 유용하지만, 설계:25,38–39는 장부 키가 없으면 미게시로 판단해 자동 결과/검사를 생략합니다. Slack start 성공 후 root_ts 장부 저장이 실패하거나 장부/키를 지우면 실제 게시된 단위도 다음 move에서 ‘키 없음’으로 통과합니다. 저장 실패 raise만으로 이후의 이 오판을 막지 못합니다.

키가 상태 폴더를 포함한 카드 경로인 것도 같은 원인입니다. 대기 경로로 start한 뒤 대기→진행에서 자동 progress를 보냈더라도, 이동 후 진행 경로로 CLOSE하면 장부의 대기 키와 달라 ‘미게시’가 될 수 있습니다. 이동 전에 키를 이관하는 계약은 현재 없습니다. ‘리포 상대 경로’는 상태 이동에도 불변인 단위 ID와 다릅니다.

최소 교정: repo/팀/카드의 상태 이동에도 불변인 ID와 현재 카드 표시 경로를 분리하고, 원격 게시 전에 tracked 카드 등에 ‘게시 대상/시도/스레드 연결’ 의도를 남겨 장부 유실과 미게시를 구분하세요. 게시 대상으로 표시된 단위에서 장부/키/결과가 미확정이면 CLOSE를 거부하고 복구 필요성을 표시해야 합니다. 장부 미존재/손상도 정상 빈 장부로 흡수하지 않습니다. 원격 매번 조회를 요구하지는 않습니다.

직접 회귀: start 원격 성공 뒤 장부 쓰기 실패→move 거부, 장부/키 삭제→게시 카드 move 거부, 대기→진행→완성에서도 같은 ID/root_ts 유지, 명시적 미게시 카드의 기존 통과. 결과 원격 성공 뒤 기록 실패는 중복 재발송을 피하는 기존 발행 불명 처리와 연결해야 합니다. 판정 405의 자동 결과 발송 자체를 되돌리라는 요구가 아닙니다.

## §4 질문 3 — HOLD-I2: 첫 문자 인용은 현재 단위의 의미 검증이 아님

설계:33의 첫 #숫자는 GitHub Issue뿐 아니라 mbox 발주 seq·PR·참고 이슈일 수 있습니다. ‘참고 #887, 현재 작업 #905’의 첫 값은 현재 단위가 아니며, 본문에 인용된 이전 카드 경로도 같은 문제가 있습니다. 문자 그대로 읽는 것은 문자열을 창작하지 않는다는 뜻일 뿐 현재 작업을 식별했다는 뜻은 아닙니다. 이를 authoritative ‘Issue/카드’ 슬롯으로 내면 잘못된 이어가기 인덱스입니다.

최소 교정: 송신자가 명시한 typed Issue/카드 필드 또는 verified 단위 metadata만 권위 값으로 사용하세요. 단순 문장·코드/인용 블록의 번호/경로는 참조 후보로만 별도 표시하거나 생략합니다. 중복/모호함·mbox seq/PR 혼용·확정 불가이면 권위 칸은 ‘없음’이어야 합니다. 명확한 값까지 모두 없애라고 요구하는 것은 아닙니다.

시험은 본문 머리의 발주 #seq, PR과 Issue 혼합, 이전 카드 인용+현재 카드, 여러 단위, 명시 필드 한 단위를 구분해야 합니다. 새로운 값이나 담당을 LLM/이름 추론으로 정하지 않습니다.

## §5 질문 4 — HOLD-I3: 좌석 이름 언급과 jsonl 소유권은 다름

설계:21은 이름이 든 최신 jsonl을 고릅니다. 좌석 A의 최신 대화에 dead 좌석 B로 보낸 mbox/발주/과거 handoff가 인용돼 있어도 B의 이름은 들어 있습니다. 이 기준이면 A의 uuid를 B의 재개 명령에 넣어 다른 대화/워크트리를 열거나 재개가 실패할 수 있습니다. 이름 검색은 후보 수집일 뿐 소유권 증거가 아닙니다.

최소 교정: 좌석 개설/승계가 확인한 seat incarnation→backend/session uuid/canonical cwd 매핑을 정본으로 쓰고 jsonl의 sessionId/cwd/backend와 대조해야 합니다. 본문 언급은 매핑 근거가 아니며 후보 충돌/부재는 명시적 오류로 종료합니다. 다른 backend의 좌석에 claude --resume를 일괄 생성하지 말고 해당 backend의 확인된 재개 방식이 없으면 명령을 내지 않습니다. 경로/인자는 shell quoting해서 그대로 실행 가능한 명령으로 만들어야 합니다.

가짜 jsonl에서 A가 B를 언급, B와 같은 이름의 이전 incarnation, 다른 cwd, backend 불일치, 정확 매핑 하나를 검사하면 됩니다. 실제 다른 좌석 pane을 조작하거나 jsonl 대화를 재개할 필요는 없습니다.

### I1 닫힘 — 게시 대상의 독립 표식과 불변 ID

설계 §3은 상태 폴더에 독립적인 팀/카드 이름 ID와 표시 경로를 분리하고, 원격 게시 전에 tracked 카드의 슬랙 시도 줄을 남깁니다. §4는 그 줄로 게시 대상을 판정해 장부/키/root_ts가 없거나 손상되면 CLOSE를 거부하고 repair를 요구합니다. 따라서 원격 start 성공 후 장부 실패나 장부 키 삭제를 ‘미게시’로 통과시키는 기존 반례가 차단됩니다. 대기→진행→완성도 동일 ID를 유지합니다.

result 원격 성공 뒤 기록 실패는 원격 결과 표식을 확인해 장부만 복구하도록 하며, §8-b가 앞 반례들을 직접 검사합니다. 구현은 generic start뿐 아니라 제안서 발행과 소급 장부 연결에도 동일한 ID/선기록 규칙을 적용해야 합니다. 제안서 설명에 남은 ‘키=카드 경로’ 문구는 새 §3의 불변 ID를 계산하는 입력 경로로 해석하고 장부의 실제 키로 사용하면 안 됩니다. 게시 의도 저장 실패는 원격 쓰기 전 중단하며, 원격 조회 실패/불완전·시도 불명은 정상 미게시나 CLOSE 허가로 흡수하지 않아야 합니다.

이 수락은 CLOSE의 fail-closed 추적 계약입니다. 결과의 원격 존재가 불명인 재실행에서 단순히 검색에 아직 안 보인다고 새 결과 글을 발송하지 않도록 기존 발행 불명 처리에 연결해야 합니다. 자동 발송/복구가 실제로 성공했다는 실행 증거는 아닙니다.

### I2 닫힘 — 본문 인용의 권위 승격 제거

설계 §3은 미러의 담당/전문을 정형 mbox 행에서 읽고 Issue/카드 권위 칸은 없음으로 고정합니다. 발주 seq·PR·참고 이슈·이전 카드 경로를 본문에서 뽑아 현재 단위로 지정하지 않습니다. §8-b의 혼합/인용/여러 단위 입력이 그 반례를 검사합니다.

명시 정형 Issue/card metadata를 나중에 추가하는 것은 별도 단위이며, 현재 블록이 모든 본문 단위를 자동으로 식별했다는 보장은 하지 않습니다. 값이 미확정임을 ‘없음’으로 보여주는 범위로 기존 I2를 닫습니다.

### I3 닫힘 — 소유권 매핑과 보이는 재개 부재

설계 §2는 정확한 tmux 이름이 살아 있을 때만 해당 좌석으로 ring하고, 그렇지 않으면 좌석표 session_uuid/cwd/agent와 해당 jsonl sessionId/cwd를 대조해 Claude 매핑이 확인된 경우만 resume합니다. 본문 이름 검색을 폐기했으므로 A가 B를 언급한 최신 jsonl을 B의 소유 대화로 고르는 반례를 제거했습니다.

매핑 부재·이전 incarnation·cwd/backend 불일치는 rc 3과 명시적 재개 없음으로 처리하며, shlex 인용/가짜 jsonl 시험도 §8-b에 반영되었습니다. 블록 생성기는 이 rc 3을 ‘재개 칸의 보이는 부재’로 다루고 다른 조회/구조 오류와 혼동하지 않아야 합니다. 매핑의 생성/갱신이 이 단위 밖이라는 한계를 유지하며, 모든 죽은 좌석이 재개 가능하다고 주장하지 않습니다.

### report 수락 유지

report kind는 매거진 발행기만 부여하고 일반 단위 도구에서 지정할 수 없으며 날짜별 magazine ID로 분리합니다(§8-b). 따라서 실제 작업 카드가 report 면제로 결과 검사를 우회하거나 ‘카드 없음’ 키에 모든 보고서가 합쳐지는 위험을 제한했습니다. 보고서 자체 면제와 보고서에 나온 실제 미결 작업의 추적은 별개라는 기존 수락을 유지합니다.
