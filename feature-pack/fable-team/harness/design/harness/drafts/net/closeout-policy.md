# 작업 마감 방침 — 랜딩·정본·전부 닫기 (오빠 2026-10-03 · ★정본★)

> 원문: 「세션을 열어두고 계속 이어가기만하는데 이게 무슨 의미가 있어. 그냥 다닫고 다시 필요시 버그 발생시 다시 열어서 하면되는데」
> 「나중에 main, v65 진짜 중요 브랜치에도 이렇게 계속 가지를 치고 갈거냐고」
> 첫 적용 사례: `BYZ-Agents design/kk/CLOSEOUT-kk-20261003.md`

1. **세션·나노는 «이어가기용»으로 열어 두지 않는다.** 단위가 끝나면 ①랜딩 → ②배포 브랜치 push → ③정본 1장 → ④전부 닫기. 남은 열린 행은 세션을 열어 둘 사유가 아니다. 정본에 적고 닫는다.
2. **정본 1장(CLOSEOUT)**에는 다음을 적는다.
   - 골 원문
   - 축별 상태와 닫는 증거 sha
   - 배포 브랜치·sha와 push 전 로컬 검증 값
   - 나중에 볼 것: «다른 트랙 랜딩 때» / «완성 후»로 나눈다
   - 다시 여는 법
   
   정본은 tracked 경로에 커밋·push 한다. ★측정·벤치 결과는 프로젝트의 원장 정본(BYZ = `docs/architect/LANG_BENCH_LEDGER.md` 등)에도 반영하고, 배포 브랜치에도 같이 올린다. CLOSEOUT 만 쓰고 원장을 빠뜨리지 않는다(10-03 오빠 지적).★
3. **가지를 치지 않는다.** 나노 브랜치는 랜딩(ff/squash)하고, 증거 커밋은 정본 줄기로 모은 뒤 닫는다. main·v65 같은 중요 브랜치도 같다. 새 가지는 «랜딩하려고» 열 때만 만들고 오래 남기지 않는다.
4. **재개 = 이벤트 기반.** 버그나 요청이 생기면 정본을 읽고, 새 세션을 열고, 최신 루트에서 새 브랜치를 딴다. 버그 하나에 세션 하나다.
5. **닫기 체크**: 미커밋 0 · 배포 브랜치 원격 sha 확인 · 정본 push · 좌석 kill(`ft-team-close` 경로 — 나노는 nano-close · 역할 좌석은 계보당 최근 2 보존(`_kept`) · 보존 2 의 kill 은 HIL 계획 1줄) · 승계 0(닫는 세션에 후계를 만들지 않는다 · 일감 단위 팀은 승계 자체가 없다 — governance §11). 브랜치 삭제는 여전히 HIL이다.
6. **«어느 정도»의 기준**: 골 축마다 닫는 증거가 하나씩 있으면 마감할 수 있다. 증거를 더 모으는 라운드(재DA·재측정)는 오빠가 원할 때만 한다.
