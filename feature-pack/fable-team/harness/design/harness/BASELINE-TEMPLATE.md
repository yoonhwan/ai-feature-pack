# baseline 코멘트 템플릿 + 카드 머리줄 `기준값:` (C20)

> 정본: `issue-improvement/SPEC-github-issue-driven-20261006.md` §12-1 · §8 C20 · `issue-improvement/MERGED-20261005.md` §4 · 골 축: 하네스 GOAL 원문 7(동시 처리의 안전판) 표 A.
> 한 줄: **수정 전 값을 적어 두지 않으면 고친 뒤 나빠졌는지 알 수 없다.** Issue 를 시작할 때 쓰고, 닫을 때 같은 세트로 다시 재서 비교한다.
> 이 파일은 템플릿이다 — 값은 비워 둔다(측정은 Issue 를 받은 쪽이 한다).

## 1. Issue 코멘트 `baseline:` (Issue 시작 시 1개)

필드 5개 전부 채운다. 하나라도 비거나 `<…>` 자리표시면 미기재다.

```
baseline:
- 지표 이름: <이 Issue 가 건드리는 지표 하나>
- 값: <수정 전 측정값 + 단위 + 분모(n)>
- 측정 세트 sha: <서비스·러너·FE 가 같은 HEAD 인 sha>
- 러너 경로: <측정에 쓴 기존 러너·명령 경로>
- 시각: <측정한 시각, 시간대 포함>
```

닫을 때는 같은 세트(같은 sha·러너)로 다시 재어 `baseline-after:` 코멘트에 같은 5필드를 쓰고, 5항 표의 「기준값 대비」 칸에 앞뒤 값을 적는다(`ISSUE-TRANSITIONS.md` §3).

## 2. 카드 머리줄 `기준값:` 1줄

카드(인덱스) 머리줄(첫 `##` 앞)에 `기준값: <지표 이름> <값> (baseline 코멘트 링크)` 1줄. 없거나 빈칸이면 `ft-nano-spawn.sh` 가 REJECT 대신 «후보 제외» 경고를 낸다.

## 4. 「없음 → 대체 축」 작성 예

지표가 없는 Issue(예: 하네스 스크립트의 문구 오류)는 빈칸 대신 이렇게 쓴다.

```
baseline:
- 지표 이름: 없음 → 대체 축: 스크립트가 틀린 출력을 내는 재현 명령의 종료코드·출력 1줄
- 값: 수정 전 `bash <스크립트> <입력>` 종료코드 1 · 출력 "<틀린 문구>"
- 측정 세트 sha: <sha>
- 러너 경로: <재현 명령 경로>
- 시각: <시각>
```

카드 머리줄: `기준값: 없음 → 대체 축 재현 명령 종료코드`
