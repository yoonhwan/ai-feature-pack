# 실측 — R34 「슬랙엔 올라오는데 planner 로는 왜 안 올라오나」 (판정 410 실측 #62599 합침 · 2026-10-08 · byz-harness-arch-claude#13)

## 골 원문 (GOAL-harness.md 복붙)
내부 하네스, 내부 스킬스를 모니터하고 요청을 사용자에게 받아 해당 부분 바로 확인 검토하고. 실제 하네스와 스킬스를 업그레이드하고 레포에 커밋 푸시하며 전 환경에 물리적 컴퓨팅 환경에도 설치하도록 배포 발행(슬랙) 수신해 반영되 업그레이드.
하네스 스킬 관리 오케는 메인오케들과 위성오케들에게 개선요청을 직접받아 등록관리하고 사용자와 협의해 개선하는 축도 필요함.
메인 하네스를 유니크하게 머신들에 완전히 독립 배분해 운용하는것.

골의 축: A(모니터·오빠 요청 「바로 확인 검토」) · 오빠 원문 「슬랙 메세지 이런거 왜 플래너로 안올라오냐?」「이런것도 빨리빨리 올라와야 처리가 되지」「빠르게 공유 처리가 안되는게 문제라고 그걸 원인파악해서 개선해달라는것」.

## 결론 (1줄)
planner 는 쪽지를 늦게 «읽지» 않는다(중앙값 22초 · 슬랙보다 먼저 읽음 54건 중 43건). 오빠가 느낀 지연의 실체는 **읽은 뒤 오빠께 안 올라가는 것**(판별 가능 39건 중 10건 = 26%)과 **슬랙 요약이 planner 가 이미 처리한 일을 «오빠 할 일»처럼 보여 주는 것**이다. 여기에 planner 자기 손이 묶이는 3가지(발신 상한 · 인터뷰 중 턴 정지 · 오빠 평문 명령 왕복)가 겹친다.

- **planner 발신 상한**: 회신(Re: 받은 seq) 은 상한 밖 또는 상한 10.
