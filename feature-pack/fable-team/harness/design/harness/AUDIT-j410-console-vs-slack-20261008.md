## 구조 진단 (요청 ②)
1. **출처가 둘이다** — 미러(`byz_mbox_slack_mirror.py`)는 mbox 행만 읽는다. planner 의 콘솔 보고는 assistant 최종 답변이라 mbox 에 없다 → 46 보고 중 미러된 것 0. planner 스레드에 실린 16개는 planner→planner 승계·이관 쪽지(#9→#10 · #9→#8)다(seq 61433·62266·62273·62280·62303·62371 실측). 오빠가 콘솔에서 본 «판정·발주·결과»가 슬랙에 가려면 지금은 그 판정이 우연히 다른 팀 쪽지에 인용될 때뿐이다(표 2·3·5·6).
2. **단위가 다르다** — 슬랙 스레드 키 = Issue 번호 > 좌석 계보(`mirror_lib.py` thread_key). 콘솔 단위 = 판정 N. 그래서 한 판정이 3곳에 흩어지거나(표 7) 어디에도 없다(표 1·9·10·11). 오빠 할 일(표 9·11)이 빠지는 게 가장 큰 손실이다.
3. **요약기가 뜻을 바꾼다** — 1줄 재작성 + 「할 일」 줄 생성 → 「세션 종료는 오빠」가 「세션을 종료해 주세요」로(표 14), 오빠 원문 relay 가 planner 의견으로(표 15), 승계 → 인수인계·팀 → 부서(표 13·17).
4. **좌석 번호 오분류** — 본문이 「[#9 …」로 시작하면 `_ISSUE` 정규식(`^\s*\[?#`)이 Issue #9 로 잡아 뿌리 글 + GitHub 링크를 만든다(표 14 · 같은 꼴 #7·#8·#11·#53 뿌리 글 5개 실측).
5. **스레드 = 좌석은 읽기에 맞지 않는다** — planner 스레드 하나에 하루 22 답글, #7~#10 네 좌석 혼재(표 16). 오빠가 «지금 상태»를 읽으려면 스레드 맨 끝까지 내려가 은퇴 좌석 글을 걸러야 한다. 상태는 «단위(판정·Issue) 스레드»에, 좌석 쪽지는 내부용으로 분리하는 게 맞다.

## 개선 방향 (요청 ③ · 판정 404 이어가기 인덱스 설계 r1 에 합칠 것 — 설계·DA 는 이 표 확인 뒤)
- 출처 추가: planner 콘솔 「결론」 보고를 그대로(재작성 0) 슬랙 «판정 N 단위 스레드»에 1:1 — 결론·할 일·바뀐 것·근거 + 각주 표. 콘솔 텍스트를 잡는 지점 = planner 좌석 Stop 훅(최종 답변) 또는 planner 가 보고와 같은 턴에 단일 발행 입구(`byz_thread_post` · 판정 404 카드 1)로 1통.
- 요약기: 「할 일」 생성 금지 — 원문에 할 일 줄이 있으면 복사, 없으면 「없음」.
- thread_key: `[#N` 은 좌석 번호로 보고 Issue 키에서 제외(명시 「Issue/PR #N」·맨 앞 맨몸 `#N` 만).
- 좌석 쪽지(승계·이관·부팅)는 내부 스레드로 분리 — 오빠 채널 상태 스레드에 섞지 않는다.
