## 3. 정리 안

① **외장/클라우드 백업은 «git 밖»에만** — 워크트리·사본은 미커밋 0 이고 sha 가 가지에 있어 git 이 곧 백업이다. 진짜 백업이 필요한 곳은 `~/.claude/projects` 62.5 GiB(대화 재개 재료)와 `.baton/archive` 4.31 GiB 다. 외장으로 옮길지 보관 기간을 둘지 오빠 결정 1줄.

② **sparse 기본** — 문서·착지·검토용 워크트리는 `--no-checkout` + sparse-checkout 만 쓴다. r1 처방 그대로이고 r2 수치가 근거를 더 단단하게 한다(BYZ 비sparse 평균 1.48 GiB vs sparse 0.30 GiB, 5배). 도구 1개(`ft-land-wt.sh <PR>` = sparse + `.worktree-info.json` purpose=land + 등록)를 두고 손 `worktree add` 는 훅으로 막는다. r891(`ft-scratch-repo` 사본 sparse 기본)이 끝나면 같은 패턴을 그대로 쓴다.

③ **착지 뒤 자동 정리** — 위 도구로 연 워크트리는 착지 sha 를 확인한 그 턴에 «닫기 계획»을 만든다(`nano-close` 의 wt-clean 과 같은 꼴 · 브랜치 보존 · 미커밋 있으면 `.hil`). 표준승인 확장(«착지용 워크트리도 nano-close 경로처럼») = 오빠 결정 1줄.

④ **중복 생성 막기** — ⓐ 등록부 밖 `$TMPDIR/repo-*`·손 `cp -R` 을 훅이 REJECT ⓑ 등록 사본을 만들 때 같은 sha 사본이 이미 살아 있으면 재사용하고 새로 만들지 않는다(이번 실측 최대 5개 3.7 GiB) ⓒ 등록 «밖» 사본도 주인을 알 수 있게 도구가 만든 경로를 쪽지 본문에 남긴다(이번 조사에서 이름이 남은 사본 0개라 주인 추정이 불가능했다) ⓓ `.sh.hil` 1,401장은 «묶음 승인» 경로가 필요하다(§4-3).

⑤ **r891 과의 관계** — r891 = 등록 사본의 sparse 기본 + 판정 끝난 사본 자동 `--done`. 이 안은 겹치지 않는 셋을 맡는다: 등록 «밖» 사본 · 팀 손 착지/문서 워크트리 · `.worktrees/` 등록 밖 폴더. **r2 에서 새로 보이는 것**: 등록 사본 326개 중 296개가 «주인 없음»인데 sweep 이 24h 문턱 때문에 104개만 집는다(가지가 붙은 사본 12 · 미커밋 1 은 문턱을 넘어도 sweep 대상이 아니다). r891 의 자동 `--done` 이 붙으면 나머지도 회수 대상이 된다(문턱을 낮추자는 제안은 아니다 · r444/r548 결정 그대로).

⑥ **`.git` pack 정리 1줄** — r2 에서 잔재가 사라졌으니 할 일은 «`git repack -ad` 1회를 부하 낮을 때(load < 10)» 뿐이다. 지금은 pack 5개 · size-pack 4.52 GiB · loose 22,935(197 MiB) · prune-packable 390. repack 뒤 원장 채움의 «read-tree·merge-base 7초 초과» 횟수를 같은 명령으로 다시 재서 비교한다(하드 룰 12 의 7초 룰은 그대로).
