## 결론 1줄
그래픽·UI/UX 팀은 **상시 좌석 0** 으로 두고, 메인·위성 어느 팀이든 «이미 승인된 일» 안에서 «중간 크기» 시각 작업이 생기면 하네스 master 에 요청 → 하네스가 좌석(arch 1 + 나노 ≤2)을 열고 «열린 동안 감시» → 요청 팀이 인계를 수락하고 랜딩 sha 를 돌려주면 → 하네스가 CLOSEOUT 를 쓰고 전부 닫는다. **팀 master 는 두지 않는다**(열기·감시·닫기 = 하네스 master · 랜딩 = 요청 팀 master).

### 2-1. 나노 1석 vs 2석 (판정 636 — 「그래픽과 코드연동 개별 핑퐁이 필요할지 하나가 다할지」)

| 축 | 1석 — sol 하나가 한 페이지의 시안 + 코드 연동 전부 | 2석 핑퐁 — 그래픽 sol ↔ 코드 연동 sol/sonnet |
|---|---|---|
| 속도 | 넘김 0 · 시안 확정 뒤 같은 좌석이 바로 코드로 | 넘김마다 mbox 왕복(시안→코드→차이 반송) · 병렬 이득은 «다른 페이지»일 때만 |
| 일관성 | 시안을 만든 손이 코드를 쓴다 → 의도 손실 0 | 시안→코드 번역 손실 · «시안과 다르게 구현» 반송 루프 위험 |
| 충돌 | 워크트리·브랜치 1 · 쓰는 좌석 1 → 0 | 같은 `graphics/<Issue>-<slug>` 에 두 좌석 → 순서 잠금 필요 · 공용 토큰 파일 동시 수정 충돌 |
| 검증 방법 | 증거 1벌: 시안 PNG ↔ 실 페이지 스크린샷(같은 폭) 나란히 + FE 시험·`next build` · turbopack get_errors 0 | 증거 2벌 + 둘 사이 대조(누가 틀렸나 판정이 한 단계 더) |
| 부하 | codex 좌석 1 · 로컬 FE 서버 1(포트 레인지 1슬롯) | codex 좌석 2 · FE 서버 1~2 · mbox 왕복 |
| 메모리 | 세션 1 + 워크트리 1 | 세션 2 + 워크트리 1(한 브랜치 = 한 워크트리 · 순서 잠금) |

★권고 1★: **기본 = 1석(한 페이지 = 한 나노 = 시안부터 코드 연동까지)**. 2석은 «역할(그래픽/코드)로 나누는 핑퐁»이 아니라 ★«서로 다른 페이지 2개를 동시에» 할 때만★ 연다 — 각 나노가 자기 페이지를 1석 방식으로 끝까지 맡고, 공용 토큰 파일 수정은 arch 가 먼저 한 번 정해 두 나노는 읽기만 한다. 역할 핑퐁은 위 표의 일관성·충돌 두 칸에서 진다.
★2석의 브랜치·워크트리(DA r3 Q3 교정 ⓐ)★: 나노마다 페이지별 하위 브랜치 `graphics/<Issue>-<slug>-<page>` + 자기 워크트리(base = 본 브랜치 최신) · 하위 브랜치 수 = 동시 나노 수(≤2) · graphics arch 가 인계 «전» 본 브랜치 `graphics/<Issue>-<slug>` 로 병합(push 0)하고 병합된 본 브랜치에서 1석 검증(`next build`·turbopack `get_errors`·스크린샷 대조)을 한 번 더 돌린다. DA·PR·CLOSEOUT 은 ★본 브랜치 sha 하나★ — 2석이어도 요청 1건 = 원격 sha 계약 1개(§3.3·§3.7 그대로). 이때 메모리 = 세션 2 + 워크트리 3(본 1 + 하위 2).

**감시 (DA Q1)**: graphics 좌석이 하나라도 열려 있는 동안 하네스 master 는 `seats-graphics.json` 의 현역 좌석 «전체»를 자기 기존 10분 틱의 감시 대상에 넣는다(governance §8 그대로 — jsonl·`✻ … done` 줄·프로세스 실측 · 정지 3분 넘으면 그 턴에 깨우기·다음 발주·닫기·HIL 확인 중 하나). 열린 좌석 0 이 되면 감시 대상에서 뺀다.

**HIL 경로 (DA Q1)**: 작업 중 막힌 명령·사람 판정 = graphics arch/나노 → mbox `[HIL]` → 하네스 master → 현역 planner → 오빠 인터뷰 → 값으로 역순 회신. ★graphics 좌석은 AskUserQuestion 0 · 오빠 인터뷰는 planner 만★(governance §7). §3.5 «오빠 시안 확인»도 같은 경로다.
