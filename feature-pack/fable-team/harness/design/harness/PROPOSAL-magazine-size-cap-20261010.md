# 제안서 — 아침 매거진 크기 상한 · 요약 우선 (R74 · 판정 806 · 2026-10-10 · arch#26)
- 상태: 수정 요청 r1
- r0 = 판정 812 A안 채택 · r1 = 구현 실측으로 숫자 1개 재결정 요청

★골 원문(복붙 3줄)★
> 내부 하네스, 내부 스킬스를 모니터하고 요청을 사용자에게 받아 해당 부분 바로 확인 검토하고. 실제 하네스와 스킬스를 업그레이드하고 레포에 커밋 푸시하며 전 환경에 물리적 컴퓨팅 환경에도 설치하도록 배포 발행(슬랙) 수신해 반영되 업그레이드.
> 하네스 스킬 관리 오케는 메인오케들과 위성오케들에게 개선요청을 직접받아 등록관리하고 사용자와 협의해 개선하는 축도 필요함.
> 메인 하네스를 유니크하게 머신들에 완전히 독립 배분해 운용하는것.

골의 어느 축: 개선요청 접수·협의(오빠 직접 「매거진은 심각하게 파일이 너무 큰데? 절대 읽으면 안된다」) + 배포 발행(슬랙 매거진).

## 결론
(r1) 승인하신 A안대로 만들었더니, 무거운 날(10-10 규모)은 md 가 약 2,700줄이 돼서 경보선 1,500줄에 걸려 발행이 멈춰요. 한 건을 A안 문구대로 «제목 + 3줄 + 원문 위치» 5줄로 줄이고, 절당 상한을 40건에서 20건으로 낮추면 약 1,150줄(PDF 약 31쪽 추정)이 돼서 목표(약 1,000줄·30쪽)에 맞아요.

(r0) 매거진이 커진 원인은 버그가 아니에요. 10-08 설계(판정 354 「풀디테일로」)가 2부를 «전문 그대로 · 상한 없음»으로 정했기 때문이에요. 2부를 «한 건 1~3줄 + 원문 위치» 색인으로 바꾸고, 파일마다 크기 상한을 두는 것을 추천해요.

## 오빠가 결정할 것
(r1) 절당 상한 숫자를 고르시면 돼요. 추천은 ①(한 건 5줄로 압축 + 절당 20건 · 경보선 1,500 그대로)이에요. ②는 절당 40건을 두고 경보선만 3,000으로 올리고(목표 초과 약 2,700줄), ③은 압축 + 절당 40건 + 경보선 2,000이에요(약 1,750줄).

(r0 · 판정 812 로 A안 결정됨) 2부 모양을 고르시면 돼요. 추천은 A안(색인형 2부 + 크기 상한)이고, B안(전문은 따로 · 요청할 때만)과 C안(2부 없음)이 있어요.

## 되돌림
생성기 스크립트를 `.bak` 으로 백업한 뒤 바꿔요. 되돌릴 때는 백업을 다시 복사하면 다음 08:00 호부터 지금 모양으로 돌아가요. 이미 발행된 매거진은 그대로 남아요.

## r1. 구현 실측 (나노 75415b2b9a · 가짜 모델 · 실 매거진 파일 0)

10-10 규모 모델(닫힌 단위 41 · 판정 절 16 · 판정 188 · 머지 87 · 이슈 60 · 열린 카드 226 · 부록 5)을 렌더한 md 줄 수예요.

| 절당 상한 | md 전체 | 2부 |
|---|---|---|
| 40 (승인값) | **2,682** | 2,294 |
| 25 | 1,892 | 1,504 |

- 원인: 한 건이 블록 여러 개(제목 · 경로 줄 · 본문 3줄+위치 · 골좌표 · 증거 목록 · DA 목록 · 블록 사이 빈 줄)라서 7~15줄이 돼요. 판정은 본문과 relay 전문을 둘 다 3줄씩 실어요. 제안서의 «건수 상한이 먼저 걸려 경보선은 평소 발동 안 함» 가정이 틀렸어요.
- ①안의 압축: 한 건 = 제목 1줄 + 본문 최대 3줄 + `… 원문: <위치>` 1줄(A안 원래 문구 그대로)이에요. 경로 줄·DA·골좌표 목록은 위치 1줄로 합치고, relay 전문은 위치만 남겨요. 예상(계산): 2부 약 740줄 + 1부·목차·각주표 약 410줄 = **약 1,150줄**이에요. 쪽수는 10-10 호 비율(약 37줄/쪽)로 **약 31쪽**(경보선 40쪽 안)이에요.
- 경보선(1,500줄 · 120 KB · 40쪽 · 넘으면 raise)은 그대로 두는 것을 추천해요. 넘치면 발행이 멈춰서 보이니까, 숫자가 다시 틀리면 바로 드러나요.
