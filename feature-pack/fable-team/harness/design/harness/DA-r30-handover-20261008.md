## §2 질문 1 — HOLD-H1: 모든 구 세션 클라이언트의 의도는 시점만으로 확정되지 않음

설계:22는 구 좌석에 붙은 클라이언트 전부를 옮깁니다. 하나는 현재 작업을 따라가는 탭, 다른 하나는 이전 대화/작업을 조회하려는 탭이어도 list-clients의 세션명만으로 구분되지 않습니다. 후계 부팅 보고와 구 좌석 자신이라는 실행자는 승계 준비를 확인할 뿐 두 번째 탭의 조회 의도를 확인하지 않습니다. keep-last-2가 남기는 ‘직전 세션 질의’ 용도와도 구분해야 합니다.

최소 교정: 자동 이동의 대상은 승계를 따르는 것으로 확인된 클라이언트/작업 탭으로 한정하고, 보존/조회 탭은 제외하는 규칙을 정하세요. 원래 승계 작업의 client identity 또는 기존에 등록된 follow/archive 구분처럼 도구가 판정 가능한 근거면 되며 매번 사용자에게 attach를 시키거나 인터뷰하라는 요구가 아닙니다. 식별 근거가 없는 클라이언트까지 ‘모두 오빠의 현재 창’으로 단정하지 않아야 합니다.

클라이언트 선택 뒤 사용자가 다른 세션으로 옮긴 경우도 실행 직전 원래 구 세션 연결/동일 client identity를 재확인해 덮지 않아야 합니다. 가짜 tmux 시험은 follow 1+archive 1, 선택 후 세션 변경/tty 재사용, 후계 없음/일부 전환 실패를 구분하고 대상 밖 클라이언트 switch 0을 확인해야 합니다. 실제 지금 남은 feature 탭의 1회 이동 권한을 이 설계 DA가 대신 행사하지 않습니다.

## §3 질문 2 — HOLD-H2: 정당한 인용·필수 HIL 기록까지 차단

설계:30–31은 문서/코드 블록 인용도 문자열만으로 Stop block하고 HIL/planner mbox에도 같은 문자열을 금지합니다. 사용자가 요청한 문서의 attach 명령 설명은 ‘승계 작업을 사용자에게 떠넘기는 실행 지시’와 다릅니다. blocked command를 원문 그대로 planner에 올려야 하는 기존 HIL 규칙도 이 문자열을 포함하면 mbox 자체가 거부되어 보고 경로가 막힐 수 있습니다.

기존 사용자 규칙의 ‘실파괴 없는 패턴 텍스트 오탐은 파일 기록+허용+묶음 통지’와 새 blanket deny의 적용 구분이 없습니다. 최소 교정은 사용자에게 승계 실행을 요구하는 지시를 차단하되, 기술 문서/감사/실패 원문 기록과 정형 HIL의 원문 전달은 명시적으로 허용하는 것입니다. 인용을 숨기거나 다른 도구로 차단을 우회하라는 요청이 아닙니다.

typed 메시지 목적/수신 대상 또는 요청/보고 형태를 구분해 오탐 기록 경로를 정하고, Stop 훅의 차단이 반복 무한 루프가 되지 않는 재검 흐름도 고정하세요. 시험은 사용자 실행 떠넘김, 요청된 문서 인용, HIL blocked-command 원문, 오탐 기록/배치 통지를 구분해야 합니다. 모든 좌석이 언제나 attach 관련 문자열을 말할 수 없다는 전역 정책은 이 승계 버그 처방과 같지 않습니다.

## §4 질문 3 — HOLD-H3: volatile 옵션은 은퇴·후계 권위의 충분조건 아님

설계:24,27은 @handed_over_to가 있으면 relay만, 없으면 그 제한이 적용되지 않는 구조입니다. 세션 재생성/옵션 삭제로 표식이 없어지면 실제 은퇴한 좌석도 다시 판정을 시작할 수 있고, 잘못된 옵션은 오빠 원문을 다른 팀/좌석으로 보낼 수 있습니다. show-option도 정확한 구 좌석을 지정하지 않으면 ambient/default session의 값을 읽을 수 있으므로 소유 세션을 고정해야 합니다.

최소 교정: 세션 옵션은 힌트/캐시로만 쓰고, 명부의 replacement/정본 담당 또는 영속 handover 기록에서 ‘구 incarnation→확정 후계’ 관계를 검증하세요. 시작/오빠 입력 처리 전에 이를 대조해 옵션이 없어도 은퇴 상태를 복원하고, 옵션/영속 관계 불일치·후계 미확정은 새 판정·임의 relay 0과 보이는 오류/관리자 확인으로 종료해야 합니다. 후계 준비 및 실제 수신 성공 여부도 확인하지 않고 ‘이어받았어요’를 확정하지 않습니다.

사용자가 구 세션으로 돌아가 이전 기록을 묻는 읽기 전용 질의와 새 작업/새 판정 요청은 구분해야 합니다. 전자는 keep-last-2의 조회 목적을 유지할 수 있고 후자만 확인된 후계로 넘기면 됩니다. manually 되돌아온 탭에 ‘창은 이미 옮겨 둠’이라고 현재 상태를 단정하는 문구도 실제 확인 없이 사용하지 않아야 합니다(:27–28).

가짜 명부/옵션으로 표식 유실·잘못된 후계·세션 재생성·다른 default session·정확 관계를 검사하고, 후계 미확정 때 구 좌석이 판정 번호를 만들거나 잘못된 상대에게 원문을 보내지 않는지 확인하세요. 이름 문자열만으로 관계를 추측하거나 새로운 후계 개설 정책을 추가하라는 요구가 아닙니다.

### H1 — HOLD 유지: T0 시점이 탭 의도까지 입증하지 않음

설계:21은 ‘T0에 구 좌석이 유일 현역이므로 조회 탭이 존재할 수 없다’고 가정하고 그때 붙은 모든 client를 follow로 기록합니다. 그러나 현역 좌석의 같은 대화/옛 출력/다른 창을 조회하는 두 번째 탭은 후계가 생기기 전에도 존재할 수 있습니다. 연결 시점을 앞당겨도 기존 H1의 ‘현재 작업 탭과 조회 탭이 같은 세션에 붙음’ 반례는 같습니다. 새 원인이 아닙니다.

identity 세 필드 및 실행 직전 session 재확인, T0 뒤 붙은 탭 제외(:22)는 tty 재사용/사용자 이동/후발 조회를 보호하는 유용한 교정으로 수락합니다. 다만 T0 이전 탭의 의미를 모두 follow로 추정하는 충분조건은 되지 않습니다. 가짜 시험은 T0 뒤 조회 탭만 다뤄 기존 반례의 T0 이전 조회 탭을 아직 검증하지 않습니다(:52).

남은 최소 과제는 기존 관리 창/launcher에서 확인된 follow 범위와 조회/archive 범위를 구분한 증거를 snapshot 입력에 연결하는 것입니다. 사용자에게 매 승계마다 attach/인터뷰를 맡기라는 요구는 아닙니다. 이미 존재한 archive 탭과 실제 follow 탭이 섞인 T0 fixture에서 archive switch 0을 확인해야 합니다. 별도 의도 근거가 없는 과거 feature 탭을 HIL 단발로 처리한다는 :47의 제한은 수락합니다.

### H2 — HOLD 유지: 인용된 요청문도 ‘요청어가 있는 줄’에 걸림

mbox 가드 제거(:45)는 필수 HIL 원문 경로를 열었고 stop_hook_active의 반복 차단 방지(:44)도 수락합니다. 하지만 :42의 substring 요청어 조건과 :43의 ‘그 밖 기록만’만으로 인용/요청 문맥이 구분되지 않습니다. 예: 감사 문서의 `이전 좌석은 "tmux attach -t X를 실행해 주세요"라고 요청했다`는 정당한 인용인데 attach+실행해/해 주세요가 같은 줄이라 block합니다. HIL의 blocked-command 원문이나 코드 블록 안 `! tmux attach …`도 동일합니다.

이는 최초 H2의 정당한 문서/HIL 인용 오탐이며 새 문장 유형이 아닙니다. :54는 인용의 일반 사례만 나열하고 요청 형태를 **인용한** 직접 반례가 빠졌습니다. 재검 플래그로 두 번째에 무조건 통과하는 것은 첫 오탐을 분류해 허용한 것과 동일하지 않습니다.

남은 최소 과제는 문서/감사/HIL/코드 인용의 typed 문맥 또는 명시 목적을 요청 지시 검사보다 먼저 분리하고, 사용자에게 실제 실행을 요구하는 줄만 차단하는 것입니다. 실파괴 없는 기록은 기존 오탐 경로에 남겨 허용해야 하며 차단을 숨기거나 다른 도구로 우회하도록 하지 않습니다. 인용 안 요청어/! prefix와 실제 사용자 실행 지시를 같은 fixture에서 구분하세요.

### H3 — APPROVE(설계), 기존 권위/표식 HOLD 닫힘

설계:20,25,28–39는 append-only handover 기록과 명부 역할 pointer의 일치를 권위로 삼고 옵션은 복원 가능한 캐시로 바꿨습니다. 표식만 없어져도 은퇴 상태를 유지하고, 잘못된 후계/명부·장부 불일치는 새 판정/임의 relay 없이 보이는 MISMATCH가 됩니다. 정확한 TMUX_PANE/세션 지정, read-only 역사 질의 유지, 새 요청의 QUEUED/도달 확인 및 현재 창 단정 제거도 반영했습니다.

:53–55의 옵션 유실·잘못된 옵션·재생성·default 세션 및 세 판정 상태 시험으로 기존 원인을 고정했습니다. 장부 오류/판정표 외 상태는 ACTIVE로 흡수하지 않고, 명부 역할 key와 실제 구 incarnation을 확정하는 운영 검증은 구현자가 확인해야 합니다. 이는 새 HOLD가 아니라 영속 권위 계약의 구현 전제입니다.

## §8 통합 이관 — 두 번째 HOLD, 연속 리뷰 종료

수락된 항목은 client identity/후발 탭/사용자 이동 보호, legacy 1회 명시 확인, HIL 경로 복원/반복 차단 방지, 영속 승계 관계 및 정확 세션의 relay 판정입니다. 남은 H1/H2는 **T0 이전 client의 follow 의도 식별**과 **요청문을 인용한 정당한 기록의 우선 허용** 두 가지입니다.

최소 다음 과제: master가 이미 사용하는 관리 창의 follow/조회 표시 근거를 정하고 snapshot에 연결한 가짜 두 client 시험, 그리고 문서/HIL 인용에 요청어가 포함된 Stop fixture를 하나의 구현/검증 단위로 배정하세요. 실제 창 이동·세션 종료·홈 설치는 이 DA에서 요청하지 않습니다. 두 부분의 판정 근거 없이 ‘T0니까 전부 follow/문장에 요청어니까 실행 지시’라고 추정하면 안 됩니다.

실행 명령은 추출본의 `bash <검증 디렉터리>/tests/harness/test_seat_handover.sh`이며 결과는 **ALL PASS · exit 0**입니다. 시험은 자체 PATH의 가짜 tmux 및 임시 명부/장부/mbox를 사용합니다(test_seat_handover.sh:20–56,123–164). 실제 tmux switch·kill·라이브 장부/명부·홈 설치·mbox 발신은 하지 않았습니다. 시험의 임시 fixture 생성/정리는 이 검증 프로세스 안에서만 수행했습니다.

### 잔여 H1 — APPROVE(지정한 T0 복수 탭 차단)

cmd_snapshot은 클라이언트가 정확히 1개인 경우만 follow로 기록하고 2개 이상이면 follow=[]·ambiguous=전체로 분리합니다(ft-seat-handover.sh:32–42). cmd_apply는 follow 목록만 try_move에 넘기며 ambiguous는 보류 출력과 planner 알림을 만듭니다(:86–109). 따라서 이전의 T0 ‘현재 탭 1+조회 탭 1’을 모두 follow로 이동하던 반례가 차단됩니다.

고정 시험:67–73은 두 탭에서 switch.log가 비어 있고 ambiguous=2·tty 목록이 표시되며, 가짜 planner 통보 1건을 확인합니다. 최종 ALL PASS/exit 0으로 이 단언들이 통과했습니다. 이 결과가 1개인 탭의 임의 의도까지 식별하거나 실제 현장 탭을 옮겨도 된다는 전역 승인은 아닙니다.

### 잔여 H2 — APPROVE(인용 문맥 선제외)

hook은 HIL/감사 헤더, 코드 fence, blockquote, 따옴표/「」/백틱을 먼저 제외한 뒤 남은 attach 패턴 줄에만 실행 요청 조건을 적용합니다(no-attach-to-user.sh:29–46). 최초 반례의 ‘이전 좌석은 "tmux attach … 실행해 주세요"라고 요청했다’는 quoted 기록으로 남고 block하지 않습니다.

실행 출력에 `PASS 인용 줄 → 기록(block 0)`와 falsepos.log의 `quoted n=1` 기록을 확인했습니다. 고정 시험:169–180의 인용/코드/HIL/감사/언급은 허용·기록하며, :182–185의 실제 실행 요청은 block합니다. :186–187의 stop_hook_active=true는 block 0·기록으로 통과했고 출력도 확인했습니다. 판정은 이 고정 인용/요청 형태에 한정하며 가능한 모든 자연어의 완전한 의미 분류를 인증하지 않습니다.
