## §2 질문 1 — HOLD-H1: 모든 구 세션 클라이언트의 의도는 시점만으로 확정되지 않음

설계:22는 구 좌석에 붙은 클라이언트 전부를 옮깁니다. 하나는 현재 작업을 따라가는 탭, 다른 하나는 이전 대화/작업을 조회하려는 탭이어도 list-clients의 세션명만으로 구분되지 않습니다. 후계 부팅 보고와 구 좌석 자신이라는 실행자는 승계 준비를 확인할 뿐 두 번째 탭의 조회 의도를 확인하지 않습니다. keep-last-2가 남기는 ‘직전 세션 질의’ 용도와도 구분해야 합니다.

최소 교정: 자동 이동의 대상은 승계를 따르는 것으로 확인된 클라이언트/작업 탭으로 한정하고, 보존/조회 탭은 제외하는 규칙을 정하세요. 원래 승계 작업의 client identity 또는 기존에 등록된 follow/archive 구분처럼 도구가 판정 가능한 근거면 되며 매번 사용자에게 attach를 시키거나 인터뷰하라는 요구가 아닙니다. 식별 근거가 없는 클라이언트까지 ‘모두 오빠의 현재 창’으로 단정하지 않아야 합니다.

클라이언트 선택 뒤 사용자가 다른 세션으로 옮긴 경우도 실행 직전 원래 구 세션 연결/동일 client identity를 재확인해 덮지 않아야 합니다. 가짜 tmux 시험은 follow 1+archive 1, 선택 후 세션 변경/tty 재사용, 후계 없음/일부 전환 실패를 구분하고 대상 밖 클라이언트 switch 0을 확인해야 합니다. 실제 지금 남은 feature 탭의 1회 이동 권한을 이 설계 DA가 대신 행사하지 않습니다.

## §3 질문 2 — HOLD-H2: 정당한 인용·필수 HIL 기록까지 차단

설계:30–31은 문서/코드 블록 인용도 문자열만으로 Stop block하고 HIL/planner mbox에도 같은 문자열을 금지합니다. 사용자가 요청한 문서의 attach 명령 설명은 ‘승계 작업을 사용자에게 떠넘기는 실행 지시’와 다릅니다. blocked command를 원문 그대로 planner에 올려야 하는 기존 HIL 규칙도 이 문자열을 포함하면 mbox 자체가 거부되어 보고 경로가 막힐 수 있습니다.

기존 사용자 규칙의 ‘실파괴 없는 패턴 텍스트 오탐은 파일 기록+허용+묶음 통지’와 새 blanket deny의 적용 구분이 없습니다. 최소 교정은 사용자에게 승계 실행을 요구하는 지시를 차단하되, 기술 문서/감사/실패 원문 기록과 정형 HIL의 원문 전달은 명시적으로 허용하는 것입니다. 인용을 숨기거나 다른 도구로 차단을 우회하라는 요청이 아닙니다.

typed 메시지 목적/수신 대상 또는 요청/보고 형태를 구분해 오탐 기록 경로를 정하고, Stop 훅의 차단이 반복 무한 루프가 되지 않는 재검 흐름도 고정하세요. 시험은 사용자 실행 떠넘김, 요청된 문서 인용, HIL blocked-command 원문, 오탐 기록/배치 통지를 구분해야 합니다. 모든 좌석이 언제나 attach 관련 문자열을 말할 수 없다는 전역 정책은 이 승계 버그 처방과 같지 않습니다.

## §4 질문 3 — HOLD-H3: volatile 옵션은 은퇴·후계 권위의 충분조건 아님

설계:24,27은 @handed_over_to가 있으면 relay만, 없으면 그 제한이 적용되지 않는 구조입니다. 세션 재생성/옵션 삭제로 표식이 없어지면 실제 은퇴한 좌석도 다시 판정을 시작할 수 있고, 잘못된 옵션은 오빠 원문을 다른 팀/좌석으로 보낼 수 있습니다. show-option도 정확한 구 좌석을 지정하지 않으면 ambient/default session의 값을 읽을 수 있으므로 소유 세션을 고정해야 합니다.

최소 교정: 세션 옵션은 힌트/캐시로만 쓰고, 명부의 replacement/정본 담당 또는 영속 handover 기록에서 ‘구 incarnation→확정 후계’ 관계를 검증하세요. 시작/오빠 입력 처리 전에 이를 대조해 옵션이 없어도 은퇴 상태를 복원하고, 옵션/영속 관계 불일치·후계 미확정은 새 판정·임의 relay 0과 보이는 오류/관리자 확인으로 종료해야 합니다. 후계 준비 및 실제 수신 성공 여부도 확인하지 않고 ‘이어받았어요’를 확정하지 않습니다.

사용자가 구 세션으로 돌아가 이전 기록을 묻는 읽기 전용 질의와 새 작업/새 판정 요청은 구분해야 합니다. 전자는 keep-last-2의 조회 목적을 유지할 수 있고 후자만 확인된 후계로 넘기면 됩니다. manually 되돌아온 탭에 ‘창은 이미 옮겨 둠’이라고 현재 상태를 단정하는 문구도 실제 확인 없이 사용하지 않아야 합니다(:27–28).

가짜 명부/옵션으로 표식 유실·잘못된 후계·세션 재생성·다른 default session·정확 관계를 검사하고, 후계 미확정 때 구 좌석이 판정 번호를 만들거나 잘못된 상대에게 원문을 보내지 않는지 확인하세요. 이름 문자열만으로 관계를 추측하거나 새로운 후계 개설 정책을 추가하라는 요구가 아닙니다.
