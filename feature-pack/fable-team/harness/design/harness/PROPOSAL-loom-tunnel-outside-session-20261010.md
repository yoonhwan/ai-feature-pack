# 제안서 — LOOM DB 터널을 «세션 밖»에서 상시 유지 (R87 · v65 master#162 요청 · 2026-10-10 · arch#27)

> 내부 하네스, 내부 스킬스를 모니터하고 요청을 사용자에게 받아 해당 부분 바로 확인 검토하고. 실제 하네스와 스킬스를 업그레이드하고 레포에 커밋 푸시하며 전 환경에 물리적 컴퓨팅 환경에도 설치하도록 배포 발행(슬랙) 수신해 반영되 업그레이드.

> 메인 하네스를 유니크하게 머신들에 완전히 독립 배분해 운용하는것.

골의 어느 축: 개선요청 접수·협의(v65 master#162 요청) + 업그레이드·반영(머신마다 설치되는 상시 터널).

## 결론
로컬 게이트웨이가 쓰는 LOOM DB 터널(내 컴퓨터 38309 → DB 10.2.0.10)을 맥의 상시 실행 관리자(launchd)에 맡기는 것을 추천해요. 지금은 이 터널을 «마지막으로 연 세션»이 쥐고 있어서, 그 세션이 닫히면 터널도 같이 죽어요(10-10 15:22 게이트웨이 오류). launchd 에 맡기면 어떤 세션이 열리고 닫히든 상관없이 살아 있고, 끊겨도 30초 안에 저절로 다시 붙어요.

## 오빠가 결정할 것
터널을 누가 쥘지 고르시면 돼요. 추천은 ①이에요.
- ① launchd 상시 터널(추천): 맥이 켜져 있는 동안 항상 유지 · 끊기면 30초 안에 자동 재연결 · 세션과 무관.
- ② 세션과 분리해서 한 번 띄우기: 지금 다른 터널 4개(8000·8001·8100·38311)처럼 세션 밖으로 떼어 띄워요. 세션이 닫혀도 살지만, 끊기면 누가 다시 열어야 해요(판정 799 절차).
- ③ 세션 닫기 전에 터널 이관 확인: 닫는 세션이 터널을 쥐고 있으면 닫기를 멈추고 이관부터 하게 해요. 원인은 그대로 두고 절차만 늘어요.

## 배경
- 38309 는 로컬 게이트웨이(8080 · v6-realtime-live)가 LOOM DB 에 붙는 길이에요. 게이트웨이는 `LOOM_PG_TUNNEL_PORT=38309` 로 떠 있고, 터널이 없으면 DB 호출이 막혀요(풀 대기 시간 초과).
- 실측(10-10 15:3x): 지금 38309 를 쥔 프로세스는 `gcloud compute ssh byz-agents-gce-stt-tts-dev --tunnel-through-iap -- -N -L 38309:10.2.0.10:5432`(서비스 계정 byz-local-dev)이고, 그 부모가 v65 master#162 세션(claude) 이에요. 15:22 에 앞 세션(#160)이 닫히며 같은 터널이 죽었고, #162 가 다시 열었어요 — #162 가 닫히면 또 죽어요.
- 다른 터널 4개는 부모가 시스템(ppid 1)이라 세션이 닫혀도 살아 있어요. 38309 만 세션의 자식이에요.
- 같은 터널이 10-03(작업자 재시작)에도 죽어 수동으로 다시 열었고, 10-10 에는 다른 팀 작업 세션이 이 포트로 일회성 터널을 열고 닫아 게이트웨이 길을 끊었어요(판정 909 — 일회성 터널은 38309 금지).
- 이 DB(10.2.0.10)는 이름은 prod 이고 dev 게이트웨이도 쓰는 «라이브» DB 예요(판정 161). 터널이 늘 열려 있는 것 자체는 지금과 같아요(바뀌는 것은 «누가 쥐는가» 뿐).

## 제안
### 오빠 화면에서 바뀌는 것
- 세션을 닫거나 새로 열어도 로컬 게이트웨이의 LOOM 오류(풀 시간 초과)가 생기지 않아요.
- 터널이 끊겨도(네트워크·IAP 재연결) 30초 안에 저절로 다시 붙어요.

### 어떻게 (①을 고르시면)
1. 킷에 launchd 설정 틀 1개 `com.byz.loom-pg-tunnel` — 지금과 같은 명령(서비스 계정 · 38309 → 10.2.0.10:5432)에 연결 유지 옵션(30초마다 생존 확인 · 3번 실패면 끊고 다시)과 «포트를 못 잡으면 바로 종료» 옵션을 붙여요. launchd 는 RunAtLoad · KeepAlive · 재시작 간격 30초.
2. 설치 도구(머신마다): 설정 틀을 `~/Library/LaunchAgents` 에 깔고 켜요. 설치 직전 38309 를 쥔 세션 터널은 같은 명령인지 확인한 뒤 그 pid 만 넘겨받아요(판정 799 와 같은 «그 pid 만» 원칙).
3. 상태 확인 한 줄: `launchctl print` + 38309 LISTEN + DB `select 1` — 하네스 상태판(byz-ops status)에 붙여요.
4. 규칙 한 줄: «38309 는 launchd 소유 · 세션에서 열고 닫지 않는다 · 일회성 터널은 38301~38399 빈 포트(판정 909)».

### 하지 않는 것

## 되돌림
`launchctl bootout` 으로 끄고 설정 파일을 지우면 지금처럼 «사람이 여는 터널»로 돌아가요. 끄는 순간 터널이 닫히므로, 되돌릴 때는 같은 명령으로 세션 밖 터널을 먼저 열고 끕니다.
