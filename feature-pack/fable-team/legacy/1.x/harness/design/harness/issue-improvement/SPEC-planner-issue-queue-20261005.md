### 3-B. 제안 [제안] — 수렴 절차 7단계 (단계마다 «닫는 증거» 없으면 다음 금지)
```
N 나노 브랜치 ──①──▶ 통합 브랜치 feat/<team> ──②~④──▶ 통합 tip ──⑤──▶ 대상(main) ──⑥──▶ 라이브 ──⑦──▶ 닫기
① 나노 완성: freshness FRESH(STALE 면 루트 병합 뒤 재시험 · STALE-OVERLAP 은 겹친 파일 arch 재대조)        증거: freshness 출력 1줄
② 수거: cherry-pick -x(기본) 또는 squash 1커밋 → 원장 행 {카드 · 워커 tip · 결과 sha · 방식 · 시각}             증거: cherry 게이트 통과 출력(OK|PASS+사유) + 결과 sha 도달 · 원장 행은 감사
③ 닫기: ft-nano-close(⑤ 게이트 통과) · wt=swept|none(P3 P3-6 이벤트 재시도)                                   증거: close 출력 · wt 값
④ 대상 동기화 → 후보 커밋 1개 만들기(한 명령 묶음 · fail-closed): fetch → T=origin/main sha 기록 → `is-ancestor T feat` 참이면 후보 = feat tip(ff) · 거짓이면 `merge-tree --write-tree T feat`(rc≠0·충돌 = 중단) → 기대 tree OID 기록 → `commit-tree <OID> -p T -p feat` 로 후보 생성 → `rev-parse 후보^{tree} == OID` 와 `is-ancestor T 후보` 둘 다 참 아니면 중단 → 삭제·「T 가 바꾼 경로」 변화 목록을 사람이 읽고 겹친 경로(양쪽이 같은 파일을 바꿈)는 결정 1줄    증거: T · feat tip · OID · 후보 sha · 경로 목록
⑤ 최종 게이트는 **후보 sha 에서**: 차분 → 전체 세트 1회 → 3버블 1회(서비스·러너·FE = 후보 sha 한 세트) → DA⑥(판정문이 후보 sha 를 이름) → push 는 그 후보만(force 0) → 원격 sha == 후보 sha 확인 · non-ff 거부 또는 T 이동이면 ④ 로 되돌아간다    증거: 차집합 0 · 4자 표 · DA 판정문(후보 sha) · 원격 sha
⑥ 라이브 1회: CD 리비전 commit-sha == 원격 sha · 3버블 4자 표                                                  증거: 리비전 라벨 · 표
⑦ 닫기 5 + CLOSEOUT → 소유 오케 「①~⑤ + 결과 sha」 → 매니저 close 대조 → planner 큐 행 클리어 + 다른 팀 큐에 「루트 이동 sha」 통지(§1 Q-4 사슬)    증거: CLOSEOUT 경로 · 3회신 seq
```
- L-1 **수거 방식 1개 기본 = `cherry-pick -x`**(v65 실측 · 공유 브랜치에 merge commit 0 · 출처 sha 가 메시지에 남음) · squash 는 「나노 커밋이 많아 1개로 접을 때」만. **어느 방식이든 닫는 증거 = 기존 cherry 게이트의 통과 출력(모드·사유) + 결과 sha 가 대상에 도달(`merge-base --is-ancestor <결과 sha> <대상>`)** · 원장 행은 감사 기록이고 게이트 REJECT 를 대신하지 못한다(DA r1 ②).
- L-2 **동시 랜딩 금지** = 같은 대상 브랜치에는 한 번에 한 팀 · 순번은 planner 큐(§1 Q-5 ①) · 한 팀이 ⑤ push 를 끝내면 다음 팀은 ④ 부터 다시(대상이 움직였으므로).
- L-5 **검사한 트리 = push 한 커밋**(S10 재발 차단): ④ 의 OID 와 후보 tree 가 같지 않으면 push 금지 · 후보가 아닌 다른 ref 를 push 하는 길은 절차에 없다 · 겹친 경로의 결정 1줄 없이는 ④ 를 닫지 못한다(DA r1 ③) · ④ 뒤 어떤 변경이든 ⑤ 를 전부 다시(DA r1 ④).
- L-3 **랜딩 원장 = 팀마다 1 파일**(`design/<x>/LANDING-LEDGER.md` · LANDING-POOL 의 ⒜feat 반영·⒝인덱스 열 그대로) — 「랜딩됨」은 매 갱신 HEAD 재확인(09-17 오판 3건 교훈) · planner 큐 행은 이 원장의 결과 sha 만 복붙.
- L-4 **겹침 카드 직렬** = 분해표에서 파일 집합이 겹치는 카드는 같은 석 또는 선행 지정 · STALE-OVERLAP 이 나오면 자동 병합 금지 · arch 1줄 판정.
