## 골 원문 (GOAL-harness.md 복붙)
내부 하네스, 내부 스킬스를 모니터하고 요청을 사용자에게 받아 해당 부분 바로 확인 검토하고. 실제 하네스와 스킬스를 업그레이드하고 레포에 커밋 푸시하며 전 환경에 물리적 컴퓨팅 환경에도 설치하도록 배포 발행(슬랙) 수신해 반영되 업그레이드.

메인 하네스를 유니크하게 머신들에 완전히 독립 배분해 운용하는것.

## §6 완료 조건 (카드로 옮김) — r2 (DA r1 Q3 HOLD 교정 · DA 파일 §2)
### 6-1. 비교는 «nodeid 상태표» 로 (실패 집합 아님)
- 고정: 같은 SHA · 같은 명령 인자(CI `ci.yml:155` 경로·`--ignore-glob` 그대로) · 같은 env(REDIS_HOST/PORT · `PAYMENT_MODE=local_mock` · `LOCAL_VLLM_BASE_URL=http://127.0.0.1:9/v1` · ★`UPDATE_GOLDEN` 미설정 기록★(`test_v65_unsealed_terminal.py:264` opt-in 쓰기 비활성)).
- 직렬 vs `-n 4 --dist loadgroup` 각각 `--junitxml` → nodeid → {passed·failed·error·skipped} + 수집 수·deselected 수. ★diff 0★ = 모든 nodeid 상태 동일 · 수집·deselected 수 동일 · 새 skip/deselect 0 · 워커 crash(「node down」·「replacing crashed worker」) 0.
- 기존 실패(로컬 env·node eval 등)는 원인별 표로 따로 대조 — 직렬·병렬 둘 다 같은 원인이면 «기존» · 원인이 다르면 diff.
- `-n 4` 2회 반복 = 같은 상태표. ★제한된 관측일 뿐 flake 부재 증명 아님★ — 그렇게 기록.
### 6-2. 환경 때문에 가려진 공유 Redis 시험 (DA Q3)
- 공유 6379 시험 대부분은 이미 `requires_real_redis` 로 CI 에서 deselect(`tests/worker/unit/conftest.py:26`) — 상태표의 deselected 목록에 그대로 남아야 한다(병렬화가 바꾸지 않음).
- 그 밖에 CI 경로에서 수집되는 공유 6379 모듈(마커 없음 · 예 `test_lst_handoff_claim.py`·`test_lst_handoff_k1_k4.py` · 간접 소비 `lst_handoff_cases`→`lst_leaf_cases`/`lst_source_cases`→`lst_runtime_cases`)의 nodeid 를 상태표에서 뽑는다. 그중 setup error·skip 의 원인이 `LST_TEST_REDIS_URL` 미설정이면 ★CI Run tests env 에 `LST_TEST_REDIS_URL: redis://localhost:6379/15` 추가★(CI services.redis = 일회용 컨테이너) 하고 로컬도 같은 값으로 다시 비교 — 그 nodeid 가 passed 로 «실행» 된 것을 상태표로 보인다. 원인이 다른 실패는 이 단위에서 고치지 않고 표에 남긴다.
- 그룹 소속 증거: `-n 4 --dist loadgroup -v` 출력에서 위 공유 모듈 nodeid 가 전부 `@shared_redis_6379` 접미로 찍힌다(수집 item 별 group 확인 · DA Q2 조건).
- 관찰(이 단위 밖 · 별건 후보): `test_lst_handoff_claim.py:21` 이 `redis://127.0.0.1:6379/0` 고정 — 로컬에서 돌리면 개발 Redis db0 에 닿는다(dev set = live).
### 6-3. CI·되돌림
- CI 1회 Python Test 잡 시간 + 워커 수 N(로그 「created: N/N workers」) 실측 · ≤6분 = 판정 438 닫힘 · >6분 = 라 재개 판단(planner).
- 되돌림 = 1커밋 revert(ci.yml 줄 + 마커 + lock).
