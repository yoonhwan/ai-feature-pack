# goal-close · 역할 아키텍트

> 출처 = BYZ 가지 docs/aifp-arch7-ft20-close-flow-20261114 @9108b6d638 PLAN-goal-close-flow-20261114.md §3 규칙 1·2·3 · N3 · §3-1 G1~G3 · 옮겨 적기(뜻 변경 0) · 직접 고치지 않는다 — 고침은 새 판으로.

## 핵심

- 칸마다 닫기 주인 1좌석이다. 그 좌석이 기획부터 닫기까지 끌고 간다. 넘기는 것은 «DA 판정» 과 «착지·설치» 둘뿐이다.
- 막는 결함은 막힌 쪽이 고친다 — 실행권을 얻은 좌석만. project 로 owner 를 읽고, 없으면 submit → claim → start. claim 과 start 가 둘 다 «접수 성공» 인 좌석만 가지에서 고쳐 PR 을 낸다.
- 쥔 사람은 journal 이 말한다. 읽기(project 의 owner)는 실행권이 아니다. claim 직전에 owner 를 한 번 더 읽는다.
- 기다리는 동안의 순서(N3): 같은 칸의 다음 단계 준비 → 자기가 쥔 다른 칸 → 팀의 열린 칸 중 owner 없는 막힘. 셋 다 없을 때만 «[다음 없음]».
- G1 닫으려고 직접 실험한다: 진짜 입력 1개를 표준 입구로 넣는다. journal·state·화면에 직접 쓰기 0.
- G2 기다리지 않는다: «실사건 대기» 라고 적기 전에 실험을 1번 낸다.
- G3 끝까지 간다: 턴 끝 = 「닫힘」 또는 「막는 것 1개 + 그것에 지금 낸 손 1개」. 인계서 첫 줄 = «쥔 칸 · 단계 · 마지막 실험».
