# goal-close · 흐름 1개와 규칙 6줄

> 출처 = BYZ 가지 docs/aifp-arch7-ft20-close-flow-20261114 @9108b6d638 design/teams/planner/research/ft-2.0/PLAN-goal-close-flow-20261114.md §3 · 옮겨 적기(뜻 변경 0) · 직접 고치지 않는다 — 고침은 새 판으로.

```
큰 골 ─ 조건 N칸(진행판 = 분자/분모 · 칸마다 «닫는 증거 1줄» 을 먼저 적는다)
  └ 조건 1칸 = 작은 골 = 닫기 주인 1좌석
       기획(끝 문장·닫는 증거·크기) → 구현(시험 Red→Green · 가지 push·PR) → DA(설계 1 · 구현 1)
       → 검증(설치본에서 실제 동작 1건) → 모니터(같은 증거가 다음 날에도 서는지 1회) → 닫기(분자 +1)
```

규칙 6줄(이것만 바뀐다):

1. **칸마다 닫기 주인 1좌석(= 골 파일의 «현재 담당» 칸 · §2-1).** 그 좌석이 기획부터 닫기까지 끌고 간다. 넘기는 것은 «DA 판정» 과 «착지·설치(master·desk)» 둘뿐이다.
2. **막는 결함은 막힌 쪽이 고친다 — 실행권을 얻은 좌석만.** 조건을 재다 결함을 보면, 닫기 주인이 그 턴에 `project` 로 그 work 의 owner 를 읽는다. owner 가 있으면 그 좌석 이름을 적고 다른 칸으로 간다(그 work 에 claim 하지 않는다). owner 가 없으면 표준 동사로 실행권을 얻는다: 접수 영수가 없으면 `submit` → `claim` → `start`. **`claim` 과 `start` 가 둘 다 «접수 성공» 인 좌석만 가지에서 고쳐 PR 을 낸다**(코드 주인 팀의 DA 가 판정). 하나라도 «낡은 실행권»·«완료 유보»·«접수 거부»·BUSY 면 고치지 않고 손을 뗀다. «넘기고 기다림» 은 없다.
3. **쥔 사람은 journal 이 말한다.** 읽기(`project` 의 owner)는 실행권이 아니다. 착수의 근거는 자기 이름으로 남은 journal 의 claim·start 줄이다. 쪽지 기억으로 발주·착수하지 않는다. 두 좌석이 owner 없음을 차례로 읽은 경우(설치본 2.0.34 코어로 tmp root 에서 직접 돌려 봄 · 10:0x): ⓐ 둘 다 claim 한 뒤 start → 먼저 claim 한 쪽 start = «낡은 실행권»(쓰기 0) · 나중 쪽만 «접수 성공» ⓑ 한쪽이 start 까지 한 뒤 다른 쪽 claim → 다른 쪽 = «완료 유보». 두 경우 모두 착수하는 좌석은 1개다. ⓑ 에서는 늦은 claim 이 그 work 에 미확정 표식을 남겨 먼저 쥔 좌석의 result 도 «완료 유보» 가 된다(지금 코어 동작 그대로 · 기존 미확정 확인 길로 푼다) — 그래서 claim 직전에 owner 를 한 번 더 읽는다.
4. **관측은 회차가 아니라 이어 재기다.** 칸이 실패하면 그 칸만 «고침 → 같은 식으로 다시 재기» 로 돈다. 통과한 칸은 다시 재지 않는다. 식을 바꿀 때만 DA 를 부른다(결함 1개마다 덧장·DA 0).
5. **하루 보고 첫 줄 = 분자.** «조건 a/b · 오늘 +k · 내가 쥔 칸 <이름> = <기획·구현·DA·검증·모니터 중 어디>». 분자가 안 움직였으면 둘째 줄 = 막는 것 1개와 그것을 고치는 좌석.
6. **빈 칸이 있으면 연다 — 지금 골에 붙은 카드만.** 다음 카드를 여는 계기 = 닫힘 또는 빈 칸(K1). 빈 칸으로 여는 카드는 «조건 <골>-<칸>» 줄이 있고 그 칸이 열려 있는 대기 카드가 먼저다(K3). 칸을 닫는 좌석은 닫기 단계에서 그 칸 조건 줄을 단 대기 카드가 0 인지 확인하고, 남았으면 완성/·보류/ 로 옮긴다. 골이 분자=분모가 되면 그 골 조건 줄을 단 대기 카드는 0 이고, 그 골 때문에 열리는 카드도 0 이다. 조건 줄 없는 카드(운영)는 골 일이 아니며 분자에 세지 않는다.
