## 2. 원인

1. `prereq()`(14~26줄)는 «- 선행:» 값에서 `r<번호>` 만 읽는다. 번호가 없거나(23줄) 번호가 카드 루트에 없으면(26줄) `선행불명` 을 돌려준다. 고르지 않는 것은 맞다(추측 0 · r2027).
2. `choose()`(140~141줄)는 `선행불명` 마다 `판정 불가 <팀> <카드> 선행 줄 판독 불가 — 건너뜀` 을 찍는다. 막는 것은 바퀴 캐시(`once`)뿐이다. 바퀴 안에서는 1줄이지만 다음 바퀴에 다시 찍는다.
3. 줄에 까닭이 없다. «참조 없음» 과 «루트에 없는 번호» 를 가르지 않고, 어떻게 고치는지도 없다.
4. 팀장에게 가는 것은 고를 카드가 0 일 때의 `[다음 없음] … 막힌 사유별 … 선행불명 n`(152줄)뿐이다. 카드 이름이 없다. 고를 카드가 1장이라도 있으면 이 쪽지는 가지 않는다. 그래서 팀장은 어느 카드를 고쳐야 하는지 모른다.

## 3. 고침

| # | 자리 | 규칙 |
|---|---|---|
| 1 | `choose()` 의 로그 | `선행불명` 줄은 그 카드의 «선행 값 + 까닭» 이 바뀔 때만 1줄 찍는다. 기억 = keeper 상태 `state["prereq_seen"]["<팀>|<카드>"] = {"val": <선행 값 그대로>, "why": <까닭 글>}`. 둘 다 같으면 줄 0. 값은 그대로인데 까닭이 바뀌어도 1줄 찍는다(r2 · DA 반례 2) |
| 2 | 줄 꼴 | `판정 불가 <팀> <카드> 선행 줄 판독 불가(<까닭>) — 건너뜀 · 고칠 꼴 «- 선행: 없음» 또는 «- 선행: r<번호>»`. 까닭 = `번호 참조 없음` 또는 `루트에 없는 번호 r<a> r<b> …`. 루트에 없는 번호는 **전부** 적는다(첫 번호만 적지 않는다 · 번호 순) |
| 3 | `prereq()` 반환 | 지금 값 3개(`""` · `선행` · `선행불명`)는 그대로 둔다. 까닭 글은 따로 돌려준다(둘째 값). 막는 판정은 바꾸지 않는다 |
| 4 | 기억 치우기 | 그 카드가 `선행불명` 이 아니게 되거나 대기 폴더에서 사라지면 `prereq_seen` 에서 그 열쇠를 지운다. 다시 `선행불명` 이 되면 1줄 찍는다 |
| 5 | 팀장 쪽지 | `[다음 막힘] <팀> 선행 줄을 못 읽는 카드 <n>장: <앞 3장 이름> · 고칠 꼴 «- 선행: 없음» 또는 «- 선행: r<번호>»` 1통. 지금 막힘 묶음이 «마지막으로 전한 묶음» 과 다를 때 보낸다(5-1~5-3). 고를 카드가 있든 없든 간다 |
| 5-1 | 묶음 지문 | 지금 막힘 묶음 = 그 팀 선행불명 카드의 (이름 · 선행 값 · 까닭) 전부. 그 지문을 바퀴마다 계산한다. 선행불명 카드가 0 이면 빈 묶음이다 |
| 5-2 | 두 기억을 나눈다 | `state["prereq_now"][<팀>]` = 앞 바퀴의 묶음 지문과 전이 번호(묶음이 바뀔 때마다 +1). `state["prereq_told"][<팀>]` = 마지막으로 **전송에 성공한** 묶음 지문. 지금 묶음이 비면 `prereq_told` 를 빈 값으로 되돌린다 |
| 5-3 | 보낼지 | 지금 묶음이 비어 있지 않고 `prereq_told` 와 다르면 보낸다. 열쇠 = `prereq|<팀>|<묶음 지문>|<전이 번호>`. 전이 번호가 들어가므로 같은 묶음이 다시 나타나도 옛 성공 지문과 겹치지 않는다. `prereq_told` 는 notify 가 성공(rc 0 또는 도착 확인)을 돌려줄 때만 지금 묶음으로 바꾼다. 실패 · 바퀴 3통 넘김(defer)은 바꾸지 않는다 |
| 6 | 5번의 보내기 | `k.notify` 를 쓴다. 받는 곳 차례 · 실패 지문 · 바퀴 3통 상한은 행 E 설계를 따른다 |
| 7 | `[다음 없음]` 쪽지(152줄) | 손대지 않는다(하루 1통 · 사유별 수) |

- 5-2 · 5-3 을 묶음 전이로 따라가면: X 전함 → 해소(빈 묶음 · told 비움) → X 다시 = told 와 다름 · 전이 번호 다름 → 다시 전함. X 전함 → Y 전함 → X = told(Y)와 다름 → 다시 전함. X 전함 → Y 전송 실패 → X = told(X)와 같음 → 안 보냄(팀장이 아는 묶음 그대로다).
- 실패한 열쇠는 행 E 의 실패 지문 규칙을 따른다(그날 재시도 0 · 다음 날 1회). `prereq_told` 가 안 바뀌었으므로 다음 날 같은 열쇠로 다시 간다. defer 는 지문을 쓰지 않으므로 다음 바퀴에 다시 간다.
- 판정은 하나도 바꾸지 않는다. 지금 건너뛰는 카드는 고친 뒤에도 건너뛴다. 줄 수와 알리는 길만 바꾼다.
- 1번의 기억을 keeper 상태에 두는 까닭: 바퀴 캐시는 바퀴가 끝나면 사라진다. keeper 가 다시 떠도 같은 줄을 또 찍지 않아야 한다.
- 로그 파일은 날마다 새로 생긴다. 값이 안 바뀐 카드는 새 날 파일에 줄이 없다. 그날 상태는 `[다음 없음]` 의 사유별 수와 5번 쪽지로 본다(Q2).

## 7. 다른 행과 겹침 · 운영 손

- `keeper_next.py` 를 행 C(`ft2-new-card-hold`) · 행 D+F(`ft2-launch-failed-end` L5 · L9)도 만진다. 이 카드는 `prereq()` 반환과 `choose()` 140~141줄 · 쪽지 1곳만 만진다. D+F L9 가 `prereq` · `choose` 를 고치므로 그 착지 위에서 시작한다.

- 카드 고침은 팀장 몫이다: cfo 4장 · harness 2장의 «- 선행:» 을 `없음` 또는 `r<번호>` 로. 이 설계의 범위 밖이다.
