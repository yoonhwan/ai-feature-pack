## R11-m1 — 비문자열 code의 타입 검사로 닫힘

`validate_frame`은 `isinstance(frame["code"], str)`를 membership 검사보다 먼저 수행한다. list/dict처럼 hash 불가능한 값도 frozenset 조회에 들어가지 않고 None으로 거부된다. `tick._run_component`는 None을 정적 RUNTIME_OUTPUT_INVALID로 매핑하고 실제 tick은 EXIT_RUNTIME(40)을 반환한다. 일반 Exception의 TypeError/EXIT_INTERNAL(50) 경로로 가지 않는다.

별도의 유한 합성 component가 정상 종료하면서 해당 JSON frame을 실제 결과 파일에 쓰도록 해 현재 tick.main/subprocess/decoder 경로를 실행했다:

| code의 JSON 타입 | validate_frame | 실제 tick exit | code / status |
|---|---|---|---|
| list | None | 40 | RUNTIME_OUTPUT_INVALID / runtime_error |
| dict | None | 40 | RUNTIME_OUTPUT_INVALID / runtime_error |
| null | None | 40 | RUNTIME_OUTPUT_INVALID / runtime_error |
| int | None | 40 | RUNTIME_OUTPUT_INVALID / runtime_error |
| float | None | 40 | RUNTIME_OUTPUT_INVALID / runtime_error |
| bool | None | 40 | RUNTIME_OUTPUT_INVALID / runtime_error |

모든 경우 MARKER_CODE가 tick 출력에 없었다. repository의 실제 tick 테스트는 list/dict/null/int 각각의 exit·정적 코드·status 및 출력/로그 marker 부재를 확인하고, 단위 테스트는 bytes/bool까지 포함한다. 단순히 “예외가 나지 않음”만 단언한 테스트가 아니다.

정상 code="" frame은 별도 실제 tick에서 **exit 0/status ok**로 수락됐으며, 기존 closed-schema·frame-building·registered-code 경로도 관련 테스트에서 통과했다.

## R11-m2 — 정확한 64-hex fullmatch로 닫힘

`_read_keys`는 문자열 타입과 `[0-9a-fA-F]{64}` fullmatch를 먼저 확인한 뒤 bytes.fromhex를 호출한다. whitespace를 decode 단계에서 묵인하지 않으며 exact NAMES·입력 상한·decoded bytes 기준 상호 distinct는 유지된다. `child_main`은 검증 결과 None이면 component import/실행 및 결과 frame 작성 전에 return 2로 종료한다.

실제 `python -m airag_consumer._pass_child --config <합성 경로>`에 stdin을 제공하고 stdout/stderr를 캡처했다:

| 불량 값 | 문자 수 | fromhex라면 decode 길이 | 실제 자식 exit | stdout / stderr bytes |
|---|---|---|---|---|
| 후미 공백 2개 | 64 | 31 | 2 | 0 / 0 |
| 후미 tab/newline | 64 | 31 | 2 | 0 / 0 |
| 선행·후미 공백 | 64 | 31 | 2 | 0 / 0 |
| 중간·후미 공백 | 64 | 31 | 2 | 0 / 0 |

대소문자만 다른 동일 bytes 키를 두 슬롯에 넣는 추가 관찰도 **exit 2 / 결과 0바이트**였다. 엄격 hex 검사 추가로 byte-wise distinct가 string-wise 비교로 퇴행하지 않았다.

repository의 기존 malformed stdin 8개와 추가 whitespace 4개는 각각 실제 child entry point에서 exit 2와 빈 결과를 단언한다. 정상 키 protocol 테스트는 실제 합성 runtime을 실행해 정확한 정제 frame을 확인한다.
