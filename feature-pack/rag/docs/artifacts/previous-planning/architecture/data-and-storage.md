# 저장, 정체성, 암호화

**상태: 확정(방향) · 스캐폴드(§"저장 경계"의 오픈/키 처리 로직 한정, 나머지는 미구현)**

SQLCipher + sqlite-vec, 원본 보존, 공간별 격리는 확정된 방향이다. 정확한 스키마/DDL은
아직 작성되지 않았다 — 아래 테이블은 논리 설계이지 확정된 마이그레이션이 아니다.
실제 구현 코드는 훨씬 작다 — [`../delivery/roadmap-and-gates.md`](../delivery/roadmap-and-gates.md) 참고.

## 저장 경계

**상태: 확정 · 스캐폴드**(open/init/key 로직은 코드로 확인됨)

하나의 SQLCipher DB와 그 SQLite 동반 파일이 저장 경계 전체다: 관리 원본 사본, 텍스트,
벡터, FTS, 메타데이터, 처리 큐, 청크 연결, 검색 이력이 모두 같은 암호화 경계 안에
있다. 평문 폴백은 없다 — SQLCipher나 키가 없으면 평문 SQLite를 조용히 여는 대신
실패로 끝난다.

- `original_ref`(엔진의 불변 관리 사본)는 `origin_uri`(외부 파일의 원래 위치, 바뀌거나
  사라질 수 있음)와 별개다.
- 키는 32바이트 난수다. phase 1은 이미 열린 file descriptor로 키를 읽는 방식(`--key-fd`)만
  지원한다; macOS Keychain 제공자는 설계되어 있으나 **미구현**이다
  (`keys.keychain_available()`는 현재 코드에서 항상 `False`를 반환한다 — 코드로 확인, 희망사항 아님).
- 여는 순서: 키 확보 → `PRAGMA key` 적용 → 실제 읽기 검증 → 스키마 검증. 틀린 키나
  평문 SQLite 파일은 실패로 끝나며 기존 DB를 절대 덮어쓰지 않는다(`init_db`가 비어
  있지 않은 기존 파일을 거부함 — `src/airag/db/connect.py`에서 코드로 확인).

## 정체성 모델

**상태: 제안**

| 개념 | 의미 |
|---|---|
| `source` | 논리적 원천 자료. 경로가 아니라 호출자 안정적인 `source_key`로 식별. |
| `source_revision` | 특정 입력 상태의 불변 스냅숏: 내용 해시, 원본 바이트 참조, 처리 버전. |
| `block` | 어댑터가 추출한 단위(페이지/문단/메시지/이미지 영역). |
| `chunk` | 하나 이상의 block을 참조하는 제한 길이 검색 단위. |
| `representation` | 원문, OCR, 추출식 요약, 비전 설명 등 — 직접 원문과 추정 표현을 구분. |
| `embedding` | `(chunk, representation, embedding_space)` 조합에 연결된 벡터. |

같은 논리 소스의 새 내용 → 새 `source_revision`. 원본 바이트는 같은데 변환/청커/임베딩
**profile**만 바뀌면 → 새 원본 리비전이 아니라 같은 원본 위의 새 파생 처리 세대.
embedding space는 모델 + 리비전 + 차원 + 모달리티 + 전처리 fingerprint를 함께 써서
격리한다 — 차원만 같다고 두 공간을 비교 가능하다고 보지 않으며, 서로 다른 공간의
벡터를 직접 비교하지 않는다.

## 발행과 삭제

**상태: 제안**

- 무거운 작업(파일 읽기, OCR, 비전, 임베딩 호출)은 쓰기 트랜잭션 **밖**에서 실행한다.
  짧은 최종 트랜잭션이 기대 리비전/세대를 재검증한 뒤 청크·연결·임베딩·FTS·활성
  리비전 포인터·발행 시퀀스를 함께 갱신한다. 중간에 실패해도 이전 검색 가능 리비전이
  그대로 남는다 — 절반만 발행된 상태가 되지 않는다.
- `delete`는 소스를 실시간 검색/확장에서 제외하고 재조정(reconcile)이 되살리지
  못하게 막는다. 외부 파일은 지우지 **않는다**. 삭제된 소스와 과거 리비전은 기본
  검색/확장에 나오지 않으며, 명시적 이력 조회로만 접근할 수 있다.
- `restore`는 tombstone을 해제하고 필요한 재조정을 수행한다. 명시적 복구 요청 없이는
  삭제된 소스가 실시간 검색으로 되돌아오지 않는다.
- 물리적 purge, 외부 파일 삭제, DB 전체 삭제, 자동 이력 정리는 1차 버전에 넣지
  않는다 — 용량은 입력 크기 상한, 동일 원본 바이트의 콘텐츠 주소 기반 중복 제거,
  용량 보고로 관리한다(자동 정리가 아니라).
