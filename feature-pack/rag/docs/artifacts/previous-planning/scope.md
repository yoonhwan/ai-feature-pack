# 목적과 책임 경계

**상태: 확정 · 미구현** (아래 §"완성 판정 개요"의 스캐폴드 항목 제외)

## 목적

가볍고 **암호화된 로컬** SQLite 기반 RAG 엔진. 여러 형태의 데이터를 수집·갱신·보존하고,
검색과 청크 연결 확장을 통해 실제 원본에 닿는 근거 묶음을 반환한다. 한 번 설치해
BYZ·KakaoBot 등 여러 소비 프로젝트가 같은 운영 계약으로 재사용하도록 만든다 — 프로젝트마다
DB/청킹/검색 루프를 다시 구현하게 하지 않는다.

| AI RAG core가 맡는 일 | 상위 에이전트가 맡는 일 |
|---|---|
| 문서·이미지·대화텍스트와 메타데이터의 등록·갱신·관리 | 어떤 자료를 어떤 목적에 쓸지 판단 |
| 암호화 저장, 원본 스냅샷, 청킹, 임베딩, 인덱스 생성 | 검색 근거로 답변·보고서·코드 등 생성 |
| 명시적 add/update/delete 요청 처리, 재시도, 재색인 | 외부 파일의 신규/변경/삭제 감지(아래 참고) |
| 검색, 원본 링크·원본 반환, 제한된 청크 연결 확장 | 추가 검색 필요성 판단과 질의 조정 |
| 처리 상태·버전·출처·검색 매니페스트 제공 | 사용자에게 결과 설명과 최종 의사결정 |

여기서 "데이터 생성"은 원본의 관리 사본, 정규화 표현, 청크, 벡터, 연결, 근거 묶음의
생성을 뜻한다 — 질문에 대한 최종 답변이나 업무 산출물은 포함하지 않는다. 이미지에서
검색용 설명(vision description)을 추출하는 처리는 입력 가공이며, 그 설명은 원본과
구분해 별도로 기록한다.

## 책임 경계 (확정, 2026-09-09 — 초기 내장 워처 계획을 대체)

**파일의 신규/변경/삭제 감지, 파일시스템 워처, 폴더 인벤토리, 폴링, 스케줄, 트리거
디바운스/재시도 타이밍은 소비 프로젝트의 몫**이다 — core가 아니라 외부 배선이다.
`airag` core는 명시적 `add`/`update`/`delete`/`search`/`expand`/`fetch`/`manage` 요청만
받아 표준화된 결과/근거를 반환하는 일반 처리기다. core 안에는 내장 디렉터리 워처,
루트 인벤토리 폴링, 자동 폴더 탐색, 상주 데몬, 소스 감시 루프가 없다.

무엇이 트리거했든 core 안에 그대로 남는 것:

- 안정적인 `source_key`/ID, 호출자 idempotency key, 예상 리비전(expected revision) 불일치 검출.
- 원자적 발행(publication)과 논리 삭제(tombstone) — 절대 절반만 발행된 상태를 남기지 않음.
- 모델 공간(embedding space) 격리 — 서로 다른 모델/리비전의 벡터를 섞지 않음.
- 검색 + 그래프 확장 전체에서 하나의 일관된 읽기 스냅숏.

`delete` 요청은 **원본 파일이 이미 사라진 뒤에도** 등록된 소스를 식별해 — core가 이를
실시간 검색에서 제외하고 관리 원본/이력을 보존한다. 외부 파일 자체를 지우지는 않는다.
재수입(reimport)은 **요청 시 core가 수행하는 작업**이며, 재수입이 필요한지/언제 필요한지
판단하는 것은 소비 프로젝트의 몫이다. 소비자 측 워처는 이후 별도 예시/어댑터로 제공될
수 있으나 지금은 구현·패키징하지 않는다.

상세 계약과 요청/응답 형태: [`contracts/consumer-integration.md`](contracts/consumer-integration.md).
결정 출처: [`decisions/log.md`](decisions/log.md).

## 완성 판정 개요

**상태: 확정(판정 기준) · 미구현(실제 판정 미실시)**

"완성"은 지원 입력 전체의 실제 처리, 암호화 저장, 소비자 요청 기반 add/update/delete
처리, 검색/원본 반환/확장, 실패 복구 시뮬레이션, 사용자 투어가 끝난 상태다 — 코드가
존재하는 것만으로 완성이 아니다. 순서와 실제 현재 상태는
[`delivery/roadmap-and-gates.md`](delivery/roadmap-and-gates.md) 참고. 지금은 phase 1
스캐폴드(`init`/`manage doctor`/`manage verify`)만 있으므로, 이 문서를 읽기 전에는
아무 기능도 동작한다고 가정하지 않는다.

## 이 패키지의 범위 밖

별도 LangChain/LlamaIndex 계층, 웹 UI, 원격 DB 서비스, 답변 생성 에이전트는 이 엔진에
요구하지 않는다. 필요해지면 같은 Python API 위에 나중에 붙일 수 있다.
