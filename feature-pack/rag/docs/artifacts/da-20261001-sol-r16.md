## 과완화 mutation — 거부가 실제로 검증되는지

임시 pytest plugin과 메모리 AST 함수로 현재 테스트에 다음 mutation을 대입했다. 저장된 source/test는 변경하지 않았다.

| mutation | 실행 테스트 | 결과 |
|---|---|---|
| stored_row_is_consistent를 True로 고정 | stored-row tamper 3종 | **2 failed / 1 passed** |
| current inode 비교를 stored inode로 대체 | 기존/새 replacement 2건 | **2 failed** |
| 초기 committed prefix mismatch 검사를 건너뜀 | drift prefix/절단 회귀 | **1 failed** |

모두 pytest exit 1이며 import/setup 오류가 아니었다. B4를 제거해도 inode 값 변조는 B2가 계속 잡기 때문에 한 보존 사례가 통과한다. 다른 guard의 정상 거부를 mutation 실패로 억지로 세지 않았다. inode를 빼면 동일 bytes replacement가 실제 성공하여 거부 기대가 깨지고, prefix 검사를 빼면 소비 바이트 재작성의 거부 기대가 깨진다.

test의 device helper는 collector.os proxy만 교체하고 소스의 실제 stat 결과를 대상으로 dev/inode를 모델링한다. 무관한 파일/FD는 원본을 사용한다. clone test는 실제 kernel inode가 바뀌었음을 먼저 확인하고, stored inode로 일관된 lstat/fstat을 반환해 open-race 오탐으로 성공/실패를 가리지 않는다. 실제 volume mount/reboot를 실행한 것은 아니다.

pending test는 lost ack 전 이벤트와 identity row, first_seen_at/normalized_sha256를 보존하고 plan finalized를 확인한다. ledger commit 후 native checkpoint가 따라잡는 복구를 원래 first_seen_at·재생된 normalized bytes와 함께 검증하며 중복 event를 만들지 않는다.

## Minor — R16-m1: zero-prefix의 event epoch를 stored incarnation과 직접 비교하지 않는다

- 위치: `test_a_row_with_nothing_consumed_yet_survives_a_device_change`의 두 파라미터.
- 현재 테스트는 재수집 성공, event 개수 1, device/inode/incarnation row 불변을 확인한다. 실제 **event.producer_epoch 및 ledger.sources.incarnation**이 최초 stored incarnation과 같은지는 직접 확인하지 않는다. 첫 event 전에는 기존 ledger event가 없으므로 이 연관을 검증하는 것이 중요하다.
- `_normalize_message`가 전달받은 epoch 대신 `r16-mutated-epoch`로 event를 만드는 mutation을 대입해 실제 producer_epoch를 잘못 만들었다. 두 zero-prefix 테스트는 그대로 통과했다. 독립 관찰은 event epoch가 stored와 다르고 ledger source incarnation은 stored와 같은 **관측 가능한 불일치**를 확인했다.

```text
WRONG_EVENT_EPOCH_ZERO_TESTS_EXIT 0
WRONG_EVENT_EPOCH_ZERO_TESTS_TWO_PASS true
MUTANT_EVENT_EPOCH_MATCHES_STORED false
MUTANT_LEDGER_INCARNATION_MATCHES_STORED true
```

- 본 HEAD 구현에는 이 mutation이 없으며 동일 경로의 독립 확인은 정상이다:

```text
CURRENT_ZERO_EVENT_EPOCH_MATCHES_STORED true
CURRENT_ZERO_LEDGER_INCARNATION_MATCHES_STORED true
```

- 보정: 두 zero 상태 모두에서 수집 전 저장 incarnation을 캡처하고 모든 event.producer_epoch와 normalized ledger source incarnation을 그 값과 비교한다. 현재 production 결함이 아닌, 중요 invariant의 영구 회귀 강도 보강이므로 minor로 판정한다.
