# AIRAG.app — 메뉴바 앱 1개가 tick 을 5분마다 돌린다

## 0. 결론
1. **추천 = 메뉴바 앱 `AIRAG.app` 1개.** Swift 로 만든 작은 앱이 5분마다 기존 tick 을 자식으로 실행한다. 메뉴에 상태·시작·정지가 보인다. launchd plist 를 직접 만지지 않는다.
2. **tick.py 는 거의 그대로 쓴다.** 앱은 launchd `StartInterval` 자리만 대신한다. 새 상주 진입점(serve)은 만들지 않는다.
3. **R-H(op 자식 HOME 격리)는 함께 쓴다.** 그러면 권한 창이 아예 안 뜰 가능성이 높다. 떠도 앱이 책임 주체라 «허용» 1번이면 된다. R-H 는 재빌드 때 허용이 풀리는 위험을 덮는 보험이다.
4. **오빠 손 = 최대 클릭 1번 + 터미널 한 줄 2번.** 한 줄은 앱 설치·시험 시작용이고, 다른 한 줄은 재기동 확인용이다. 둘 다 master 가 `ft-hil.sh` 로 드린다.
5. **오빠 결정 1건(나중)**: 재빌드 뒤에도 허용을 유지하려면 안정 서명이 필요하다. 지금은 비용 0 인 «이 맥 전용 자체 서명 인증서»를 추천한다. Apple 개발자 인증서(연 99달러)는 배포가 필요할 때만 고른다(§3).

## 3. 권한 귀속과 유지
### 3-1 누가 책임 주체인가
- LaunchServices 로 연 앱(Finder 더블클릭·`open`·로그인 항목)이 띄운 자식 프로세스는, 그 앱을 책임 주체로 갖는다. tick python과 그 손자 op 의 «다른 앱 데이터» 요청은 `AIRAG.app` 이름으로 묻는다.
- 그래서 앱은 tick 을 `Process`(posix_spawn)로 바로 띄운다. 자식의 책임 주체를 바꾸는 기능은 쓰지 않는다. 셸 경유·`launchctl`·`open` 재호출도 쓰지 않는다.
- 라벨: **지지**(터미널은 Ghostty 가 책임 주체라 허용이 이어졌다 · 10-18 h1·oprh) · **이 맥에서 앱 번들로는 미확인**(§5 시험이 가른다).

### 3-2 R-H 를 함께 쓴다
| 경우 | R-H 없음 | R-H 있음 |
|---|---|---|
| 첫 실행 | 창 1번 → 허용 1클릭 | 창 0 예상(op 가 보호 폴더를 안 연다) |
| 앱 재빌드·업데이트 뒤 | 서명이 바뀌면 창 다시 뜰 수 있음 | 창 0 예상(요청 자체가 없음) |
| R-H 가 앱 아래서 안 먹히면 | — | 창 1번 → 허용 1클릭(안 B 본래 경로로 내려감) |
그래서 R-H 를 빼지 않는다. R-H 는 «창 0» 을 노리고, 안 B 의 «허용 1회» 는 R-H 실패 때의 받침이다.

### 3-3 허용이 다음 기동·재빌드 뒤에도 유지되는가
| 서명 방식 | 다음 기동(같은 빌드) | 재빌드 뒤 | 비용·손 | 판단 |
|---|---|---|---|---|
| 임시 서명(ad-hoc · `codesign -s -`) | 유지 예상(같은 cdhash) · 미확인 | **풀린다**(cdhash 가 바뀜 → 다시 물을 수 있음) | 0 | 시험 1회차만 · 운영엔 비추 |
| **이 맥 전용 자체 서명 인증서** | 유지 예상 | 유지 예상(같은 인증서·같은 번들 ID 면 지정 요건이 같음) | 0원 · 인증서를 터미널에서 1회 만들어 로그인 키체인에 넣음 · `-T /usr/bin/codesign` 으로 키체인 창 회피 | **추천** · 키체인 창이 뜨는지 미확인(§6 K6) |
| Apple Developer ID | 유지 | 유지 · 다른 맥 배포 가능 · 공증 가능 | 연 99달러 · 오빠 계정 가입 | **오빠 결정 사항** · 배포가 필요할 때만 |
- 번들 ID 는 하나로 고정한다(예: `com.byourz.airag`). 바꾸면 허용이 새로 필요하다.
- 앱은 `~/Applications/AIRAG.app` 한 곳에만 둔다. 다운로드 폴더에서 바로 열면 macOS 가 임시 위치로 옮겨 실행해(App Translocation) 신원이 흔들린다.

## 4. 로그인 시 자동 실행
- 메뉴의 «로그인 시 실행» 토글이 `SMAppService.mainApp.register()` 를 부른다(macOS 13+). 앱 자신을 로그인 항목으로 등록한다.
- 우리 쪽 launchd plist 파일은 0개다. 등록 정보는 시스템이 관리하고, 시스템 설정 «로그인 항목» 에 `AIRAG` 이름으로 보인다. 일반인도 거기서 끌 수 있다.
- 처음 등록할 때 «백그라운드 항목 추가됨» 알림이 뜰 수 있다. 이것은 권한 창이 아니고 알림이라 클릭이 필요 없다(미확인 · §5 에서 기록).
- 옛 `com.airag.consumer` plist 는 지금 미적재다(앞 설계 F3). 앱 운영 전환 때 «다시 적재하지 않음»만 확인하고, 파일 삭제는 별도 HIL 이다.

## 5. 시험 설계 — 클릭 최대 1번 (사전 약속)
전제: 앞 설계의 탐지기 시험 S0·S1(터미널 · 클릭 0)을 먼저 Nano 가 돌린다. 결과에 따라 앱 시험의 기대값이 정해진다. 실행은 master 가 `ft-hil.sh --add` 로 `! bash /tmp/h<N>` 한 줄로만 드린다. 값 출력 0.

**h-A (설치 + 1회차)** — 오빠 터미널 한 줄
1. 빌드한 `AIRAG.app` 을 `~/Applications` 에 복사한다(시험 빌드는 자체 서명).
2. `open -W -n ~/Applications/AIRAG.app --args --once` 로 앱을 1패스 모드로 연다. 앱은 tick 1번을 돌리고 스스로 끝난다(메뉴바 상주 0).
3. 끝나면 구간 TCC 로그를 집계한다(PROMPTING 줄·AppData/AllFiles 요청 줄·책임 주체 이름). tick 로그 마지막 줄의 `status`·`code` 를 남긴다.

**오빠가 보는 것**: 창이 뜨면 1번만 뜬다. 문구는 «"AIRAG" 이(가) 다른 앱의 데이터에 접근하려고 합니다» 꼴이다. **«허용»을 1번 누른다.** 창이 안 뜨면 아무것도 누르지 않는다.

**h-B (재기동 확인)** — 오빠 터미널 한 줄 · 클릭 0
- 같은 `open -W -n … --once` 를 1번 더 실행하고 같은 집계를 한다. 이것이 «반복 0» 의 증거다(새 프로세스·같은 앱).

| h-A 결과 | h-B 결과 | 읽는 법 | 다음 |
|---|---|---|---|
| PROMPTING 0 · status ok | PROMPTING 0 · ok | R-H 가 앱 아래서도 먹힌다 · 클릭 0 | **채택** · 메뉴바 상주 모드 운영 승인으로 |
| PROMPTING 1(책임 주체 = AIRAG) · 허용 뒤 ok | PROMPTING 0 · ok | 앱 허용이 다음 기동에 이어진다 | **채택**(클릭 1회로 끝) · 재빌드 유지는 §3-3 자체 서명으로 |
| PROMPTING 1 · 허용 뒤 ok | **PROMPTING ≥1** | 앱 허용도 세션 한정 → 안 B 불성립 | 즉시 중단 · **안 C(SDK)** 로 · master 보고 |
| PROMPTING 1 인데 책임 주체가 python·op | — | 앱이 책임 주체가 아니다(귀속 실패) | 중단 · 허용 누르지 않음 · 안 C 로 |
| status 가 ok 아님(키 오류 외) | — | 권한과 무관한 실패 | 그 code 로 별도 진단 · 판정 보류 |
| 앱이 60초 안에 안 끝남 | — | tick 상한(호출 21초 × 3병렬 + 패스) 초과 · 판정 불가 | 앱 종료 · 로그만 수집 · master 보고 |
상한: h-A·h-B 각각 70초 안(하드 룰 22). `open -W` 는 `timeout 70` 으로 감싼다.

- **하지 않은 것**: op 실행 0 · 권한 창을 띄우는 실행 0 · launchctl 변경 0 · plist·runtime.json·설치본·DB 변경 0 · 값 출력 0 · push 0. 실행한 것은 읽기뿐이다(`swiftc --version`·`security find-identity`·`plutil -extract`·로그 마지막 줄 필드 이름). 쓴 파일 = 이 문서 1장.
