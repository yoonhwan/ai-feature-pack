### R1. 키체인이 잠긴 뒤에는 같은 서명 키를 다시 사용할 경로가 없다

- 기준: §3-3, K3, K6, Q2, Q5. 재빌드에도 같은 신원을 쓰고, 키체인 접근 창을 피해야 한다.
- 위치: `feature-pack/rag-consumer/macos/build.sh:60`, `:62`, `:78`, `:80`, `:85`. 서명 경로는 `:40`부터다.
- 재현 입력: `make-identity`로 인증서를 만든 다음 macOS를 재기동하고, `AIRAG_SIGN_IDENTITY='AIRAG Local Signing' bash build.sh build`를 실행한다. 이 회차에는 실행하지 않았다.
- 기대: 기존 인증서로 다시 서명한다. 같은 번들 ID와 지정 요건을 유지한다.
- 실제 코드 경로: 임의 비밀번호는 함수의 지역 변수에만 있다. 키체인 생성과 해제에 사용한 뒤 보관하거나 사용자에게 전달하지 않는다. 재기동으로 키체인이 잠기면 `sign_app`에는 해제 경로가 없다. `make_identity` 재호출도 기존 키체인 파일이 있으면 거부한다. `:85`는 다음 세션에 비밀번호가 필요하다고 알리지만 그 비밀번호를 복구할 수단을 제공하지 않는다.
- 같은 로그인 동안 키체인이 계속 풀려 있으면 다른 셸에서도 서명될 수 있다. **셸이 끝나자마자 실패한다는 지적은 아니다.** 재기동 또는 정상적인 키체인 잠금 이후의 재사용이 끊긴다는 반례다.
- 고쳐야 할 동작: 같은 개인키를 재사용할 수 있는 보관·해제 절차를 제공한다. 키체인 또는 인증서를 매번 새로 만드는 방식은 K3의 같은 신원 유지 조건을 닫지 못한다. 실제 창 유무는 별도 승인된 시험으로 확인해야 한다.

### R2. 정지 후에도 op 또는 실제 패스를 실행하는 손자가 남을 수 있다

- 기준: K5, 발주 검토 항목 3. 다음 예약뿐 아니라 실행 중인 작업의 정지를 검토한다.
- 위치: `feature-pack/rag-consumer/macos/AIRAG/AIRAG.swift:198`, `:201`, `:222`, `:334`, `:338`. 실제 손자는 `feature-pack/rag-consumer/src/airag_consumer/tick.py:410`, `:501`, `:560`, `:562`에서 실행된다.
- 재현 입력: tick이 `op read` 또는 `_pass_child`의 종료를 기다리는 동안 메뉴의 정지를 누르고, tick 종료 직후 시작을 누른다. 이 회차에는 실행하지 않았다.
- 기대: 앞 패스의 작업이 정리된 뒤 재시작할 수 있다.
- 실제 코드 경로: 앱은 양수 PID 하나에만 SIGTERM과 SIGKILL을 보낸다. tick에는 SIGTERM을 받아 실행 중인 `subprocess.run`의 자식을 정리하는 처리가 없다. 운영체제는 부모 PID에 보낸 신호를 자식에게 자동 전파하지 않는다. tick이 기본 SIGTERM 동작으로 끝나면 `passFinished`가 PID를 지우고 강제 종료 예약도 취소한다. 손자는 계속 실행될 수 있고 시작 메뉴는 다시 활성화된다.
- tick의 잠금 파일 설명자도 tick 종료 때 닫힌다. `_run_component`는 `close_fds=True`로 자식을 띄우므로 그 잠금이 손자 작업의 생존을 보호하지 않는다. 따라서 앞 손자의 종료를 기다리지 않은 재시작 경로가 있다.
- 고쳐야 할 동작: 실행 중인 작업 전체의 수명을 정지·재시작 상태와 묶는다. 구현 방식은 설계 담당자가 정한다. tick 파일 수정 금지라는 구현 카드의 제약 때문에 앱의 PID 한 개 종료를 손자까지 정리된 것으로 간주해서는 안 된다.

### R3. --once의 대기 예산이 최대 75초여서 70초 상한을 지키지 못한다

- 기준: §5 h-A·h-B의 70초 상한, 발주 시험 시간 제한.
- 위치: `feature-pack/rag-consumer/macos/AIRAG/AIRAG.swift:286`, `:291`, `:293`, `:295`.
- 재현 입력: tick이 65초 동안 끝나지 않고 SIGTERM 유예 5초에도 종료하지 않으며, SIGKILL 뒤 종료 통지가 즉시 도착하지 않는 경로를 실행한다. 이 회차에는 실행하지 않았다.
- 기대: 앱이 같은 전체 마감 안에 작업을 정리하고 종료한다.
- 실제 코드 경로: 최초 65초, SIGTERM 뒤 5초, SIGKILL 뒤 다시 5초의 상대 대기를 연속으로 허용한다. 최대 대기 예산만 75초이며 프로세스 시작 등의 시간은 별도다. `:286`의 70초 이내라는 설명과 다르다. 외부 `timeout 70 open -W ...`는 앱이 스스로 종료한다는 보장이 아니며, 외부 명령의 종료만으로 앱과 손자의 정리도 입증되지 않는다.
- 고쳐야 할 동작: 최초 시작부터 하나의 전체 마감을 사용하고, 종료 유예와 회수 시간을 그 안에 포함한다. 정상 완료와 마감 종료를 분리해서 검증한다.

### R4. --once는 앱 경로 검사를 건너뛴다

- 기준: K8. 앱이 자기 경로를 검사하고 잘못된 위치에서 실행하면 경고한다.
- 위치: `feature-pack/rag-consumer/macos/AIRAG/AIRAG.swift:357`, `:360`, `:425`, `:427`.
- 재현 입력: Downloads에 있는 AIRAG.app을 `--once` 인자로 연다. 이 회차에는 실행하지 않았다.
- 기대: 잘못된 앱 위치를 확인하고 경고한다.
- 실제 코드 경로: 경로 검사는 메뉴바 모드의 `applicationDidFinishLaunching` 안에만 있다. `main`의 `--once` 분기는 그 전에 tick을 실행하고 종료한다. 따라서 잘못된 위치 또는 App Translocation 위치에서 한 번 실행하는 경로에는 검사도 경고도 없다.
- 고쳐야 할 동작: 실행 모드를 나누기 전에 공통 경로 검사를 수행한다. 창 없는 모드의 실패·경고 방식은 설계에서 정한다. 현재 경로 검사 순수 함수의 시험만으로 이 분기의 준수를 입증할 수 없다.

## 범위 밖 1건과 값 노출 검토

**O1. app.json의 실행 파일 재지정은 허용 목록 없는 실행 경로다.** `resolveSettings`는 절대 경로 또는 `~/` 경로면 `python`을 받는다(`AIRAG.swift:127`, `:132`). `makeTickProcess`가 이를 그대로 실행한다(`:272`). 예를 들어 `{"python":"/tmp/custom-python"}`을 넣으면 그 파일을 tick 인자와 함께 실행하도록 설정된다. 셸 문자열 주입은 아니지만 앱의 책임 주체 아래 실행 파일을 바꾸는 표면이다. 다만 고정된 계약에는 설정 재지정 금지·허용 목록·다른 로컬 사용자에 대한 위협 모델이 없다. 소유 사용자가 설정을 바꾸는 행위를 새 거부 기준으로 만들지 않고 범위 밖으로 기록한다. 채택 여부는 설계 밖 결정 1의 판단으로 남긴다.

stderr는 고정 모양의 단어로 정제하지 않고 `app.err.log`에 그대로 쓴다(`AIRAG.swift:279`). 매 패스 잘라 쓰므로 보존 범위는 마지막 패스다. 최초 생성 모드는 0600이고 최종 심링크는 거부한다. tick의 통상 오류는 고정 문구이며 op 출력은 `capture_output`으로 수집하고 패스 자식 stderr는 버린다. 이 소스 범위에서 실제 키·토큰이 앱 로그로 유출되는 입력은 확인하지 못했다. 따라서 무해하다고 확정하거나, 정제하지 않는다는 이유만으로 값 노출 반례를 만들지 않는다. 실제 키·토큰 파일을 읽는 시험은 하지 않았다.

## 변경 경계

쓴 파일은 이 판정서 하나다. 앱·시험·빌드 스크립트·설계·설치본·설정·DB를 수정하지 않았다. 앱 실행·설치·키체인 쓰기·op 실행·launchd 적재·권한 창·실제 종료 신호·commit·push는 모두 0이다. 빌드한 것은 임시 순수 시험 실행 파일뿐이다. 2회차에는 R1~R4와 이들이 요구하는 시험을 먼저 대조한다. 운영 권한·로그인·재빌드의 미시험 항목을 코드 시험 통과로 대신하지 않는다.
