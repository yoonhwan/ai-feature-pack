# 3. M3 — 계측 인수 조건 (r16 §3 표·§6 인수 조건 대체/보강)
r16 §3 의 필드 선택(NAMES 이름만·값 비출력)은 수용되었다. 아래가 «닫힌 스키마·실패 경로·수집 실패·수치 의미·시간·크기·시험·되돌림» 이다.
## 3.1 닫힌 스키마
로그 줄에 최상위 키 `probe` 하나를 추가한다(기존 필드 불변). 구조: `{"v": 1, "keys": [...], "tick_total_s": <수>, "load1": <수|null>, "op_resident": <정수|null>, "probe_error": [<허용 목록 문자열>…]}`
| 항목 | 규칙 |
|---|---|
| `keys` | 길이 **0~3**·`name` 은 `NAMES` 3종 중 하나·**중복 0** |
| `keys[].attempts` | 길이 **1~2**(재시도 1회 상한 — 세 번째 시도 기록 불가)·`{start_ms, end_ms, outcome}` |
| 시간 값 | `start_ms`·`end_ms` 는 틱 시작(`time.monotonic`) 기준 **유한·비음수**·`end_ms ≥ start_ms`·소수 셋째 자리 반올림(기록 직전 1회) |
| `outcome` 허용 목록 | `ok`(rc=0 이고 출력이 `_KEY` 형식 일치) · `bad_format`(**rc=0 이나 형식 검증 실패** — 기존 코드의 `OP_KEY_READ_OR_FORMAT_FAILED` 와 같은 지점) · `nonzero_rc`(rc≠0 — 같은 코드) · `timeout`(`TimeoutExpired`) · `exec_error`(`OSError`). 그 밖 값 기록 0 |
| `tick_total_s` | **종료점 = 로그 줄 직렬화 직전**(`json.dumps` 호출 직전). 시작점 = `main` 의 첫 `time.monotonic()` |
| `load1` | `os.getloadavg()[0]`(유한 비음수)·실패 시 `null` |
| `op_resident` | §3.3 정의·실패 시 `null` |
| `probe_error` | 허용 목록 `load_unavailable` / `op_resident_unavailable` / `collect_failed` 의 부분집합(없으면 키 자체 생략) |
- 문자열 값은 위 닫힌 목록에서만 나온다(참조·환경·경로·출력 문자열 유입 0). 값 비출력 센티넬 시험(§3.5) 필수.
## 3.2 실패 경로 정의
| 상황 | `probe` 기록 |
|---|---|
| 환경에 세 키가 이미 있음(`op read` 0회) | `keys: []` · `tick_total_s` 만 |
| 일부만 누락 | **누락된 키만** `keys` 에 기록(있던 키는 항목 0) |
| 호출 전 설정 오류(`CREDENTIAL_SETTINGS_*`·`OP_SERVICE_ACCOUNT_*`·`EXISTING_KEY_FORMAT_INVALID` 등 `op` 호출에 도달 못 함) | `keys: []` · 기존 `code`/`exit` 그대로 |
| 병렬 작업 중 한 키가 예외(`TickError`) | **수집은 `read()` 내부의 키별 사전 할당 기록 목록에 시도마다 `finally` 로 추가**한다(`pool.map` 반환값 경유 금지) → 먼저 예외가 나도 `with ThreadPoolExecutor` 가 나머지 작업을 기다리는 동안 나머지 키의 시도 기록이 남는다. 키마다 자기 목록만 갱신(공유 목록 변이 0) |
| 최종 `TickError` | `probe` 를 그 오류 로그 줄에도 합류(기존 `code`·`type` 불변) |
## 3.3 `op_resident` 의 정의 (기존 `op_children` 대체)
- 의미 = **틱 시작 시점에 상주하던 `op` 프로세스 수**(상주 daemon 포함 전체). **이 틱이 만든 자식 수가 아니다**(그건 `attempts` 개수가 대신한다 — 이름 `op_children` 은 폐기).
- 방법 = `ps -axo comm=`(**명령 이름만**; 인자·환경·참조 비열람)의 출력에서 basename 이 `op` 인 줄 수. **추가 `op` 실행 0.** 수집은 **읽기 예산(7초 룰 마감) 시작 전**에 하고 자체 한도 **1.0초**·초과·실패 시 `null` + `probe_error`. 이 한도 때문에 읽기 호출·재시도 횟수·기한이 바뀌지 않는다.
- 이 필드는 **선택 필드**다: 구현 DA 가 `ps` 추가 서브프로세스를 계측의 행위 변경으로 판정하면 **필드째 삭제**한다(H4 는 `attempts` 겹침으로 본다).
## 3.4 계측 수집 실패가 본 동작을 바꾸지 않음
- 모든 계측 수집·직렬화는 `try/except Exception` 으로 감싸 **실패해도 기존 `exit`·`status`·`code`·`type`·`summary`·`op` 호출 횟수·재시도 횟수·`TickError` 전파를 바꾸지 않는다**(수집 실패 표현 = `probe_error`·`null`).
- 시간 한도: 수집 전체(부하·프로세스 수) ≤ 1.0초·읽기 마감 밖에서 수행.
- **최악 행 크기:** 키 3 × 시도 2 × (숫자 둘·허용 문자열 하나) + 고정 필드 → 설계 상 1KB 미만. `LOG_MAX_BYTES=1,000,000` 은 **파일 회전 기준**이며 `append_log` 가 큰 단일 행을 거부하지 않는다 — 따라서 **상한은 직렬화 규칙(허용 목록·소수 3자리·길이 ≤3/≤2)으로 보장**하고 시험에서 **최악 행(키 3·시도 2·모든 `probe_error`) 직렬화 길이 ≤ 2,048바이트**를 단언한다.
## 3.5 시험·커밋 인수 조건
- **공통:** 실제 `op` 호출 0 — 합성 `op`(가짜 실행 파일 또는 `subprocess.run` 대체)·주입 시계만. 값 센티넬(환경·참조·토큰 값)이 로그·결과·화면에 0.
- **커밋 ⓐ(계측 · 행위 불변):** 기존 상수 **7.0/14.0 그대로**. 시나리오(성공 / timeout→성공 / timeout→timeout / timeout+출력 있음 / rc≠0 / rc=0 형식 오류 / `OSError` / 남은 마감 소진)를 **ⓐ 이전 커밋(기준)과 ⓐ 이후에서 같은 주입 시계·합성 `op` 로 실행**해 **`subprocess.run` 호출 횟수·호출별 `timeout` 인자·`TickError`(`exit`·`code`·`kind`)·반환 키 값이 동일**함을 단언한다(기준 기록은 기존 시험 재사용 가능). 계측 수집을 일부러 실패시킨 변이(부하·`ps` 예외·직렬화 예외)에서도 위 항목이 동일.
- **커밋 ⓑ(상한 · 행위 변경):** 10.5/21.0 으로 바꾸되 ① 두 번째 시도의 timeout = `min(10.5, 남은 마감)` ② 마감 소진 시 재시도 없음 ③ 첫 timeout 에 stdout/stderr 출력이 있으면 재시도 없음 ④ **세 번째 시도 없음** 을 합성 시험으로 단언. 600·300·70 값 사용 0(70 은 천장 단언에만 허용).
- 스키마 시험: 닫힌 스키마(§3.1) 위반(키 4개·중복·시도 3개·음수·NaN/inf·`end<start`·허용 밖 outcome)을 주입한 직렬화기가 거부/`probe_error` 로 떨어지는지.
## 3.6 되돌림·승인 경계
- 설치(R-2) **직전** 현재 설치본을 백업(`runtime.bak-<ts>`)하고 **모듈 해시를 기록·검증**한다(diff 0). 이 백업이 규칙에 맞는 **기본 복원 대상**이다(직전 설치본 = 21:23 의 7.0/14.0 판).
- **`runtime.bak-20261016-2123`(30초 판)은 이력 증거일 뿐 기본 복원 대상이 아니다.** 30초 판으로의 복원은 규칙 12 위반(600/300 금지·70초 안이라 해도 7초 룰 값 아님)이라 **오빠 판정 없이 하지 않는다.**
- 복원은 consumer 가 미적재·disabled 인 상태에서만 하며, 복원·설치·재개는 **각각 기존 승인 경계**를 따른다(§5).

# 6. N2 정정 — F7 한정 (r16 F7·§8 대체)
- 「부하 평균 23.7·24.0·21.3 / 14코어」는 **내가 21:45 에 친 `uptime`·`sysctl hw.ncpu` 한 줄 스냅샷**이다. DA 는 보존 자료에서 **독립 원시 측정으로 재검증하지 못했고**, 당시(틱 시각) 부하를 대신하지도 않는다. 틱 시각 부하는 여전히 **미기록**이다.
- 「op 프로세스 25개(모두 ppid 1)」는 내 `ps -axo pid,ppid,etime,comm` 출력 25행(인자 비열람 — 이름만 `op`)이다. **25개 전부가 `op daemon` 이라는 근거가 아니다**(command 로 확인된 것은 checker 의 **표본 5개**뿐이며 이를 25개 전부로 확대하지 않는다). 지연과의 관계는 미확인 그대로.
