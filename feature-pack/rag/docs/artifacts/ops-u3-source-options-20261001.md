# U3 — 상시 수집 대상 후보표 + allow_gaps 선택지 (2026-10-01, 사용자 선택 대기)

골 원문(GOAL-LEDGER-airag.md 복붙):
최신 fable-team 하네스를 이식하고 기존 AIRAG 증거를 재대조한 뒤, Claude Opus 5.5 HELM·Sonnet 5.5 Master/Nano·GPT-6.1 Sol DA 완성 루프로 AIRAG를 운영 가능한 상태까지 닫는다.
골의 어느 축인가: A03 — A02 트리 5순위 U3(상시 수집 대상·gap 정책, 후보 C07·C12). 이 문서는 선택지 제시이며 `runtime.json` 은 바꾸지 않았다.

조사 방법: 코드 읽기(`collector.py`·`runtime.py`) + `~/.codex/sessions` 의 rollout 파일 **메타데이터**(크기·수정시각·세션 id 앞 8자·cwd 폴더명)만. 대화 본문은 읽거나 출력하지 않았다.

## 1. 동작 사실 (코드 근거)

1. **소스 등록은 `runtime.json` 의 `sources` 에 사람이 한 개씩 적는 방식**이다. 폴더 탐색·글롭·자동 등록은 설계상 없다(`PLAN.md:159` «core에 워처·폴링·전체 폴더 탐색을 넣지 않는다»). 따라서 «향후 세션도 자동으로»는 현재 구조로는 불가능하고, 새 세션마다 사용자가 소스를 추가해야 한다(자동 등록은 새 기능 = 별도 설계 결정).
2. **수집기는 codex rollout 형식 전용**이다(`collect_codex_rollout`). Claude Code 세션 기록(HELM·Master·Nano 좌석)은 형식이 달라 지금 수집할 수 없다.
3. **파일이 자라면 이어서 수집한다**: 런타임은 `captured_byte_limit=None`(= 현재 파일 크기까지)으로 호출하고, 패스당 최대 8 MiB(`max_batch_bytes=8,388,608`)를 처리한다(`collector.py:654,704`). 이전에 «유한 snapshot 28,156,963B»로 기록된 것은 그때의 투어 수집 한도였다.
4. **gap 정책**(`collector.py:453-461,659-661`): 소스 레코드가 검증에서 거부되면
   - `allow_gaps=false`(현재 설정): 예외 `EventError` 로 **그 패스 전체가 실패** → 5분 틱마다 같은 레코드에서 같은 오류로 멈추고 그 뒤 새 대화는 수집되지 않는다(이미 gap 으로 기록 끝난 구간은 재구성 경로가 `allow_gaps=True` 로 고정(`collector.py:541`)이라 통과).
   - `allow_gaps=true`: **내용 없는 안전한 gap 메타**(구간·해시)만 기록하고 계속 진행. 거부된 레코드를 수용된 이벤트로 바꾸지 않는다. `coverage_complete=false` 는 gap 이 남아 있는 동안 유지되고 `status` 에 gap 수가 보인다.
5. 한 틱(`run --once`)은 수집→발행(임베딩 호출)→**기억 추출(LLM 호출, 현재 코드는 동시 1)**→아카이브→백업(03:00 슬롯이면)을 순서대로 한다. 따라 잡아야 할 분량이 많으면 첫 며칠 동안 틱마다 일부만 처리한다(패스당 처리량은 미측정 — 첫 패스 관찰 항목).

## 4. allow_gaps 선택지

| 선택지 | 효과 | Master 의견 |
|---|---|---|
| **G1 `true`** | 거부 레코드는 내용 없는 gap 메타로 기록하고 계속 수집. gap 수·`coverage_complete=false` 가 status 에 계속 보임. 거부 레코드를 수용하지는 않음 | **권장** (S1 의 알려진 거부 1건 때문에 사실상 필요) |
| G2 `false`(현재) | 거부 레코드에서 패스가 실패하고 같은 지점에서 틱마다 반복 실패 | 서비스 목적과 충돌 |

권장 조합: **S1 + G1**. 이 경우 `runtime.json` 은 `allow_gaps` 한 줄만 바뀌고 소스 목록은 그대로다(변경 전 파일 백업 필수, 등록·기동은 사용자 수동 1회 확인 이후).

## 5. 첫 패스에서 관찰해 보고할 값 (사용자 U4 요청 반영)
수집 바이트(패스당 ≤ 8 MiB)·새 창 수·임베딩 호출 수·기억 추출 요청 수와 지연·새 후보 수(확인 대기/검증 대기 증가)·gap 수·`coverage_complete`·`backup_count`. 기억 추출 동시성은 현재 코드가 1 이라 «최대 2» 한도 안이다.
