## 추가 단언의 의미

`source_row`는 device/inode/incarnation 순서의 튜플이다. 두 zero 상태를 만든 뒤 재수집 **이전**에 저장한 `row[2]`가 최초 incarnation이다. 추가 세 줄은:

1. 최초 stored incarnation을 별도 변수로 보관한다.
2. 재수집된 event.producer_epoch가 그 값과 같음을 확인한다.
3. normalized ledger의 sources.incarnation도 그 값과 같음을 확인한다.

기존 next_native_offset=0, 재수집 성공, event 개수 1, 저장 identity row 불변 단언을 그대로 유지한다. 새 변수는 사후 값을 읽어 기대값을 맞추는 방식이 아니며, 이 단일-source fixture에서 fetchone의 대상도 명확하다. mock 성공 결과로 epoch를 대체하지 않는다.

## 독립 mutation 대조

r16과 동일하게 `_normalize_message`가 받은 epoch 대신 `r16-mutated-epoch`를 넘겨 실제 normalized event를 만드는 임시 pytest plugin을 사용했다. source 파일을 쓰거나 production 함수를 고치지 않고 별도 테스트 process 메모리에서만 대입했다.

```text

R16_SAME_MUTATION_BOTH_ZERO_TESTS_FAIL true
R16_SAME_MUTATION_NEW_EVENT_EPOCH_ASSERTION_FAILS true
```

두 파라미터 모두 `stored_events(ledger)[0]["producer_epoch"] == stored_incarnation`에서 실패한다. setup/import 문제나 다른 부수 오류로 만든 Red가 아니다. r16에서 이 mutation은 두 테스트를 통과했으므로 지정 누락이 실제로 닫혔다.
