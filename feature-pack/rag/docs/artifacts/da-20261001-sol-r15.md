| b465b4a 이전 | data→reason | true | true |
| 현재 | data→reason | false | true |

## ② 입력 순서·명시적 동명 베이스·검토 경로

`class Base: __init__(self, code)`와 다른 파일의 `class Base: __init__(self, field)` 및 `Child(Base)`를 **3파일 전체 6개 순열**로 실행했다. Child의 literal은 모두 structural이었다. lookup이 서로 다른 effective binding 후보를 하나로 union하지 않고 None/모호함으로 처리하는 지정 경로는 충족한다.

모호한 imported Choice도 structural로 분류되므로 검토 항목 없이 classify하면 미분류가 남아 closed-world가 거부한다. 새 tests는 pure scan/classify를 실제 코드로 실행하고 성공 mock을 사용하지 않는다. 정확한 code literal 선언·PATH 제외·forward/backward equality를 각각 확인하므로 단순 “예외가 없음” 테스트가 아니다.

unambiguous package exception subclass의 message-as-code 보존도 테스트한다. 단, 예외 여부가 서로 다른 동명 베이스를 섞는 경우는 새 테스트에 없다(R15-m1).

## Minor — R15-m1: 혼합된 예외/일반 베이스에서 message fallback이 모호함을 없앤다

- 심각도: **minor**, 이유 코드 생성 의미. 위치: `tests/_regen_reason_codes.py:118-124`, `:127-142`, `:162-163`.
- `is_exception(node)`는 같은 이름의 모든 베이스 중 **하나라도** Exception이면 True를 반환한다. class_bindings는 예외의 기본 message binding을 상속 후보 단계에 넣지 않고, 외부 define 단계에서 비-code binding을 `is_exception=True`에 따라 message_is_code로 바꾼다. 그 결과 일반 field 베이스의 후보까지 예외-message 후보로 바뀌어 서로 다른 해석이 하나로 합쳐진다.

독립 합성 반례:

```python
# a.py
class Base(Exception): pass

# b.py
class Base:
    def __init__(self, field): self.field = field

# c.py
from b import Base
class Child(Base): pass
Child("PATH")
```

```text
MIXED_BASE FORWARD PATH_ALLOWED true KIND declaration UNCLASSIFIED 0 CONTRADICTIONS 0
MIXED_BASE REVERSED PATH_ALLOWED true KIND declaration UNCLASSIFIED 0 CONTRADICTIONS 0
ACTUAL_MIXED_DATA_CHILD_IS_EXCEPTION false
ACTUAL_MIXED_DATA_CHILD_FIELD_VALUE_MATCHES true
```

실제 b.py의 일반 Base로 Child를 만들어도 정상 field 데이터인데, 생성기는 PATH를 이유 코드로 허용하고 closed-world도 통과한다. 입력 순서가 동일해졌다는 것만으로 semantic correctness가 보장되지는 않는다. 보수적 import/base 해석 정책이면 이 불일치는 structural·수기 검토로 올라가야 한다.

후속 보정: 각 상속 후보의 constructor binding과 예외-message fallback을 **같은 후보 안에서** 계산한 뒤 합친다. 하나의 전역 any(exception)로 다른 일반 후보를 승격하지 않는다. `Base(Exception)`/`Base(field)` 및 역순, unambiguous exception 보존을 함께 회귀로 고정해야 한다. 현재 frozen에 PATH가 새로 들어간 것은 아니고 runtime source/레지스트리는 변경되지 않았으므로 major로 세지 않는다.
