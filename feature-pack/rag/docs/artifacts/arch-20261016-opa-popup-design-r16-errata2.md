# 2. Major 2 정정 — 크기·숫자 직렬화·복구 계약 (정오표 §3.4 최악 행 문장·§3.1 소수 반올림 문장 대체)
## 2.1 크기 제한의 대상
- 상한은 **`probe` 값(compact JSON)의 길이 ≤ 1,024바이트**와 **줄 증가분(`probe` 를 넣은 최종 줄 길이 − 넣지 않은 기준 줄 길이) ≤ 1,033바이트**(= `,"probe":` 9바이트 + 1,024)다.
- **전체 행 상한은 두지 않는다.** 기존 `summary` 정수는 자릿수 제한이 없고(`_result.py:183`) 이 단위는 기존 필드를 바꾸거나 **절단하지 않는다**. `LOG_MAX_BYTES` 는 기존 파일 회전 기준 그대로(변경 0).
- 정오표 §3.4 의 「최악 행 ≤ 2,048바이트」 문장은 **폐기**한다(대상이 불명확했음).
## 2.2 숫자 직렬화 규칙 (정수부 폭 포함)
| 값 | 타입 | 범위(닫힘) | 표기 |
|---|---|---|---|
| `start_ms`·`end_ms` | **`float`**(정확히 `float`; `int`·`bool`·`Decimal` 거부) | 유한·`0.0 ≤ v ≤ 120,000.0` | 생성 시 `round(v, 3)` 1회 → `json.dumps` 의 기본 표기(범위·반올림 때문에 지수 표기 불가: 0 이 아닌 최솟값 0.001, 최댓값 6자리 정수부) |
| `tick_total_s` | `float` | 유한·`0.0 ≤ v ≤ 86,400.0` | `round(v, 3)` |
| `load1` | `float` 또는 `null` | 유한·`0.0 ≤ v ≤ 10,000.0` | `round(v, 2)` |
| `op_resident` | **`int`**(`bool` 거부) 또는 `null` | `0 ≤ v ≤ 100,000` | 10진 정수 |
| `v` | `int` | `== 1` | |
- **정수부 폭**: 위 범위가 곧 폭 제한이다(시간 값 정수부 ≤ 6자리). 범위를 벗어나는 값은 **정수든 부동소수든 전부 거부**한다 — DA 가 든 «유한·비음수 301자리 정수 12칸 → 4,181바이트» 반례는 **타입(`float` 아님)·범위 두 조건 모두에 걸려 거부**된다.
- 최악 `probe`(키 3 × 시도 2 × 최대폭 값 + `probe_error` 3종 + 고정 필드)는 위 규칙 아래 설계상 약 800바이트이고, 이를 시험에서 직렬화해 ≤ 1,024 임을 단언한다.
## 2.3 초과·검증 실패 처리 경로 («유효한 최소 레코드» 복구 사슬)
최종 로그 줄은 **한 곳(`main` 끝의 줄 조립)** 에서 만든다. 기존 필드로 만든 **기준 줄**(현재와 바이트 동일)을 먼저 확정한 뒤 `probe` 를 붙인다.
| 단계 | 동작 | 실패하면 |
|---|---|---|
| ① | 수집 기록(키별 시도·`tick_total_s`·`load1`·`op_resident`)으로 `probe` 구성 | `probe_error` 에 해당 사유를 넣고 값은 `null`(§3.1 표) — **줄은 그대로 진행** |
| ② | **스키마 검증**(§3.1 표·§2.2 규칙·객체별 추가 키 거부) | ④ 로 |
| ③ | **크기 검사**(`probe` 직렬화 ≤ 1,024) | ④ 로(사유 `probe_too_large`) |
| ④ | **유효한 최소 `probe`** = `{"v":1,"keys":[],"probe_error":["<probe_invalid / probe_too_large / collect_failed>"]}` 로 대체(≈60바이트·항상 유효) | ⑤ 로 |
| ⑤ | **`probe` 를 붙이지 않은 기준 줄**을 그대로 출력(= 이 단위 도입 전과 **바이트 동일**한 줄) | (해당 없음 — 기준 줄은 기존 코드 경로) |
- **불변:** 어느 단계의 실패도 `exit`·`status`·`code`·`type`·`summary`·**반환 코드**·`op` 호출 횟수·재시도 횟수·`TickError` 전파를 바꾸지 않는다. **`summary` 를 잘라 상한을 맞추지 않는다**(상한이 대상은 `probe` 뿐). `probe` 처리 전체는 `try/except Exception` 안에 있으며 예외 메시지·값을 기록하지 않는다(사유는 허용 목록 문자열만).
- `append_log`·`out.write`·회전·보관(14일)·`log_dir` 부재 시 `tick log_unavailable` 처리는 **현행 그대로**다.
## 2.4 합성 시험 보강 (정오표 §3.5 에 추가)
- **최종 로그 비교:** 합성 `op`·주입 시계로 실행한 뒤 **실제로 기록된 최종 로그 줄(파일)과 stdout 줄**을 읽어, `probe` 키를 제거한 딕셔너리가 **도입 전 기준 실행의 줄과 키·값 모두 동일**함을 단언한다(`ts`·`status`·`exit`·`code`·`type`·`summary` 전부 · 반환 코드 동일). 파일 줄 == stdout 줄.
- **복구 사슬 시험(변이):** ① 스키마 위반 주입(키 4개·중복·시도 3개·음수·NaN·inf·`end<start`·허용 밖 outcome·**301자리 정수**·`bool`·추가 키) → ④ 최소 `probe` ② 크기 초과 주입 → ④ ③ `probe` 구성·직렬화 예외 주입 → ④ ④ 최소 `probe` 생성까지 실패시키는 주입 → ⑤ **기준 줄과 바이트 동일**. 각 경우 반환 코드·기존 필드 동일.
- **summary 불변 시험:** 매우 큰 정수(자릿수 큰 합법 summary)가 있는 줄에서도 `summary` 값이 절단·변형되지 않고 `probe` 증가분만 ≤ 1,033바이트.
- 크기 시험: 최악 `probe` 직렬화 ≤ 1,024·줄 증가분 ≤ 1,033.

# 3. Minor 1 정정 — 닫힌 스키마 한 표 (정오표 §3.1·§3.2·§3.3 일부 대체)
`probe` 의 **정상 레코드**와 **최소 레코드(복구)** 를 한 표로 확정한다. 각 객체에서 **표에 없는 추가 키는 거부**한다(검증 실패 → §2.3 ④).
## 3.1 `probe` 최상위 필드
| 필드 | 정상 레코드 | 최소 레코드(복구) | null 허용 | 값 조건 |
|---|---|---|---|---|
| `v` | **필수** | 필수 | 아니오 | `int` · `== 1` |
| `keys` | **필수** | 필수(`[]`) | 아니오 | 리스트 길이 0~3 · 항목 `name` 중복 0 |
| `tick_total_s` | **필수** | **생략** | 아니오 | 유한·`0.0~86,400.0`(§2.2) · 종료점 = 줄 직렬화 직전 |
| `load1` | **필수** | 생략 | **예**(수집 실패) | `float` 범위(§2.2) |
| `op_resident` | **필수**(이 필드를 구현 DA 가 삭제하면 **스키마 표에서 제거** — 모든 레코드에서 생략, `v` 는 1 유지(미배포)) | 생략 | **예**(수집 실패) | `int` 범위(§2.2) |
| `probe_error` | **조건부**(비어 있으면 키 자체 생략) | **필수**(정확히 1항목) | 아니오 | 리스트·중복 0·허용 목록 `load_unavailable / op_resident_unavailable / collect_failed / probe_invalid / probe_too_large` 의 부분집합 |
- **정합:** `load1 == null` ⇔ `probe_error` 에 `load_unavailable` · `op_resident == null` ⇔ `op_resident_unavailable`. 최소 레코드의 사유는 `collect_failed / probe_invalid / probe_too_large` 중 하나.
- **경로별 내용(정오표 §3.2 의 «`keys: []` · `tick_total_s` 만» 문장 대체):** 세 키가 환경에 이미 있거나 호출 전 설정 오류로 `op` 호출에 도달하지 못한 경로도 **정상 레코드**이며 `v`·`keys: []`·`tick_total_s`·`load1`·(`op_resident`) 를 모두 가진다(`tick_total_s` 만 있는 레코드는 존재하지 않는다).
## 3.2 하위 객체
| 객체 | 필수 키(정확히 이 집합) | 조건 |
|---|---|---|
| `keys[]` 항목 | `name`, `attempts` | `name` ∈ `NAMES` 3종(참조·경로 문자열 아님) · `attempts` 길이 **1~2** |
| `attempts[]` 항목 | `start_ms`, `end_ms`, `outcome` | §2.2 범위·`end_ms ≥ start_ms` · `outcome` ∈ {`ok`, `bad_format`(rc=0 이나 형식 검증 실패), `nonzero_rc`, `timeout`, `exec_error`} |

# 4. Minor 2 정정 — `attempts`·`op_resident` 의미 (정오표 §3.3 대체)
- **`attempts` 길이 = «`op` 호출 시도 수».** `subprocess.run` 을 부른 횟수이며 **`OSError`(실행 파일 부재·권한 오류 등)도 시도 1건**이다. **자식 프로세스가 실제로 생성된 수가 아니다**(정오표 §3.3 의 「이 틱이 만든 자식 수를 `attempts` 개수가 대신한다」 문장은 **폐기**).
- **`op_resident` = 틱 시작 시 관측된, 명령 이름이 `op` 인 프로세스 수.** `ps -axo comm=`(이름만·인자·환경·참조 비열람)에서 basename 이 `op` 인 줄 수, 읽기 마감 시작 전·자체 한도 1.0초·실패 시 `null`. 상주 `op daemon`·다른 세션의 `op` 를 구분하지 않으며 **이 틱이 만든 자식 수가 아니다**. 이 값과 지연의 관계는 미확인(직접 지지 자료로 쓰지 않음). 구현 DA 가 `ps` 추가 서브프로세스를 계측의 행위 변경으로 판정하면 **필드째 삭제**(§3.1 표 주석).
