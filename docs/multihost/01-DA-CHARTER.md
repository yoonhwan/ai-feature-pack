# DA 심사 헌장 — 멀티 호스트 설계 (DESIGN-multihost-20261021.md)

심사 대상은 문서 1장이다. 코드는 없다. 아래 7개를 «깨뜨리려고» 읽는다.

1. **회귀**: 호스트 1개일 때 현재 동작이 문자 단위로 같은가? 어떤 기본값이 바뀌는가?
2. **우편함 정합**: 같은 메시지 중복·유실·순서 뒤집힘이 어느 경로에서 생기는가? 두 호스트가 동시에 쓰면?
3. **split-brain**: 망이 끊겼다 붙을 때 좌석 명부(`seats.json`)와 실제 tmux 가 어긋나는 시나리오와 복구 절차.
4. **비밀·접근**: Tailscale 인증키·ACL·ssh 키가 어디에 저장되고 어디로 새는가? 로그·쪽지·화면 출력 경로 포함.
5. **되돌림**: 실패했을 때 한 호스트만 빼고 단일 호스트로 돌아가는 길이 문서에 있는가? 원격에 남는 잔재(워크트리·tmux 세션·launchd/systemd)는?
6. **의존 한 점**: Tailscale 계정/코디네이터 장애 시 전체가 멈추는가? 최소 저하 모드가 있는가?
7. **단계 쪼갬**: 첫 단계가 정말 «읽기 전용으로 증명 가능» 한가? 각 단계의 닫는 증거가 실행 가능한 명령 1줄인가?

판정 형식: 질문마다 `질문 N: PASS | HOLD — 근거 1~2줄(문서 줄 인용)`. 마지막 줄 `최종: APPROVE | HOLD`. HOLD 가 2회 연속이면 3번째 심사 대신 설계자가 문제를 다시 보고(하드 룰 14), 필요하면 리서치 나노를 붙인다.
출력 파일은 매 실행 «새 파일명» 으로 쓰고 기록 직전 첫 줄을 다시 연다(덮어쓰기 사고 방지).
