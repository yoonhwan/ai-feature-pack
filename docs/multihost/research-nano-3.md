## 1. 선례 3개 — «수신자 교체(evict) · 이중 소비 · 응답 유실»을 어떻게 단순하게 푸는가

### A. qmail / Maildir (파일 1개 = 메시지 1개, 디렉터리 = 상태)

핵심 규칙(3줄):
1. 배달은 `tmp/<uniq>` 에 다 쓴 뒤 **`link()` → `new/<uniq>`** — `new/` 에 보이는 순간 이미 완성본이다(부분 파일 0).
2. 소비는 **`new/` → `cur/` 로 rename**(= 내가 가져갔다). 읽기와 소유 이동이 한 동작.
3. 재배달해도 파일명(uniq)이 다르면 **중복이 된다** — 중복 판정은 파일명이 아니라 상위(사람·MTA) 책임.

- 보장 수준: **at-least-once**. 같은 호스트 안 rename 원자성만 신뢰. 순서 보장 0.
- 복구 기계: **없음**. 크래시 잔재는 `tmp/` 에 남고, 다음 청소가 지운다. «얼마나 갔는지» 장부 없음.
- evict/세대: **개념 자체가 없다** — 수신자를 바꾸면 그냥 **다른 디렉터리**를 쓴다. 옛 디렉터리는 안 읽으면 그만(격리 코드 0).

### B. Postfix 큐 관리자 (incoming → active → deferred → bounce)

핵심 규칙(3줄):
1. 큐 파일 하나에 **메타(도착시각·시도횟수·다음 재시도 시각)를 함께** 넣는다(별도 파일 없음).
2. 배달 실패는 **삭제가 아니라 `deferred/` 로 이동** + 재시도 시각 갱신. 성공해야 큐에서 사라진다.
3. `maximal_queue_lifetime`(기본 5일)을 넘기면 **bounce(발신자에게 반송)** — 조용히 버리지 않는다.

- 보장 수준: **at-least-once**, 기한 안에서. 기한 밖 = «반송»이라는 명시적 종결.
- 복구 기계: **있음 — 큐 디렉터리 재스캔**. 진행도 장부 파일이 없고, «큐에 있으면 아직 할 일»이라는 불변식으로 재개한다.
- 이중 소비: **막지 않는다.** 대신 «받는 쪽이 중복을 견딘다»(Message-ID 로 상위에서 dedup) — 프로토콜이 아니라 관례.
- evict/수신자 교체: 큐 키가 수신 주소이므로 주소가 바뀌면 **새 큐 항목**이고 옛 항목은 deferred→bounce 로 자연 소멸. 별도 «이관» 단계 없음.

### C. ssh + rsync 스풀 (+ `done/` 마커 · git-annex/Syncthing 류는 후보였다가 제외)

핵심 규칙(3줄):
1. 보낼 것은 `spool/` 에 파일로 두고, **원격 성공(rc 0) 뒤에만** `done/` 으로 옮긴다.
2. `rsync --partial --append-verify` 또는 같은 이름 덮어쓰기 = **재전송 멱등**(같은 파일명).
3. 「성공 응답을 못 받음」은 **성공/실패를 모르는 상태**로 취급하고, 재전송해서 결과를 확인한다(수신측이 멱등이면 안전).

- 보장 수준: **at-least-once**(수신측 멱등일 때) / 멱등이 아니면 **최대 1회가 아니라 «0 또는 여러 번»**.
- 복구 기계: **있음 — `done/` 의 유무가 유일한 장부**. `spool/` 에 남아 있으면 다시 보낸다.
- 왜 git-annex/Syncthing 은 제외했나: 둘 다 «여러 곳에 사본을 두고 나중에 합친다»는 전제 — 우리 r4 결정(§3.0 «메시지마다 주인 호스트가 정확히 하나»)과 정반대이고, 병합·순서 뒤집힘 위험을 새로 들여온다. 비교용으로만 의미가 있다.

### 1.1 세 선례의 «공통 최소 기계» (이 4개면 위 세 문제를 다 다룬다)

| 문제 | 선례들이 쓰는 단 하나의 기계 | 안 쓰는 것 |
|---|---|---|
| 응답 유실(성공/실패 모름) | **재전송 + 수신측 멱등 키(DUP)** | 늦은 성공 표식, 시도 횟수 원장, 「배달 안 됨」 판정 |
| 이중 소비 | **원자적 rename 으로 소유 이동**(`new/`→`cur/`, 큐→done) | 소비 표시 파일, ack 프로토콜, 세대 검사 |
| 수신자 교체(evict) | **수신자를 «다른 디렉터리/주소»로. 옛 것은 안 읽음** | 옛 것 자동 이관, fence 표식, 격리 원자 교체 |
| 크래시 재개 | **«큐에 있으면 아직 할 일» 불변식 + 디렉터리 재스캔** | phase 진행도 파일, 재개 지점 기록 |

## 2. 이 선례 기준으로 우리 설계에서 «빼도 되는» 항목

기준: 선례가 **같은 문제를 더 적은 기계로** 풀고 있고, 우리 보장 문장(§3.3 «한 메시지는 한 호스트에서 한 좌석 세대가 한 번만 소비»)을 **약화하지 않는** 것만 올렸다. «빼면 잃는 보장»이 우리가 이미 «약속하지 않는다»고 쓴 것이면, 그건 잃는 게 아니라 **문서에서 지워지는 것**이다.

| # | 항목명 | 줄 | 빼도 되는 이유(1줄) | 빼면 잃는 보장(1줄) |
|---|---|---|---|---|
| 1 | `late` 늦은 성공 표식 | L73 · L100 · L270 · L276 | Postfix/rsync 는 «성공 응답 못 받음 = 재전송해서 확인» 하나로 처리하고 늦은 성공을 표시하지 않는다 | «옛 기계에 이미 갔을 수 있음» 사전 경고 — 대신 수신 DUP 가 흡수(중복 가능성은 표시만 못 함) |
| 2 | `disp.json` 처분 기록 + `LATE_CHANGED` + `DISP_EXPIRED` + 7일 기한 | L72–L75 · L272–L276 | Postfix 에는 «사람 처분 원장»이 없다 — 반송(bounce) 또는 재시도뿐이고, 사람 판단은 큐 밖 일로 둔다 | 재실행해도 **같은 new_mid 유지**(= 처분 멱등). 빼면 재실행이 두 통을 낼 수 있음 |
| 3 | `reboot_unknown` boot-id 판정 | L72 · L112 | at-least-once 를 약속하는 한 재부팅 여부는 배달 결정에 무관 — 두 선례 모두 재부팅을 따로 보지 않는다 | «재부팅 뒤 중복 배달 회피» — 상한은 deliver DUP 로 이미 막힌다 |
| 4 | `entered_at`·`committed_at`·별도 `<mid>.tries` 파일 | L73 · L85 · L112 | Postfix 는 시각·시도횟수를 **큐 파일 하나의 헤더**에 넣는다(파일 3개 → 1개) | 재전송 기한 계산의 «단일 기준 시각» — 파일 mtime 1개로 대체 가능(정밀도만 잃음) |
| 5 | `to_gen` 세대 필터 + `quarantine-local/` + `inbox isolate` 옛 행 격리 | L88–L89 · L234 · L271 | Maildir 은 세대를 검사하지 않고 **새 수신자 = 새 디렉터리**로 끝낸다(같은 효과, 검사 코드 0) | 같은 호스트 안 옛 세대 «섞임 방지»의 형식 증명 — 디렉터리 분리(`inbound-<gen>/`)로 바꾸면 효과는 유지되나 JSONL 격리 원자성 보장은 사라짐 |
| 6 | `spool_seq`·`out_seq` 커밋 순서 보장(§3.5 전체) | L106 · L105–L108 | Maildir·rsync 스풀 모두 **순서를 약속하지 않는다** — 받는 쪽 LIFO 표시면 충분 | 같은 (발신→수신) 쌍의 «커밋 순서 = 배달 seq 순서» 보장 |
| 7 | `BODIES_TTL_DAYS` 14일 묘비 + «재전송 기한 7일 < 묘비 14일» 두 단계 계약 | L75 · L85 · L275 | Postfix 는 `maximal_queue_lifetime` **하나**로 끝낸다(묘비 수명과 재전송 기한을 분리하지 않음) | «기한 안 재전송은 반드시 DUP 에 걸린다»는 형식 증명 — 하나로 합치면 증명은 사라지고 상수 하나만 남음 |
| 8 | `quarantine/.tmp-<mid>/` 3단계 넣기 절차(①tmp ②rename ③디렉터리 rename) | L73 | Maildir 의 `tmp/`→`link`→`new/` 두 단계면 충분 — 보관함 «넣기»는 원자를 이미 rename 1회로 하고 있다 | 잔재 `.tmp-*` 처리의 일반 규칙(그러나 이미 «다음 작업이 마저 끝낸다»로 흡수됨) |
| 9 | `recv --replay` (14일 재현) | L90 · L305(P3) | Maildir·Postfix 는 «표시 재현»을 약속하지 않는다(터미널 표시는 UX 이지 전달 보장이 아님) | rename 뒤 출력 전 종료 시 «한 번 더 보기» |
| 10 | evict·reserve `phase` 진행도 기록 파일 2종 | L268 · L271 | Postfix 의 재개는 «큐 디렉터리를 다시 스캔» — 진행도 파일 없음. 우리도 `outbound/`·`seats.json` 상태 자체가 진행도다 | 중단 지점별 «정확히 어디서 이어가는지» 단정 — 재스캔 방식은 단계 재실행 멱등성에 의존 |
| 11 | `MAX_PER_TO`(10) `RING_FULL` 별도 규칙 | L82 | (선례에 **있는** 기계다 — Postfix queue limit → defer) **빼지 말 것**. 표에 넣은 이유는 «이건 선례도 갖고 있다»는 대조용 | 빼면 수신 폭주 보호가 사라지고 무한 큐가 된다 |

**요약**: 선례 기준으로 **진짜로 줄일 수 있는 덩어리**는 ①`late` 표식(1) ②사람 처분 원장 `disp.json` 계열(2) ③`reboot_unknown`(3) ④별도 메타 파일 3종(4) ⑤`--replay`(9) — 이 다섯은 «보장 약화 없이» 문서·코드에서 빠질 수 있는 후보다. ⑥`to_gen`/`isolate`(5)와 ⑦두 단계 묘비 계약(7)은 **빼면 형식 증명이 사라지는** 것이라 «빼기»가 아니라 «더 싼 등가물로 바꾸기»(디렉터리 분리 / 상수 하나)로만 다룰 수 있다.

## 3. 빼면 안 되는 것 (선례도 갖고 있는 최소 기계)

- **원자 rename 으로 소유 이동**(consume-on-read) — 세 선례 전부. 우리 §3.3 의 근간.
- **멱등 키 = 파일 존재(mid) + DUP** — Postfix·rsync 스풀 전부. «검사와 커밋이 같은 잠금 구간»(§11)이 이걸 호스트 경계로 확장한 형태.
- **«큐에 있으면 아직 할 일» 불변식** — phase 파일을 빼도 이게 남아야 재개가 성립.
- **한도(backpressure)** — Postfix queue limit. `RING_FULL` 은 빼면 안 된다.
- **보관함 = 디렉터리 1개**(r8 L73, DA 메모 반영) — 처분·표식이 함께 움직이는 성질은 Maildir 의 «파일 1개 = 메시지 1개» 사상의 확장이라 유지 가치가 있다. (단, `late` 를 빼면 디렉터리 안 항목은 `msg`+`disp.json` 2개로 줄어든다.)
