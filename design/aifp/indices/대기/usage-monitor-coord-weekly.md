## 정의 (이 카드가 고정하는 3개)
### 정의 1 — 조율/구현 분류 = 좌석 이름의 역할 토큰(폴더 글자 맞추기를 버린다)
- 판단: 명부·역할 기반으로 간다. 까닭 = 폴더 이름은 역할을 담지 않고(기준값 사), «그 밖 = 조율» 은 이름 없는 세션까지 조율로 센다. 세션 파일이 좌석 이름을 가지고 있어(기준값 아) 명부 파일을 따로 읽지 않아도 된다.
- 세션 1개의 좌석 이름을 정하는 순서: ⓐ 그 jsonl 의 `session_info.name`(여러 줄이면 마지막 줄) ⓑ 없으면 seat-resume 기록 가운데 `jsonl` 칸이 그 파일인 것의 `name` ⓒ 둘 다 없으면 이름 없음
- 역할 = 좌석 이름 문법의 «역할 칸» 하나다(r2 · DA HOLD-DESIGN BYZ 325717). 문법 = ft-name-lint.sh 의 `<프로젝트>-<팀>-<역할>[-<꼬리>]#<N>`: `#` 가 정확히 1개이고 그 뒤가 숫자뿐 → `#` 앞을 `-` 로 갈라 토큰이 3개 이상(빈 토큰 0) → 셋째 토큰이 역할 칸. 첫째(프로젝트) · 둘째(팀) · 넷째부터(석 · 에이전트 · 카드 slug · qa 범위)는 읽지 않는다. 그래서 팀 이름이 `qa` · `master` 여도, 나노 일 이름에 `da` · `arch` 가 있어도 역할이 바뀌지 않는다.
- 석 칸 없는 옛 꼴(`byz-harness-master-pi#1`)과 석 칸 있는 새 꼴(`byz-harness-master-0-pi#1`)은 역할 칸 자리가 같다(둘 다 셋째). 그 밖의 이름 꼴은 지원하지 않는다: 문법으로 안 풀리는 이름(`#N` 없음 · 토큰 2개 이하 · 빈 토큰)은 안에 역할 낱말이 있어도 «못 가림» 이다(토큰 찾기로 되돌아가지 않는다).
- 읽은 값(2026-11-17 13:22 · 최근 48시간 pi 세션 파일 577개 · 읽기만): 이름 있는 313개 전부 문법으로 풀렸고 역할 칸 = master 127 · arch 118 · desk 26 · nano 23 · tester 13 · da 6 · 옛 식(첫 표 토큰)과 갈래가 달라지는 이름 0 · 이름 없는 파일 264개

| 갈래 | 역할 토큰 |
|---|---|
| 구현 | `nano` · `tester` · `qa` · `repro` · `tool` · (문법 밖 옛 낱말) `implementer` · `worker` |
| 조율 | `master` · `arch` · `da` · `desk` · `pm` · `checker` · `analyst` · (문법 밖 옛 낱말) `lead` · `architect` · `orch` |
| 못 가림 | 이름 없음 · 문법으로 안 풀리는 이름 · 역할 칸이 표에 없는 낱말 |

- «못 가림» 은 조율에도 구현에도 넣지 않는다. 보드에 따로 한 줄로 보인다.
- 조율 몫 % = 조율 가중 합 ÷ (조율 + 구현 가중 합) · 못 가림은 분모에서 뺀다 · 못 가림 몫 % = 못 가림 ÷ 전체
- 못 가림 몫이 10% 를 넘으면 보드 첫 줄에 «판정 불가 · 못 가림 n%» 를 쓰고 조율 % 는 참고값으로만 보인다(완료 판정에 쓰지 않는다). 10% 는 이 카드가 정한 문턱이다(오늘 seat-resume 만으로도 안 붙는 몫이 11.2% 였다 · ⓐ 를 먼저 보면 더 준다 = 실제 값은 완료 조건 6 에서 잰다).
- 표는 ft-name-lint.sh 의 역할 예약어 12개(`--roles` 출력)를 전부 담는다. 시험이 그 출력과 표를 대조한다(예약어가 늘었는데 표에 없으면 시험 FAIL).
- 역할 표는 도구 머리의 상수 1개다. 새 역할 이름이 생기면 «못 가림» 으로 보이고, 표에 더하는 것은 PR 1줄이다.
- 범위 = `~/.pi/agent/sessions` 의 claude 모델 요청(기준 측정과 같다). `~/.claude/projects` 세션(48시간 12.6M = 0.8%)은 좌석 이름이 없어 «못 가림» 에 든다.

### 정의 2 — 주간 환산 사용률
- 식: 주간 % = (창 안 claude 모델 가중 합 × 168 ÷ 창 시간) ÷ ((5x 장수 × WK_5X + ultra 장수 × WK_ULTRA) × TARGET_UTIL) × 100
- 창 = 48시간(끝 = 재는 시각 · 완료 판정에 쓰는 값) · 보드에는 24시간 · 168시간 값을 참고 줄로 같이 쓴다(짧은 창은 튄다 · 기준값 다)
- 분자 = 가중 식(기준값 나) · 모델 이름에 claude 가 든 요청 전부(조율 · 구현 · 못 가림 합 · pi 와 claude 런타임 모두) · codex · 그 밖 모델 제외
- 분모 상수 5개는 `~/.claude/fable-team/state/capacity/accounts.env`(또는 `--inv-file` · `$CTX_PLAN_CAP_FILE` = ctx-plan 과 같은 순서)에서 읽는다. 하나라도 비면 «판정 불가 · 상수 <키>» 1줄이고 % 를 내지 않는다(기본값으로 채우지 않는다).
- 보드에는 낮은 앵커(WK_*_LOW)로 센 % 를 괄호로 같이 쓴다(기준값 마). 완료 판정은 높은 앵커 값으로 한다(desk 기준 측정과 같은 자).
- 검산: 기준 사본 h48.json 을 넣으면 150% 가 나온다(완료 조건 3).
- 이 값의 이름 = «로컬 W 환산»(도는 머신의 세션 로그로만 센 값). 다른 머신·밖 경로에서 같은 계정을 쓰면 이 값에 안 잡힌다. 그래서 아래 대조 값을 나란히 둔다(팀장 결정 aifp 5945).

### 정의 2-2 — 계정 실측 주간 %(대조 값)
- 출처 = `~/.claude/fable-team/state/capacity/anchor-snapshots.jsonl`(ft-acct-quota 10분 표본 · 한 줄 = `ts` + `accounts[]` 의 `tier` · `w`) · 또는 `--acct-file` · 읽기만
- 쓰는 표본 = 파일 뒤에서부터 처음 읽히는 줄 1개(끝 줄이 반쯤 쓰였으면 그 앞 줄)
- 식: 계정 실측 주간 % = Σ(w × 계정 한도) ÷ Σ 계정 한도 · 계정 한도 = tier `max_5x` → WK_5X · `max_20x` → WK_ULTRA(정의 2 와 같은 상수 파일 · TARGET_UTIL 은 곱하지 않는다 = 계정이 보여 주는 % 그대로의 가중 평균)
- 판정 불가 3꼴(값을 내지 않는다 · 0 으로 채우지 않는다): 표본 파일 없음·읽히는 줄 0 = «계정 표본 없음» · 표본 `ts` 가 재는 시각보다 30분 넘게 앞 = «계정 표본 낡음 n분» · `w` 가 빈 값(null)인 계정 또는 표에 없는 tier = «계정 표본 빈 값 <email 앞 3글자>» / «계정 tier <값>»
- 차 = 계정 실측 − 로컬 W 환산(부호를 붙여 쓴다). +20%p 이상이면 표지 «다른 머신·밖 경로 의심 +n%p»(로컬이 못 본 사용이 있다). −20%p 이하이면 표지 «로컬이 더 큼 −n%p · 자 차»(다른 머신 의심이 아니다). 20%p 는 팀장이 준 예 값을 문턱으로 고정한 것이다.
- 두 값은 자가 다르다(차를 읽을 때 알아야 할 것 2개): ⓐ 로컬 W 환산은 48시간 속도를 168시간으로 늘린 값이고, 계정 실측은 계정마다 다른 리셋 시각부터 지금까지 쌓인 값이다(막 리셋된 계정은 0%) ⓑ 로컬은 분모에 TARGET_UTIL 0.85 를 곱한다. 읽은 값: 2026-11-17 12:49 표본 = 10계정(5x 5 · 20x 5) 계정 실측 41.2% · 같은 날 기준 측정 로컬 48시간 150%.
- 완료 판정(보드 ⑦)은 두 값 모두 ≤ 100% 일 때만 «목표 안» 이다. 계정 실측이 판정 불가면 ⑦ 도 «판정 불가 <사유>» 다.
